# PointNet++ 完整架构笔记

---

## 1、

所属：计算机视觉 3D点云 点云特征提取 PointNet++ 层级化局部特征学习

描述：PointNet++ 是 PointNet 的改进版本，核心思想是将 PointNet 递归应用于点云的嵌套分区（层级化局部区域），解决了 PointNet 无法捕获局部结构的问题。整体架构分两阶段：下采样阶段通过多个 Set Abstraction (SA) 模块逐层提取多尺度局部特征（每个 SA 包含 FPS采样 → Ball Query分组 → PointNet提特征）；上采样阶段针对分割任务通过 Feature Propagation (FP) 模块做插值上采样 + Skip Connection 恢复逐点特征，分类任务则直接 Global Max Pooling + FC。核心创新是引入了"多尺度分组 (MSG)"和"多分辨率分组 (MRG)"来处理点云密度不均的问题。

冲突：
    ① 容易把 PointNet++ 的 SA 模块理解成就是 PointNet——实际上 SA = FPS + Ball Query + PointNet，PointNet 只是 SA 的最后一步，前两步（采样中心点、球形分组邻居）才是 PointNet++ 区别于 PointNet 的关键
    ② 容易忽略 FPS（最远点采样）的"覆盖性"优势——FPS 不是随机采样，而是每一步选离已选点集最远的点，保证中心点均匀覆盖整个点云，这对后续局部特征提取至关重要
    ③ 容易把 Ball Query 理解成固定半径内取所有邻居——实际上每个球内有最大点数限制 M，超出则随机采样，不足则用最近邻或自身复制补齐
    ④ 容易混淆 MSG 和 SSG——MSG 是同一 SA 内用多个半径各自分组+PointNet，结果 concat 融合，用于处理密度不均；SSG 是单一半径，速度快但密度敏感
    ⑤ 容易以为 FP 模块就是简单的最近邻插值——实际上 FP = 距离加权插值(3个最近邻，1/d^p加权) + Skip Connection(concat SA层对应特征) + Unit PointNet(Shared MLP降维融合)

    （2）核心模块速查

| 模块 | 作用 | 关键参数 | 细节 |
|------|------|---------|------|
| **FPS** (最远点采样) | 选出覆盖整个点云的中心点 | N' 个中心点 | 每一步选离已选点集最远的点，保证均匀覆盖 |
| **Ball Query** | 以中心点为球心，半径 r 内找邻居 | r=半径, M=最大采样点数 | 超出 M 随机采样，不足则复制最近邻 |
| **PointNet** | 邻居特征 → Shared MLP → Max Pool → 局部特征 | 通道: d→C1→C2→Cout | Max Pool 保证置换不变性 |
| **MSG** (多尺度分组) | 多半径分组 → 各自PointNet → concat融合 | r1,r2,r3 (如 0.1,0.2,0.4) | 应对点云密度不均 |
| **SSG** (单尺度分组) | 单一半径分组 | r1 | 速度快，但密度敏感 |
| **FP** (特征传播) | 上采样：插值 + Skip Connection + Unit PointNet | k=3 最近邻, p=2 距离权重 | Inverse Distance Weighted |

    （3）MSG vs SSG 对比

```
          SSG (单尺度)                      MSG (多尺度)
    ┌──────────────────┐          ┌──────────────────────┐
    │ Ball Query (r₁)   │          │ Ball Query (r₁, M₁)  │─┐
    │ → MLP → Max Pool  │          │ → MLP → Max → feat₁ │ │
    └──────────────────┘          ├──────────────────────┤ │ concat
                                  │ Ball Query (r₂, M₂)  │─┤ → MLP
                                  │ → MLP → Max → feat₂ │ │  融合
                                  ├──────────────────────┤ │
                                  │ Ball Query (r₃, M₃)  │─┘
                                  │ → MLP → Max → feat₃ │
                                  └──────────────────────┘
```

    （4）SA 模块三个步骤的数学理解

```
Step 1 - FPS (最远点采样):
    输入: 点集 P = {p₁, p₂, ..., p_N}, 每个 pᵢ ∈ Rᵈ
    输出: 中心点集 C = {c₁, c₂, ..., c_N'} ⊂ P, N' < N
    算法: 贪心迭代, 每次选离已选集合最远的点
    → 保证中心点均匀覆盖全空间

Step 2 - Ball Query (球形查询):
    对每个中心点 cⱼ:
        neighbors = {pᵢ | ||pᵢ - cⱼ|| < r}
        采样固定数量 M 个 (超出截断, 不足补最近邻)
    → 输出: (N', M, d) 的分组特征

Step 3 - PointNet:
    对每组邻居:
        features → Shared MLP (逐点, Conv1d) → Max Pool over M
    → 输出: (N', Cout) 的局部特征
    → Max Pool 保证了"点顺序无关"的置换不变性
```

    （5）FP 模块的详细机制

```
FP 上采样三步骤:
    
    ① Interpolation (距离加权插值):
       对当前层的每个点, 找上一层中最近的 k=3 个点
       feature = Σ(wᵢ × fᵢ) / Σwᵢ
       wᵢ = 1 / d(p, pᵢ)^p  (p=2, 距离越近权重越大)
    
    ② Skip Connection:
       concat(插值特征, 同分辨率SA层特征)
       → 融合高维语义和低维几何信息
    
    ③ Unit PointNet:
       Shared MLP + 降维
       → 融合后的特征维度降低，送入下一层
```

    （6）分类 vs 分割的架构区别

| | 分类 | 分割 |
|---|---|---|
| 下采样 | SA×3, 最终 1 个全局点 | SA×2~3, 降到 N'' 个点 |
| 上采样 | 不需要 | FP×2~3, 恢复到 N 个点 |
| 最终输出 | Global Max Pool → FC → 类别 | Per-Point MLP → 逐点类别 |
| Skip Connection | 不需要 | 每层FP concat同分辨率SA特征 |

    （7）一句话总结

> **PointNet++ = 层级化 SA 模块（FPS采样 + Ball Query分组 + PointNet提特征）逐层下采样提取多尺度局部特征 → 分类走 Global Pooling + FC，分割走 FP 插值上采样 + Skip Connection 逐点预测。MSG 通过多半径分组应对点云密度不均问题。**

# BEVFormer 完整架构笔记

---

## 2、

所属：计算机视觉 3D目标检测 BEVFormer 时空BEV Transformer 纯视觉多相机3D检测

描述：BEVFormer 是基于 Transformer 的纯视觉 3D 目标检测模型，核心思想是用 BEV query 在 3D 空间主动检索多相机图像特征（SCA空间交叉注意力）并与历史帧对齐（TSA时序自注意力）构建 BEV 地图，再用 object query 在地图上做 cross-attention 检测物体。整体架构：多相机图像 → Backbone+FPN 提取 2D 特征 → BEV Encoder (6层，每层 TSA+SCA+FFN) 构建 BEV Feature → Decoder (6层，Self-Attn+Cross-Attn+FFN+Box Refinement) 用 900 个 object query 检测 → Detection Head 输出 3D 框。与 BEVFusion 的本质区别：BEVFormer 是 Encoder-Decoder 固定 Q 形式（query 主动检索），BEVFusion 是纯 Encoder 密集 Q 形式（每个 BEV 格子就是一个 Q）。

冲突：
    ① 容易混淆 SCA（BEV Encoder 内）和 Decoder 的 Cross-Attention——SCA 是 BEV Query → 图像特征（可变形稀疏采样），Decoder 的 Cross-Attn 是 Object Query → BEV特征（全局密集注意力），两者 Q 的来源和采样的目标完全不同
    ② 容易把 BEV query 理解成图像特征——BEV query 是 BEV 空间的可学习向量，通过跨视角注意力主动"问"图像特征，不是被投影过来的图像特征
    ③ 容易混淆 Box Refinement 和 Detection Head——Box Refinement 只预测中心点偏移 (Δcx, Δcy, Δcz) 逐层精调位置，Detection Head 预测完整框含尺寸/朝向/速度
    ④ 容易以为 Decoder 的 Self-Attention 和 Cross-Attention 功能相同——Self-Attn 是 query↔query（去重+划分地盘），Cross-Attn 是 query→BEV（找证据）
    ⑤ 容易忽略时序建模——BEVFormer 通过 TSA（时序自注意力）融合历史帧 BEV，这是它相比纯单帧方法的核心优势
    ⑥ 容易混淆预设高度 Z 和预测高度 Z——BEVFormer 不预测 Z，只预设 4 个固定高度作参考点；最终物体的 Z 由 Detection Head 回归

    （2）三步走总览

```text
BEVFormer 推理流程
│
├─ 1. 准备参考点
│    ├─ BEV网格 + 4个预设高度 → 3D点 (x,y,z)
│    └─ 投影到2D图像 → 像素坐标 (u,v)（只算坐标，不取特征）
│
├─ 2. BEV Encoder（6层）
│    ├─ TSA：当前BEV ↔ 历史BEV（时序对齐）
│    ├─ SCA：BEV Query → 用 (u,v) 去图像特征采样 → 注入BEV
│    └─ FFN
│    → 输出最终 BEV 特征图
│
└─ 3. Decoder + Head（6层）
     ├─ Self-Attn：900个Query互相去重
     ├─ Cross-Attn：Query → BEV特征图（全局找证据）
     ├─ FFN
     └─ Box Refinement：更新参考框中心（逐层精调）
     → Detection Head → 3D Bbox + 类别
```

    （3）SCA 完整采样流程（核心机制）

```text
Step 1: 生成 3D 锚点
        ref_3d: (D=4, B, H*W, 3)
        每个 BEV 格子沿 Z 方向取 4 个高度点作为 3D 参考点

Step 2: 投影到 2D
        每个 3D 点 × 所有相机的 lidar2img 矩阵
        → 得到在每个相机图像上的像素坐标 (u, v)

Step 3: 判断可见性
        bev_mask 筛选掉 (u, v) 超出图像宽高范围的点
        （相机拍不到的位置直接跳过）

Step 4: 可变形采样（Deformable Attention 核心）
        对于投影点 (u, v)，网络并不直接取该点的特征：
        
        ① 网络预测一组偏移量 (Δu, Δv)
        ② 去采样 K 个邻域点：(u+Δu₁, v+Δv₁), (u+Δu₂, v+Δv₂) ...
        ③ 这 K 个点不一定聚在一起，可能散落在周围，
           用来捕捉物体的边缘、纹理等上下文信息
        ④ 通过双线性插值拿到这 K 个点的特征值
        ⑤ 加权求和 → 该 3D 点最终对应的图像特征
```

    （4）TSA 时序自注意力

```text
当前帧 BEV query + 历史帧 BEV feature
        ↓ concat
从 concat 结果 predict 采样 offset
        ↓
去历史 BEV 对应位置取特征
        ↓
与当前 BEV 做 mean 融合
```

本质：对比同一空间位置在不同时间的特征变化 → 学习运动信息。
注意：prev_bev 只跑 Encoder（only_bev=True），torch.no_grad() 不计算梯度。

    （5）Decoder 中 Self-Attention 与 Cross-Attention 的角色

```text
Self-Attention（Query ↔ Query）:
   Q、K、V 全部来自 object query
   → 让 900 个 query 互相"开会"
   → 商量好谁负责哪个区域，避免抢同一辆车
   → 隐式去重：A(强)通过高权重拉拢B(弱)，B的输出被A覆盖

Cross-Attention（Query → BEV）:
   Q 来自 object query（"我想找什么"）
   K、V 来自 BEV Feature（"地图上有什么"）
   → 每个 query 去 BEV 地图找对应位置的证据
   → 残差加回: query_new = query_old + cross_attn_output
```

    （6）Box Refinement 机制

```text
完整的"隐藏→解码→更新"流程：

Step 1: 隐藏位置
  Query_Feature (256维) + 位置编码 (256维) = 带位置的Query
  → 把参考点坐标 (x,y,z) 通过位置编码"隐藏"在 Query 中

Step 2: 解码偏移量
  带位置的Query → MLP(Linear→ReLU→Linear) → (Δcx, Δcy, Δcz)

Step 3: 更新显式参考框
  新参考点 = 旧参考点 + (Δcx, Δcy, Δcz)
```

逐层演化：
```text
Layer 1: ref_init (粗略) → cross-attn BEV (范围大) → 预测 Δ → ref_1 (好一点)
Layer 2: ref_1   (好一点) → cross-attn BEV (范围缩小) → 预测 Δ → ref_2 (更好)
...
Layer 6: ref_5   (很准)   → cross-attn BEV (精准定位) → 预测 Δ → ref_6 (最终)
```

本质：reference_point 越好 → cross-attention 采样位置越准 → 预测越准 → 正反馈逐层迭代。6 层 decoder 的输出全部算 loss（auxiliary loss）。

    （7）Box Refinement vs Detection Head 分工

| 阶段 | 预测内容 | 更新对象 | 目的 |
|------|---------|---------|------|
| Box Refinement（每层） | (Δcx, Δcy, Δcz) | 参考框中心 | 把中心点"挪"到物体真实位置 |
| Detection Head（最后层） | (w,l,h,θ,vx,vy) | 完整 3D 框 | 补齐尺寸/朝向/速度 |

最终框 = Box Refinement 的精准中心点 + Detection Head 的尺寸/朝向/速度。

    （8）训练机制：Hungarian 一对一匹配

```text
训练时 900 个 query 的输出与 GT 做 Hungarian 匹配：
  - 一个 GT 框只能匹配一个 query（一对一）
  - 匹配到 GT 的 query → 正样本，学对应物体
  - 没匹配到 GT 的 query → 负样本，学"我是背景"

结果：推理时不需要 NMS（query 在训练中已学会不重复预测同一物体）
```

    （9）关键区别速查表

| 容易混的点 | 区分 |
|-----------|------|
| SCA vs Decoder Cross-Attn | SCA: BEV Query→图像特征(稀疏采样)；Decoder Cross-Attn: Object Query→BEV特征(全局注意力) |
| Box Refinement vs Detection Head | Refinement 只预测中心点偏移(逐层)；Head 预测完整框(一次性) |
| 预设高度 Z vs 预测高度 Z | BEVFormer 不预测 Z，只预设4个固定高度作参考点；物体Z由Head回归 |
| Self-Attn vs Cross-Attn | Self: query↔query去重；Cross: query→BEV找证据 |

    （10）一句话总结

> **BEVFormer = BEV query 通过 SCA 从图像主动取特征 + TSA 融合历史帧 → 6 层构建 BEV 地图 → 900 个 object query 通过 Self/Cross-Attn + Box Refinement 在地图上迭代检测 → Detection Head 输出 3D 框。纯视觉 Encoder-Decoder，query 式检索，一对一匹配无需 NMS。**

# BEVFusion 完整架构笔记

---

## 3、

所属：计算机视觉 3D目标检测 BEVFusion 多传感器融合 纯Encoder密集预测

描述：BEVFusion 是 MIT 韩松组提出的多传感器（相机 + LiDAR + Radar）多任务（检测 + BEV 语义分割）融合框架。与 BEVFormer 的核心区别：BEVFormer 是 Encoder-Decoder 固定 Q 形式（query 主动检索），BEVFusion 是纯 Encoder 密集 Q 形式（每个 BEV 格子就是一个 Q，密集预测）。BEV 构建方式：相机端通过 DepthLSSTransform（深度估计 + Lift-Splat 投影）把图像特征"撒"到 BEV 栅格；LiDAR 端通过 SparseEncoder（3D 稀疏卷积）后压扁 Z 轴形成 BEV 特征。融合方式：ConvFuser（concat 后 3×3 卷积）或 AddFuser（各模态对齐通道后相加，训练时随机丢弃某模态以增加鲁棒性）。融合后的 BEV 特征经过 Decoder Backbone（2D CNN）+ Neck 做精炼，最后接多任务 Head。全程无 object query，无时序注意力，是密集预测风格。

冲突：
    ① 容易把 BEVFusion 的"Decoder"和 Transformer Decoder 混淆——BEVFusion 的 decoder 是一个 2D CNN backbone+neck 在 BEV 特征上做精炼，不是 Transformer decoder，没有 cross-attention 和 object query
    ② 容易以为所有 BEV 方法都用 query 式——BEVFusion/PointPillar/CenterPoint 都是纯 Encoder 密集预测，只有 DETR/BEVFormer/PETR 是 query 式
    ③ 容易以为融合就是用 Transformer 做 attention——BEVFusion 的融合就是简单的 concat+Conv 或 add，没有 attention 机制
    ④ 容易忽略 AddFuser 的随机 dropout 机制——训练时随机丢弃一个模态的 BEV 特征（模拟传感器失效），测试时不丢，这是 BEVFusion 鲁棒性的关键设计
    ⑤ 容易混淆 BEVFusion 和 BEVFormer 的 BEV 构建方式——BEVFusion 是"投影+堆积"（深度估计→撒到 BEV 格子），BEVFormer 是"BEV query 主动检索"（跨视角 attention），前者快但依赖深度质量，后者精度高但慢
    ⑥ 容易把深度预测理解成预测单一深度值——实际是给每个像素预测一个深度分布（softmax 归一化），是软分配，同一像素可贡献给多个不同深度的 3D 位置

解决方法：

    （2）Camera 分支详解（LSS：Lift-Splat-Shoot）

四个步骤：

```text
Step 1 - Backbone + FPN:
    多相机图像 → ResNet/SwinT → 2D特征图 (B,N,C,H',W')

Step 2 - Depth 预测:
    2D特征 → depthnet → softmax归一化
    depth = softmax(x[:, :D], dim=1)  # (BN, D, H', W')
    每个像素在 D 个深度 bin 上的概率分布（软分配）

Step 3 - Lift (抬升):
    2D特征 × 深度分布 → 3D视锥
    x = depth.unsqueeze(1) * x[:, D:].unsqueeze(2)
    # depth: (BN, 1, D, H', W') × x: (BN, C, 1, H', W')
    # → (BN, C, D, H', W')
    本质：每个像素沿深度方向展开为一串候选3D点

Step 4 - Splat (投影):
    (u,v,d) → 相机坐标 → 世界坐标 (x,y,z)
    按 (x,y) 投影到 BEV 网格 → scatter_add 聚合
    → Camera BEV: (B, 80, 128, 128)
```

| 步骤 | 操作 | 含义 |
|------|------|------|
| Lift（抬升） | 2D像素 → 沿深度扩展成3D点 | 每个像素沿深度方向"展开"为一串候选3D点 |
| Splat（投影） | 3D点 → 投到 BEV 网格 | 3D点按世界坐标"撒"到BEV格子里聚合 |

本质：每个像素根据自己的深度信念，把特征撒到对应的 3D 位置。多视角在同一个世界坐标系中自然对齐融合。

    （3）LiDAR 分支详解（体素化 + 稀疏卷积）

```text
Step 1 - 体素化 (Voxelization):
    离散点云 (N, 4) → 按 (x,y,z) 划分3D网格
    → 每个体素固定容量(max 10个点)
      - 超过10个：随机采样
      - 不足10个：补0
    → Voxel Features: (M, 10, 4)

Step 2 - PFNLayer (最精妙的设计):
    单层逻辑：
    x = Linear(inputs)          # (M,10,C_out/2) 共享MLP
    x = BN(x) + ReLU
    x_max = max(x, dim=1)[0]    # (M,C_out/2) 体素全局max
    
    if last_layer:
        return x_max             # 最后一层：只输出一个向量
    else:
        x_repeat = x_max.repeat(1,10,1)     # max复制回每个点
        x = cat([x, x_repeat], dim=2)       # (M,10,C_out)
        # "局部+全局"：每个点既保留自身特征，又感知体素全局

Step 3 - SparseEncoder:
    Voxel Features → 稀疏张量 → 多层稀疏3D卷积(stride=2)
    → squeeze Z → LiDAR BEV: (B, 128, 128, 128)
```

PFNLayer 设计精髓：
- 共享 MLP：类似 PointNet，体素内所有点通过同一个线性层 → 参数共享
- Max Pooling：置换不变性，点顺序不影响结果
- Concat 回每个点：保留逐点信息的同时让每个点感知全局

    （4）两种 Fuser 对比

| | ConvFuser | AddFuser |
|---|---|---|
| 融合方式 | concat后接3x3 Conv | 各模态1x1对齐通道后相加 |
| 参数量 | 较大 | 较小 |
| 训练鲁棒性 | 无特殊处理 | **随机drop一个模态**（模拟传感器失效） |
| 推理 | 正常融合 | 正常融合 |

AddFuser 关键设计：训练时 random() < dropout → 随机丢一个模态 → 模型学会"只有一个传感器也能检测" → 推理时即使 LiDAR 坏了也能靠相机继续工作。

    （5）Decoder Backbone + Neck（2D CNN）

```text
融合后 BEV → Multi-Scale 2D CNN（类似图像检测backbone）
→ FPN Neck → 多尺度 BEV 特征
```

**与 BEVFormer 的关键区别：** 这里用的是 2D CNN，不是 Transformer Decoder。没有 object query，没有 cross-attention。CNN 在规则网格上做卷积天然适合 BEV 这种结构化的空间表示。

    （6）多任务 Heads

| Head | 任务 | 输入 | 输出 | 特点 |
|------|------|------|------|------|
| **CenterHead** | 3D检测 | BEV特征 | 类别+3D box | anchor-free密集，heatmap找中心，需要NMS |
| **TransFusionHead** | 3D检测 | BEV特征+heatmap proposals | 类别+3D box | query式(200个proposals)，不需NMS，先密集后稀疏 |
| **Segmentation Head** | BEV语义分割 | BEV特征 | 语义图(车道线/可行驶区域等) | 纯密集预测，逐像素分类 |

    （7）CNN 在 BEV 上的优势

BEV 是规则物理空间网格，具有强局部连续性和空间一致性。CNN 的局部感受野和平移不变性（inductive bias）与此天然匹配 → 稳定快速。

BEVFormer 能 work 的原因：通过 Deformable Attention（只采样少量关键点）+ BEV query（自带空间含义）给 Transformer 加了"空间约束"，本质上是 CNN + Transformer 的折中。

| | CNN | Transformer |
|---|---|---|
| GPU优化 | Conv2d在cuDNN/TensorRT高度优化 | attention是memory-bound |
| 延迟 | 固定计算图，延迟可预测 | 动态性导致延迟抖动 |
| 收敛 | 局部归纳偏置，快速收敛 | 需从数据学空间结构，慢 |

    （8）关键认知点

```
1. 融合为什么这么简单？
   → 两者都被投影到同一个 BEV 坐标系，空间已对齐
   → 坐标对齐误差才是真正的瓶颈，不是融合策略
   → 简单融合 = 模态间解耦，方便单独升级或替换

2. 深度预测是 Camera 分支的 Achilles 之踵
   → 单目深度 ill-posed 问题
   → 深度错 → (u,v,d)→(x,y,z) 错 → 特征投到错误 BEV 位置

3. 为什么 LiDAR 用稀疏卷积？
   → 点云天然稀疏（99%+ 体素是空的）
   → 密集 3D 卷积算力不可接受
   → spconv 只在非空体素计算

4. 多模态融合的真正瓶颈
   → 不是融合策略（attention vs concat vs add）
   → 而是坐标对齐误差
   → 特征放错位置，再好的 fusion 也救不了
```

    （9）BEVFusion vs BEVFormer 完整对比

| 维度 | BEVFormer | BEVFusion |
|------|-----------|-----------|
| **架构类型** | Encoder-Decoder（DETR式） | Pure Encoder（密集预测） |
| **Q形式** | 可学习 BEV query + object query | BEV栅格密集Q（每个格子一个Q） |
| **图像→BEV** | BEV query + SCA 投影采样 | LSS（深度预测+Lift-Splat） |
| **传感器** | 只要相机 | 相机 + LiDAR + Radar |
| **融合方式** | 隐式（attention中自动对齐） | 显式（concat/add在BEV空间） |
| **检测方式** | object query → cross-attn BEV | CNN head 直接在BEV上预测 |
| **时序建模** | ✅ TSA（时序自注意力） | ❌ 无 |
| **分割任务** | 无 | ✅ BEV语义分割 |
| **需要NMS** | 不需要（Hungarian Matching） | CenterHead需要，TransFusionHead不需要 |
| **核心优势** | 时序理解强，纯视觉端到端 | 多传感器融合精度高，多任务 |

    （10）范式对立：密集预测 vs Query 检索

```text
纯Encoder密集Q (CNN系):
    BEVFusion: 每个BEV格子=一个Q → 密集预测 → head在BEV上滑动
    CenterPoint: 每个BEV格子=一个Q → heatmap找中心 → 预测box
    
Encoder-Decoder固定Q (DETR系):
    BEVFormer: BEV query(固定) → BEV特征 → object query(固定) → 预测box
    DETR/PETR: object query(固定) → cross-attn(特征) → 直接出box

关键区分：是否有"外部的可学习query"——有=固定Q(DETR系)，无=密集Q(CNN系)
```

    （11）一句话总结

> **BEVFusion = 相机(LSS 投影) + LiDAR(稀疏卷积) → 都在 BEV 空间中对齐 → 简单拼接/相加融合 → CNN 精炼 → 多任务密集预测。全流程无 object query、无时序注意力，是纯 Encoder 架构。与 BEVFormer 的 query 式检索形成"密集预测 vs query 检索"的两种范式对立。**

## 一、架构范式分类

| 范式 | 代表网络 | 核心特征 |

| 网络 | 核心创新 | 面临挑战 |
|------|---------|---------|

| LiDAR-only检测 | CenterPoint | 简单有效，SOTA基线 |

# FCOS3D 完整架构笔记

---

## 4、

所属：计算机视觉 3D目标检测 单目相机 FCOS3D anchor-free 2.5D编解码

描述：FCOS3D 是将 2D anchor-free 检测器 FCOS 扩展到 3D 空间的单目 3D 检测模型。核心设计哲学：**让神经网络不直接感知相机内参 cam2img**，而是通过前/后处理来桥接 2D 图像和 3D 空间。网络本身是纯 CNN，输入只有图像像素，输出是 2.5D 编码（像素坐标+深度+尺寸+朝向等）；相机内参在前处理中将 3D GT 投影为 2.5D 编码，在后处理中将预测的 2.5D 编码反投影回 3D 空间。这种"编解码"范式使网络学习的是与相机无关的几何表示，泛化能力更强，同一模型可处理不同相机参数的数据。

冲突：
    ① 容易以为网络直接输出 3D 坐标——实际上网络输出的是 2.5D 编码（像素偏移+深度+尺寸+朝向），需要后处理用 cam2img 反投影才得到真正的 3D 框
    ② 容易以为 cam2img 参与了网络前向——实际上训练和推理时网络前向完全不用 cam2img，cam2img 只在前后处理中做编解码
    ③ 容易混淆"深度 z"和"3D 中心点坐标"——FCOS3D 中网络预测的是深度 z（单一值），不是 (x,y,z) 三个坐标
    ④ 容易忽略 Center Sampling 的作用——不是所有在 GT bbox 内的像素都是正样本，只有 GT 投影中心周围 1.5×stride 半径内的才是

解决方法：
    （1）完整架构流程图

```text
输入图像 (N, 3, H, W)
      │
      ▼
┌─────────────────────────────────────┐
│  Backbone: ResNet101 + DCNv2        │
│  - 4个 stage，输出 C2~C5            │
│  - stage3/4 使用 DCN（可变形卷积）     │
│  - strides: [4, 8, 16, 32]         │
│  - 输出通道: [256, 512, 1024, 2048] │
└─────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│  Neck: FPN (Feature Pyramid Network)│
│  - 输入: C2~C5                      │
│  - 输出: P3~P7 共 5 层              │
│  - channels: 256                    │
│  - strides: [8, 16, 32, 64, 128]   │
└─────────────────────────────────────┘
      │ (5 个多尺度特征图)
      ▼
```

    （2）9 维回归目标

    （3）核心设计：cam2img 编解码

```text
┌──────────────────────────────────────────────────────────┐
│  训练时                                                 │
│                                                       │
│  前处理: 3D GT ──cam2img投影──→ 2.5D编码(centers_2d+depth) │
│  网络:   图像像素 ──纯CNN──→ 2.5D预测                   │
│  Loss:   2.5D预测 ←→ 2.5D编码 (直接在编码空间计算)        │
│                                                       │
│  后处理: 2.5D预测 ──cam2img反投影──→ 3D框 (仅推理时)      │
└──────────────────────────────────────────────────────────┘
```

**关键认知：网络完全不感知 cam2img**，学习的是"图像像素 → 2.5D 几何表示"的映射，与相机参数解耦。

    （4）训练流程

```text
数据加载:
  LoadImageFromFileMono3D → 图像 + cam2img
  LoadAnnotations3D → GT (3D框) → cam2img投影 → centers_2d + depths
  Resize + Flip → 同步更新 bboxes & centers_2d

正负样本分配:
  对每个 FPN 层的每个像素:
    ① Center Sampling: 像素在 GT center_2d 周围 (半径 1.5×stride)
    ② Regress Range: 当前 FPN 层负责特定尺度范围
       stride=8:   [0, 48)     ← 小物体
       stride=16:  [48, 96)
       stride=32:  [96, 192)
       stride=64:  [192, 384)
       stride=128: [384, INF)  ← 大物体
    ③ 取距离最近的 GT
  满足 → 正样本(计算回归 loss) / 不满足 → 负样本(仅分类 loss)
```

    （5）损失函数一览

| Loss | 任务 | 损失函数 | code_weight | 备注 |
|------|------|---------|-------------|------|
| loss_cls | 类别分类 (10类) | Focal Loss (γ=2.0, α=0.25) | - | 正+负样本 |
| loss_offset | 2D 偏移 (Δx,Δy) | Smooth L1 (β=1/9) | 1.0 | 仅正样本 |
| loss_depth | 深度 z | Smooth L1 (β=1/9) | **0.2** | 深度不确定，降权 |
| loss_size | 3D 尺寸 (w,l,h) | Smooth L1 (β=1/9) | 1.0 | 仅正样本 |
| loss_rotsin | 朝向 sin(θ) | Smooth L1 + sin差分 | 1.0 | 仅正样本 |
| loss_velo | 速度 (vx,vy) | Smooth L1 (β=1/9) | **0.05** | 速度高度不确定 |
| loss_centerness | 中心度 | BCE | - | 正样本 |
| loss_dir | 方向二分类 (0/π) | 交叉熵 | - | 正样本 |
| loss_attr | 属性分类 (9类) | 交叉熵 | - | 正样本 |

**权重设计解读：** depth(0.2) 和 velo(0.05) 权重极低，因为单目深度估计高度不确定，降权防止其噪声主导梯度。code_weight 直接乘到每个样本每个维度的 Smooth L1 loss 上，所有 loss 联合一次反向传播。

    （6）推理流程

```text
前处理: 图像 → BGR→RGB → Normalize → Pad
模型前向: 图像 → Backbone+FPN+Head → 2.5D预测 (完全不使用cam2img)
后处理:
  ① 筛选: 取 cls_score > 阈值, centerness > 阈值
  ② 解码: (Δx,Δy) + 像素坐标 → 2D投影中心
          depth: exp(z) → 实际深度
          size: exp(w,l,h) → 实际尺寸
          rot: sin(θ) + dir_cls → 完整 θ
  ③ 反投影: 2D投影中心 + depth → cam2img反投影 → 3D中心 (x,y,z)
  ④ NMS: 3D NMS去重
  ⑤ 输出: 最终3D检测框
```

    （7）代码对应关系

| 组件 | 类名 |
|------|------|
| 检测器 | `FCOSMono3D` |
| Head | `FCOSMono3DHead` |
| BBox Coder | `FCOS3DBBoxCoder` |
| 数据预处理器 | `Det3DDataPreprocessor` |

    （8）一句话总结

> **FCOS3D = ResNet+DCN Backbone → FPN → per-pixel 预测 2.5D 编码（偏移+深度+尺寸+朝向+速度），cam2img 只在前后处理中做 3D↔2.5D 编解码，网络完全与相机参数解耦。纯 CNN anchor-free 单阶段，端到端训练。**

# PGD 完整架构笔记

---

## 5、

所属：计算机视觉 3D目标检测 单目相机 PGD (Probabilistic and Geometric Depth) FCOS3D改进版 概率深度+几何深度

描述：PGD（FCOS3D++）是 FCOS3D 的直接改进版，发表于 CoRL 2021。核心观察：单目 3D 检测的本质瓶颈是**实例深度估计不准**——深度不准会阻碍所有其他 3D 属性预测的精度提升。PGD 引入了两个创新组件：(1) **Probabilistic Depth（概率深度）**：将深度建模为概率分布而非单一值，捕捉深度估计的不确定性；(2) **Geometric Depth（几何深度）**：构建场景中不同物体之间的几何关系图，利用物体间的空间关系相互约束深度。最终深度 = 概率深度与几何深度的加权平均。Backbone 和 Head 整体继承 FCOS3D 架构，核心改动在深度预测分支。

冲突：
    ① 容易把 PGD 理解成全新的模型架构——实际上 PGD 完全继承 FCOS3D 的 Backbone(ResNet101+DCN) + FPN + FCOSMono3DHead，核心改进只在深度预测上加了两个模块
    ② 容易把"概率深度"理解成预测多个深度值——实际上是预测深度的概率分布（均值+方差），不是多个候选深度
    ③ 容易忽略"几何深度"是跨物体交互——几何关系图在多个预测物体之间传播深度信息，是实例级别的交互，不是像素级别的
    ④ 容易混淆 PGD 和 FCOS3D 的输出格式——PGD 额外输出深度不确定性（方差），其余回归目标与 FCOS3D 一致（9维）

解决方法：
    （1）完整架构流程图（与 FCOS3D 对比）

```text
              FCOS3D                              PGD
     ┌────────────────────┐           ┌────────────────────────┐
     │ Backbone+FPN        │           │ Backbone+FPN (同FCOS3D) │
     │ ResNet101+DCN       │           │ ResNet101+DCN           │
     └────────┬───────────┘           └───────────┬────────────┘
              │                                   │
              ▼                                   ▼
     ┌────────────────────┐           ┌────────────────────────┐
     │ FCOSMono3DHead     │           │ FCOSMono3DHead         │
     │ ├ cls_score        │           │ ├ cls_score  (同左)     │
     │ ├ bbox_pred(9维)   │           │ ├ bbox_pred (9维,同左)  │
     │ │  ├ offset(2)     │           │ │  ├ offset(2)          │
     │ │  ├ depth(1)  ◄───┼─ 改动 ───│ │  ├ depth(1) + var(1) │
     │ │  ├ size(3)       │           │ │  ├ size(3)            │
     │ │  ├ rot(1)        │           │ │  ├ rot(1)             │
     │ │  └ velo(2)       │           │ │  └ velo(2)            │
     │ ├ centerness       │           │ ├ centerness   (同左)   │
     │ ├ dir_cls          │           │ ├ dir_cls      (同左)   │
     │ └ attr_pred        │           │ └ attr_pred    (同左)   │
     └────────────────────┘           │                        │
                                      │ ✚ 新增模块:            │
                                      │ ├ Probabilistic Depth  │
                                      │ │  深度均值μ + 方差σ²  │
                                      │ └ Geometric Depth      │
                                      │    物体关系图 + 消息传递│
                                      │                        │
                                      │ 最终深度 = α×μ_prob   │
                                      │         + β×d_geo     │
                                      └────────────────────────┘
```

    （2）Probabilistic Depth（概率深度）

```text
核心思想：单目深度估计 inherently uncertain，不预测单一值，
         而预测一个概率分布（高斯分布，均值+方差）

改动点（在深度预测子塔的最后）：
  
  FCOS3D:
    depth_feat → Conv → depth (1通道, 直接用Smooth L1监督)
  
  PGD:
    depth_feat → Conv → [depth_mean(1), depth_var(1)]
                         ↑               ↑
                      深度均值          深度方差(不确定性)
    
  方差 σ² 的含义：
    - 方差小 = 模型对这个深度很确定（如近处大物体）
    - 方差大 = 模型不确定（如远处小物体、遮挡物）
    
  Loss 改进：
    FCOS3D: Smooth L1(pred_depth, gt_depth) × 0.2
    PGD:    负对数似然损失 (Negative Log-Likelihood)
            L = (pred_mean - gt)² / (2×σ²) + log(σ) / 2
            ↑ 方差大时自动降权         ↑ 防止方差无限大
```

**本质：让模型自己学会"什么时候该信任自己的深度预测"，不确定性高的地方梯度自动减弱。**

    （3）Geometric Depth（几何深度）

```text
核心思想：场景中物体之间的空间关系可以提供额外的深度线索

流程：
  Step 1: 构建物体关系图
          每个检测到的物体作为一个节点
          边 = 物体间的空间关系（如"A在B前面"、"A和B并排"）
  
  Step 2: 消息传递 (Message Passing)
          置信度高的物体 → 传递"深度参考" → 附近的物体
          几何一致的相互增强 → 几何矛盾的相互抑制
  
  Step 3: 几何深度融合
          对每个物体的 Probabilistic Depth + Geometric Depth
          做加权平均：
          
          depth_final[i] = w_prob[i] × μ_prob[i] + w_geo[i] × d_geo[i]
          
          其中 w_prob ∝ 1/σ² (方差越小权重越大)
          w_geo 基于几何一致性得分
```

**类比：** 你知道旁边车的精确位置（因为雷达/视觉），就可以推断自己大概在什么深度范围——这就是"几何关系约束"。

    （4）与 FCOS3D 的改动点对比

| | FCOS3D | PGD |
|---|--------|-----|
| Backbone | ResNet101 + DCNv2 | **完全相同** |
| FPN | P3~P7, 256ch | **完全相同** |
| 分类/偏移/尺寸/朝向/速度 | 独立子塔预测 | **完全相同** |
| **深度预测** | 单值 z, Smooth L1 | 均值 μ + 方差 σ², NLL Loss |
| **几何深度** | 无 | 物体关系图 + 消息传递 |
| **最终深度** | 直接用预测值 | 概率深度与几何深度的加权融合 |
| 后处理 | cam2img 反投影 | **完全相同** |

    （5）性能对比

nuScenes 数据集 (ResNet101 + DCN):

| 方法 | mAP | NDS |
|------|-----|-----|
| FCOS3D (1×) | ~28.9 | ~36.1 |
| PGD (1×) | 31.7 | 39.3 |
| PGD (1×) + finetune + TTA | 35.5 | 41.8 |
| PGD (2×) + TTA | 36.8 | 43.1 |

当时在 KITTI 和 nuScenes 上均取得纯视觉单目方法的 SOTA。

    （6）一句话总结

> **PGD = FCOS3D 的深度增强版。继承全部架构，将深度预测从单一值升级为概率分布（Probabilistic Depth），并引入跨物体的几何关系图约束（Geometric Depth），最终深度由两者加权融合。核心思想：既然单目深度 inherently uncertain，就让模型自己建模不确定性，并借助场景几何关系互相纠偏。**

    （7）PGD 到底只加了什么（极简版）

```
FCOS3D 全部保留不动，只在深度预测上改了两处：

  ① Probabilistic Depth:
     预测值: z (一个数) → (μ, σ²) (均值+方差)
     Loss:   Smooth L1 → NLL 负对数似然
     效果:   学不准的样本自动降权，不确定的不硬拟合

  ② Geometric Depth:
     新增:   物体关系图 + 消息传递
     效果:   相邻物体的深度互相"投票"，几何一致的增强、矛盾的抑制
     最终:   depth = α×概率深度 + β×几何深度

Backbone, FPN, 分类, 偏移, 尺寸, 朝向, 速度 → 全部不变
```

    （8）为什么不需要额外标注数据

```
数据集和 FCOS3D 完全一样（nuScenes / KITTI），不需要任何额外标注：

  方差 σ² 不需要标注:
    NLL Loss 自动学习——模型发现某个样本怎么学都学不准，
    σ² 自动调大("这个我不确定，别硬拟合了")，梯度自然变小。
    如果很好学，σ² 自动变小("我很有把握")。
    全程不需要人工标注"这个物体的深度确定性是 0.8"。

  几何关系图不需要标注:
    不是人工画图说"A和B有空间关系"。
    模型根据预测出的 3D 位置，自动判断哪些物体空间相邻、
    相对关系如何，然后在相邻物体间做消息传递。

  数据标注工作量 = 零增加，只是模型内部把"深度"做得更聪明。
```

# DETR3D 完整架构笔记

---

## 6、

所属：计算机视觉 3D目标检测 多视角 DETR3D Query直连图像 无BEV中间表示

描述：DETR3D (Wang et al., 2022) 将 DETR 范式直接用于多视角 3D 检测。核心思想：**object query 自己"生"出 3D 参考点，投影到各相机图像上采样特征，省掉 BEV 这个中间表示。** 每个 query 分成两条路——content 分支做 attention 交互（语义："我要找什么"），pos 分支通过 MLP 直接输出世界坐标系下的 (x, y, z)（"我猜物体在这"）。然后把这个 3D 坐标通过相机内外参投影到各视角的 2D 特征图上采样，特征强的位置说明猜对了，特征弱的下一层修正。6 层 Decoder 逐层 refine，最后一层的 query 直接通过 MLP Detection Head 输出最终 3D 框。全程没有 BEV Encoder，query 直连图像。

冲突：
    ① 容易把 DETR3D 的 pos 分支和 BEVFormer 的 Box Refinement 混淆——DETR3D 是 query **自己生成** 3D 参考点（从零猜），BEVFormer 是**已有**参考点然后预测偏移（从预定义位置微调），前者更难收敛
    ② 容易忽略 DETR3D **没有 BEV**——query 直接投影到各相机图像，没有中间的 BEV 特征图，这是它和 BEVFormer 最根本的架构区别
    ③ 容易把 query 的 pos 分支理解成预测 bbox——pos 分支只输出中心点 (x,y,z)，不含尺寸/朝向/速度，完整 3D 框由最后的 Detection Head 统一输出
    ④ 容易以为 DETR3D 的参考点是固定的——实际上每层 Decoder 都会重新从 query 预测新的 (x,y,z)，逐层修正

解决方法：
    （1）完整架构流程图

```text
                                多视角图像输入
          Camera 1          Camera 2      ...      Camera N
         (3, H₁, W₁)       (3, H₂, W₂)            (3, H_N, W_N)
              │                 │                       │
              ▼                 ▼                       ▼
    ┌──────────────────────────────────────────────────────────┐
    │  Backbone (共享权重, 每张图独立过)                         │
    │  ResNet-101 + FPN                                        │
    │  输出: N 张特征图 F_k ∈ (C, H_k/16, W_k/16)               │
    └──────────────────────────────────────────────────────────┘
              │
              ▼
    ┌──────────────────────────────────────────────────────────┐
    │  Transformer Decoder (6 layers, iterative refinement)     │
    │                                                           │
    │  输入: 900 个 object queries, 初始随机                     │
    │                                                           │
    │  每层 Decoder Layer 做 3 件事:                             │
    │                                                           │
    │  ① Query → 预测 3D 参考点                                  │
    │     query 的 pos 分支 → MLP → c ∈ R³ (世界坐标系 x,y,z)    │
    │     "query 自己猜物体在哪"                                 │
    │                                                           │
    │  ② 3D→2D 投影 (用到相机内外参)                             │
    │     for each camera k:                                   │
    │       c_2d(k) = K_k · T_k · c_3d                        │
    │     投影到各视角 → 得到对应的 2D 像素位置                    │
    │                                                           │
    │  ③ 从各视角采样特征 → 更新 query                            │
    │     f_k = BilinearSample(F_k, c_2d(k))                   │
    │     f = concat(f_1, f_2, ..., f_N)                       │
    │     query ← Self/Cross-Attn + FFN                        │
    │                                                           │
    │  注意: 同一层所有 query 共享所有相机特征                      │
    │        每层都重新预测 3D 位置 → 投影 → 采样 → 修正           │
    └──────────────────────────────────────────────────────────┘
              │
              ▼
    ┌──────────────────────────────────────────────────────────┐
    │  Detection Head (接最后一层 Decoder 输出的 queries)        │
    │                                                           │
    │  每个 query → MLP → 10 个数字:                             │
    │  [x, y, z, w, l, h, sinθ, cosθ, vx, vy]                 │
    │                                                           │
    │  每个 query → MLP → cls_score (C 类分数)                   │
    │                                                           │
    │  Head 不做推理、不做交互，只是把 256维向量"翻译"成数字       │
    └──────────────────────────────────────────────────────────┘
              │
              ▼
    ┌──────────────────────────────────────────────────────────┐
    │  Hungarian Matching (一对一, 不需要 NMS)                   │
    └──────────────────────────────────────────────────────────┘
```

    （2）核心机制：Query 自生成 3D 参考点

```text
query (256维向量)
    │
    ├─→ content 分支 → 做 attention 交互
    │    "语义：我要找车"
    │
    └─→ pos 分支 → MLP → 输出 c = (x, y, z)
                              ↑
                     "我猜物体在世界坐标系里的这个位置"

猜完之后：
  c = (x, y, z)  →  投影到各相机  →  采样特征  →  验证

  猜对了 → 采样到的特征强 → 确认
  猜错了 → 特征弱 → 下一层换位置再猜

6 层逐层 refine: query 猜位置 → 验证 → 修正 → 再猜 → 越来越准
```

    （3）为什么省掉了 BEV

```text
BEVFormer 的路:  图像 → BEV Encoder → BEV Feature → query 从 BEV 找证据
DETR3D 的路:     图像 → query 直接投影到图像上采样特征

没有中间的 BEV 特征图，query 直连多相机图像特征。
好处: 架构更简单，不需要维护 BEV 特征图
代价: 没有 BEV 这个结构化中间表示，query 更难找准位置，训练更难收敛
```

    （4）Detection Head 做什么

```text
最后一层 Decoder 输出 900 个 query（每个 256 维向量）
        │
        │  此时每个 query 已经"知道"自己负责的那个物体：
        │    - 3D 位置 (pos分支6次修正后很准了)
        │    - 图像证据 (cross-attention采回来的)
        │    - 和其他 query 协商的结果 (self-attention分好地盘)
        │
        ▼
   ┌──────────┐
   │   MLP    │  → (x, y, z, w, l, h, sinθ, cosθ, vx, vy)  10个数
   └──────────┘
        │
        ▼
   这个 query 对应的 3D 框

Head 只是"翻译"：把 256 维向量语言翻译成 10 个坐标数字。
所有"思考"在前面 6 层 Decoder 里已经做完了。
```

    （5）训练难点

```text
初始 query 是随机的
  → 猜的 (x,y,z) 完全是瞎猜
    → 投影位置是乱的
      → 采到的特征不对
        → 反馈信号弱
          → 前几层基本"碰运气"
            → 训练前期很不稳定

缓解措施:
  - GT 框中心点监督 pos 分支，强制学会"猜在物体附近"
  - 900 个 query，总有几个碰巧猜对的，通过 self-attention 带偏其他 query
  - 中间层也加辅助 loss，逐层引导
```

    （6）一句话总结

> **DETR3D = 多相机图像过共享 Backbone → 900 个 query 自预测 3D 坐标 → 投影到各相机图像采样特征 → 6 层迭代 refine → MLP Head 直接输出 3D 框。全程无 BEV，query 直连图像。架构简单但训练难收敛，更多是范式探索。**
