> 来源：追问"独立子塔输出的特征维度和输入一样（都 256），那还能叫投影到任务子空间吗"。一句话：**子空间的本质是方向（基）的选择，不是维度的降低；同维子空间也是子空间，满秩线性变换换一组基，就是在做子空间投影。**

### 一、数学上：子空间不等于低维空间

n 维空间 V 的子空间 W 可以是：

- **低维的**：256 维里的一条线（1 维）、一个平面（2 维）；
- **同维的**：256 维里，由 256 个"不是原来那组基"的新方向张成的另一个 256 维空间。

在 3 维空间里随便找三个线性无关的向量，它们张成的还是整个 3 维空间，但这三个向量定义了一组**新的基**，相当于换了个"视角"。**"子空间"这个词的重点是方向，不是维度。**

### 二、独立子塔做的是"线性变换"，不是"降维"

```
cls_feat = W_cls · f + b_cls      # W_cls: 256×256
reg_feat = W_reg · f + b_reg      # W_reg: 256×256
```

输出维度和输入一样时，W 是 256×256 的矩阵。它一般**满秩**，所以不丢信息，但它做了一件事：**把 f 重新组合成一组新的方向。**

- 原来 f 的 256 维，是 **backbone 学出来的基**；
- 经过 W_cls 后，cls_feat 的 256 维，是**分类任务自己学出来的基**。

两组基张成的都是 256 维，但**方向不一样**。分类真正关心的那些方向，在 cls_feat 这组基下可能只集中在少数几个维度上；在原 f 下可能分散在很多维度里。

> **"投影到分类子空间"不一定意味着降维，而是意味着"换一组对分类更友好的基"。**

### 三、直观类比：RGB → 任务方向

假设一张 RGB 照片，三个通道 R/G/B：

- 分类可能只关心"是不是红色物体"，真正需要的是"**红色程度**"这个方向；
- 回归可能只关心"物体边缘在哪"，真正需要的是"**亮度梯度**"这个方向。

```
cls_feat = W_cls · [R, G, B]     # W_cls 是 3×3 满秩
reg_feat = W_reg · [R, G, B]     # W_reg 是 3×3 满秩
```

维度都是 3 维，没降维。但 cls_feat 的第 1 维可能强烈对应"红色程度"、后两维是噪声；reg_feat 的第 1 维强烈对应"亮度梯度"。**它们真正关心的子空间其实只有 1 维**，只是被埋在一个 3 维输出里。

### 四、为什么不直接降维，非要保持同维

| 原因 | 说明 |
| :--- | :--- |
| ① 兼容后续 1×1 读出 | 读出层通常期望输入 256 维（输出才是类别数/坐标数），子塔降维太狠会限制读出层表达 |
| ② 训练更稳定 | 满秩线性 + 非线性优化比强行降维更平滑，不易出现信息瓶颈 |
| ③ 让网络自己决定用多少维 | 保持 256 维，训练让有用信息集中到少数维度、其余接近零/噪声——**软性子空间选择**，比硬降维更灵活 |
| ④ 残差连接常见 | 子塔常用 `x + conv(x)`，输入输出维度必须一致才能相加 |

### 五、硬投影 vs 软投影

| 方式 | 结构 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **软子空间投影**（常见） | 子塔保持同维（256→256），训练后信息集中在少数维度 | 不强制丢信息、灵活、训练稳 | 参数多、结构上没显式约束 |
| **硬子空间投影** | `W: 256 → 64` 直接降维 | 参数少、计算省、任务冲突更小（各自只留自己的 64 维） | 可能丢信息，64 维不够时性能掉 |

实际中很多设计**子塔内部保持维度，最后读出时才降维**；也有轻量设计直接在子塔里降维，看具体权衡。

### 六、一句核心总结

> **子空间 ≠ 低维空间；同维线性变换 = 换基 = 一种子空间投影。** 独立子塔输出 256 维，不代表没做子空间投影——它做的是满秩线性变换，把通用特征重组成对分类/回归更友好的方向。真正被"选择"的子空间可能只是这 256 维里的少数几个方向，但结构上保留 256 维，**让网络自己决定用哪些方向**。
