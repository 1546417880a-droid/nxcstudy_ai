## 14. RoPE（旋转位置编码）完整总结 (2026.07)

### 一句话总结

> **RoPE用固定的"频率金字塔"（从高到低）乘上"递增的位置索引"（0,1,2,...），为每个位置、每个维度生成专属旋转角度，让模型通过不同维度分别捕捉从近到远的位置关系，实现高效的相对位置编码。**

### 三大核心要素

**① 频率（theta_i）** — 由维度决定，完全固定

```python
theta_i = 10000^(-2i/dim), i = 0, 1, 2, ..., dim/2-1
```

| 特点 | 高频（i小） | 低频（i大） |
|------|-----------|-----------|
| 频率值 | 大（如1.0） | 小（如0.001） |
| 旋转速度 | 快 | 慢 |
| 擅长捕捉 | 短距离依赖（相邻词） | 长距离依赖（远距离词） |
| 角色 | "显微镜"，关注局部 | "望远镜"，关注全局 |

**② 位置（pos）** — 由序列索引决定，所有维度共享

```python
pos = 0, 1, 2, 3, ..., seq_len-1
```

**③ 旋转角度 = pos × theta_i** — 每个位置、每个维度专属角度

### 五步工作流程

```
Step 1: 计算固定频率
inv_freq = 1.0 / (10000^(2i/dim)) = [1.0, 0.562, 0.316, 0.178, ...]
                                         高 → → → → → → → 低

Step 2: 位置 × 频率 = 角度矩阵
位置0: [0,    0,     0,     0,    ...]
位置1: [1.0,  0.562, 0.316, 0.178, ...]
位置2: [2.0,  1.125, 0.632, 0.356, ...]

Step 3: 复制匹配head_dim（每对维度共享同一频率）
维度对0(0,1)用θ₀, 维度对1(2,3)用θ₁, ...

Step 4: 计算cos/sin缓存
cos_cached = cos(emb), sin_cached = sin(emb)

Step 5: 应用到Q/K向量（逐维度对旋转）
x'_2i   = x_2i·cos(θ_i·pos) - x_{2i+1}·sin(θ_i·pos)
x'_2i+1 = x_2i·sin(θ_i·pos) + x_{2i+1}·cos(θ_i·pos)
```

### 关键特性

| 特性 | 说明 |
|------|------|
| 操作维度 | 每个向量的特征维度（head_dim），不是跨样本 |
| 参数共享 | 所有token、所有head、所有batch共用同一套频率 |
| 相对位置 | 两个token的相似度只依赖于相对距离 (m-n) |
| 多尺度 | 不同频率捕捉不同距离的依赖关系 |
| 预计算 | cos/sin可提前缓存，推理时直接查表 |

### rotate_half：旋转的真正执行者

**为什么有了 cos/sin 缓存还需要 rotate_half？**

cos_cached 和 sin_cached 只存储了"角度"，没有实现"旋转"。rotate_half 才是真正实现旋转矩阵交叉项的操作。

**数学本质**（以维度对 (x₀, x₁) 为例）：

```
旋转公式：
  x₀' = x₀·cos(θ) - x₁·sin(θ)    ← 需要 x₁（交叉项）
  x₁' = x₀·sin(θ) + x₁·cos(θ)    ← 需要 x₀（交叉项）
```

rotate_half 的作用就是构造交叉项：

```python
def rotate_half(x):
    x1 = x[..., : x.shape[-1] // 2]   # 前半
    x2 = x[..., x.shape[-1] // 2 :]   # 后半
    return torch.cat((-x2, x1), dim=-1)  # [-后半, +前半]

# 对 [x₀, x₁, x₂, x₃]
# rotate_half → [-x₁, x₀, -x₃, x₂]
```

**组合在一起**：

```
x * cos + rotate_half(x) * sin

= [x₀·cos, x₁·cos, x₂·cos, x₃·cos]
  + [-x₁·sin, x₀·sin, -x₃·sin, x₂·sin]

= [x₀·cos - x₁·sin, x₁·cos + x₀·sin, ...]  ← 真正的旋转！
```

**如果没有 rotate_half 会怎样？**

```python
# ❌ 只用 x * cos
q_rotated = q * cos  # 每个维度独立缩放，没有交叉

# 后果：
# - 失去相对位置编码能力，退化为逐元素缩放
# - 一个维度的输出只看自己，相邻维度互不干扰
# - 等同于普通位置嵌入，失去RoPE全部优势
```

**三者分工**：

| 组件 | 角色 |
|------|------|
| cos_cached / sin_cached | 存储旋转角度（cosθ, sinθ） |
| rotate_half | 提供交叉项（`[-x₁, x₀, -x₃, x₂, ...]`） |
| 两者结合 `x*cos + rotate_half(x)*sin` | 完整旋转矩阵 |

> **rotate_half 不是可选的装饰，而是旋转的核心——它让 x₀ 和 x₁ 能够互相影响，实现真正的2D旋转。**

### RoPE 三层架构：频率→角度→旋转

```
频率 (Frequency)  →  决定"转多快"  →  由维度决定（固定）
角度 (Angle)      →  决定"转多少"  →  由位置×频率决定
旋转 (Rotation)   →  真正"转起来"  →  用cos/sin + rotate_half实现
```

**第1层：频率** — 维度决定了齿轮大小

```python
theta_i = 10000^(-2i/dim)
# 高频(i小) = 小齿轮，转得快，对短距离敏感
# 低频(i大) = 大齿轮，转得慢，对长距离敏感
```

**第2层：角度** — 位置×频率决定转动圈数

```python
角度 = pos × theta_i
# 位置0→角度0（不转），位置1→角度θ，位置2→角度2θ
# 位置越大，转得越多；频率越高，角度增长越快
```

**第3层：旋转** — cos/sin + rotate_half 真正转动向量

```python
x' = x * cos(角度) + rotate_half(x) * sin(角度)
# 对维度对 (x₀, x₁):
#   x₀' = x₀·cos(θ) - x₁·sin(θ)
#   x₁' = x₀·sin(θ) + x₁·cos(θ)
```

**三层对照表**：

| 层次 | 概念 | 代码 | 决定因素 | 比喻 |
|------|------|------|---------|------|
| 1 | 频率 | `inv_freq` | 维度索引 i | 齿轮大小（转速） |
| 2 | 角度 | `pos × inv_freq` | 位置 × 频率 | 转动圈数 |
| 3 | 旋转 | `x·cos + rotate_half(x)·sin` | 角度 + 向量 | 最终位置 |

**一句话**：频率是"刻度"（转多快），角度是"读数"（转多少），旋转是"动作"（真正转起来）。

### RoPE 记忆口诀

```

高频看近低频远，协同捕捉全距离
每个向量独立转，位置编码妙无穷
```
