> 来源：梳理推理侧一个记录每帧"缓存身份"的元数据函数。一句话：**它不是每个 token/帧都进 KV 缓存，而是按角色选择性入缓存**，只为应对视频高帧率、高计算成本做的优化。它记录的角色 = 帧在缓存策略中的身份（scale 帧 / keyframe / 普通帧），供可视化、评估、调试时核对。

### 一、核心结论：与文本 Transformer KV 缓存同构，但多一个"角色"开关

| 步骤 | 文本 Transformer（标准自回归） | 视频流式推理（用此元数据） |
| :--- | :--- | :--- |
| 当前 token/帧生成 Q | ✅ | ✅ |
| Q 去 attend 历史 KV | ✅（**所有**历史 token） | ✅（**仅 scale + 所有 keyframe**） |
| 融合 V 得到输出 | ✅ | ✅ |
| 当前 token/帧的 KV 是否入缓存 | ✅ 是（**全部**都进） | ❌ **仅当角色 = 0 或 1** |

- **关键区别不在 attention，而在"写回缓存"这一步**：普通帧的 Q 照常去 attend 全部缓存 KV，只是它自己的 KV 不被写入缓存（用完即弃）；文本模型是每个 token 的 KV 都回写。
- 帧率越高（如 30fps）、帧间冗余越大，越不需要每帧都当参考——全存 KV 显存会爆。

### 二、三个角色（帧的缓存身份）

| 角色码 | 含义 | 是否入缓存 | 类比（文本 Transformer） |
| :--- | :--- | :--- | :--- |
| `0` = **scale 帧** | 全局坐标底图，后续每一帧都要 attend | ✅ **必须存** | 相当于"系统提示词 / 初始上下文" |
| `1` = **keyframe** | 长期参考点，相当于关键摘要帧 | ✅ **存** | 相当于被长期保留的历史 token |
| `2` = **非关键帧** | 只 attend 现有缓存，用完即弃（"只看不记"） | ❌ **不存** | 相当于临时 token |

### 三、缓存规模控制公式

```
缓存中 KV ≈ 总帧数 / keyframe_interval + scale_frames
```

- 用 `keyframe_interval`（关键帧间隔）+ scale 帧数控制缓存大小，**远小于原始总帧数 S**。
- 帧序 / 角色分配是**逐帧判断**的，该元数据就是把这套逐帧判断的结果事后记录成"身份标签"。

### 四、元数据记录下来的作用

- **可视化**：只画关键帧；
- **评估**：确认哪些帧被当作全局底座（scale 帧）；
- **调试**：核对帧序、角色分配是否与 phase-2 逐帧判断一致。
