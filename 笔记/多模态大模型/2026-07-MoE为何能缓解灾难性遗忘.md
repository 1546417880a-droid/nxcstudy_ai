## 28. MoE 为什么能缓解灾难性遗忘 (2026.07)

> 来源：讨论 MoE 持续学习能力时整理

### 一句话总结

> **MoE 每次训练只激活少数专家（如 Kimi K3 激活 16/896 个），大部分专家参数保持不变，旧知识因此得到“物理隔离”，从而显著减缓灾难性遗忘。**

### 核心逻辑：参数隔离

| | 传统稠密模型 | MoE 模型 |
|---|---|---|
| 参数更新范围 | 全部参数都参与更新 | 只有被路由选中的少数专家更新 |
| 知识存储 | 所有知识纠缠在一起 | 不同知识分散在不同专家 |
| 学新任务 | 容易覆盖旧知识 | 旧知识所在的专家大概率不被触动 |
| 比喻 | 整个大脑一起调整 | 专家委员会，每次只调整相关专家 |

### 为什么 MoE 有优势？

```
输入 token → Router → 选择 top-K 个专家
              ↓
        只有这 K 个专家前向 + 反向更新
              ↓
        其他 800+ 专家参数完全不动
              ↓
        它们存储的旧知识保持完整
```

**结论**：MoE 的稀疏激活天然提供了一种 **参数隔离**，让新旧知识尽量不冲突。

### 学术界佐证

谷歌 DeepMind 等机构的研究（如 *Mixture of Experts for Lifelong Learning*）表明：

- MoE 在持续学习（Continual Learning）场景下表现优于稠密模型
- 核心策略：**Parameter Isolation**，为不同任务保留独立的专家空间
- 目标：**Learning without Forgetting**

### 需要厘清的两个关键点

**1. 预训练阶段依旧全量更新**

在海量预训练阶段，所有专家都会参与训练。此时不存在“防止遗忘”的需求，目标是让所有专家获得通用基础能力。

```
预训练：所有 896 个专家都训练  ← 没有遗忘问题
微调/持续学习：只激活 top-K 专家  ← 缓解遗忘的优势在这里体现
```

**2. 路由器坍缩风险**

如果路由器总是把 token 派给少数几个“全能”专家，大部分专家闲置，模型就退化为稠密模型，缓解遗忘的优势也会消失。

**解决方案：负载均衡损失（Load Balancing Loss）**

```python
# 强制路由器雨露均沾
loss_total = task_loss + α * load_balancing_loss

# load_balancing_loss 让每个专家被使用的频率尽量均匀
```

### 对比总结

| 阶段 | 是否缓解遗忘 | 原因 |
|---|---|---|
| 预训练 | 不适用 | 所有专家都参与，目标是学通用能力 |
| 微调 / 持续学习 | ✅ 有效 | 只更新少数专家，旧知识被隔离 |

### 记忆口诀

```
稠密模型全脑调，新旧知识互相扰
MoE 路由选专家，只动少数留多数
预训练时全专家，微调阶段显神威
负载均衡防坍缩，遗忘缓解有底气
```
