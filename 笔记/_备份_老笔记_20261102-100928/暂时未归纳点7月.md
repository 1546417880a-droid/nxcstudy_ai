# 视觉定位/检测的完整范式地图 (2026.07)

> 来源：分析 Eagle/LocateAnything 模型架构时整理

---

## 总览

```
                        视觉定位/检测
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
   密集预测路线          集合预测路线          生成式路线
   (dense)             (set prediction)      (generative)
        │                   │                   │
   ┌────┴────┐         ┌────┴────┐         ┌────┴────┐
  One-stage  Two-stage  DETR系   CLIP对齐   自回归    扩散
  (YOLO)    (R-CNN)   (G-DINO)  (OWL-ViT) (LLM系)  (DiffDet)
                                                  │
                                          ┌───────┴───────┐
                                       LLM-as-          Non-LLM
                                       Detector         AR
                                       (LocateAnything) (Pix2Seq)
```

---

## 1. Two-Stage（两阶段）— R-CNN 家族

```
图像 → CNN Backbone → RPN (候选区域) → RoI Pooling → 分类+回归
```

| 模型 | 特点 |
|---|---|
| Faster R-CNN | RPN + RoI, 闭集 |
| Mask R-CNN | 加 mask 分支 |
| Cascade R-CNN | 多级 refine |
| Dynamic R-CNN | 动态 label assignment |

**核心**: "先找可能的位置（region proposal），再判断每个位置是什么"。

**优缺点**:
- 精度高，尤其对小目标好
- 速度慢（两阶段），逐渐被单阶段和 DETR 系取代

---

## 2. Dense Prediction（单阶段密集预测）

```
图像 → CNN/FPN → 多尺度 feature map → 每个位置直接预测 cls + bbox
```

| 模型 | 特点 |
|---|---|
| YOLO v1-v11 | anchor-based → anchor-free，工业落地王者 |
| FCOS | anchor-free，per-point prediction |
| CenterNet | keypoint-based，检测目标中心点 + wh |
| RetinaNet | Focal Loss 解决类别不平衡 |
| ATSS | adaptive training sample selection |
| RT-DETR | DETR 思想 + 单阶段速度，百度出品 |

**核心**: "图像上每个位置都在猜——这里有没有东西？框多大？什么类别？"

**优缺点**:
- NMS 后处理是瓶颈（部分新模型已去掉）
- 小目标和高分辨率下仍需要 FPN 多尺度支持

---

## 3. Object Query（DETR 系，集合预测）

```
图像 → CNN Backbone → Transformer Encoder → Transformer Decoder
                                                ↑
                                     learnable object queries (N个)
                                                ↓
                                     并行输出 N 个预测 (cls + bbox)
                                     用 Hungarian 匹配做 bipartite matching
```

| 模型 | 特点 |
|---|---|
| DETR | 开创性，收敛慢（500 epochs） |
| Deformable DETR | 可变形注意力，收敛加速到 50 epochs |
| DINO | 去噪训练 + 混合 query 选择 + CDN |
| **GroundingDINO** | 文本特征注入 query，开放词汇 |
| Co-DETR | 协同训练多个检测头 |
| DETA | 双塔 encoder-decoder |
| RT-DETR | 实时 DETR |

**核心**: 不再需要 anchor 和 NMS，用 N 个 learnable queries "学会去注意图像中的物体"。

**优缺点**:
- 天然的端到端，去掉 NMS
- 小目标需要更多 queries，收敛仍需技巧
- GroundingDINO 是视觉定位领域最主流的 DETR 变体

---

## 4. CLIP-Style Two-Tower（视觉-语言对齐）

```
文本 → Text Encoder ──→ text features ──→ 与视觉 region features 对齐 ──→ 分类/回归
图像 → Vision Encoder ──→ image/region features ─┘
```

| 模型 | 特点 |
|---|---|
| **GLIP / GLIPv2** | "phrase grounding = detection"，用自然语言替代固定类别 |
| **OWL-ViT / OWLv2** | CLIP vision encoder + 简易检测头，开箱即用 |
| RegionCLIP | CLIP + region-level 对比学习 |
| GroundingDINO 1.5 | 融合了 CLIP 对齐 + DETR 结构 |

**核心**: 不生成文本，而是把文本 embedding 和视觉 region embedding 拉到同一个空间，算相似度。

**与 LLM-as-Detector 的区别**:
- CLIP 系: 文本仅用于 feature 对齐，不参与推理
- LLM 系: 文本和图像在 LLM 内部深度交叉注意力，真正"理解"指令

---

## 5. LLM-as-Detector（大模型为基座，生成式）

```
图像 → ViT → MLP Projector → LLM (自回归生成) → 坐标 token 序列
```

| 模型 | 特点 |
|---|---|
| **LocateAnything (Eagle)** | PBD 并行解码，MTP+AR hybrid，12.7 BPS |
| **Kosmos-2 / Kosmos-2.5** | 微软，用 `<gri>` bounded token |
| **Ferret** | Apple，支持任意形状 referring + 区域描述 |
| **Qwen2.5-VL / Qwen3-VL** | 阿里，VLM 原生支持坐标输入/输出 |
| **Rex-Omni** | IDEA 出品，类似路线 |
| Shikra / Griffon | 学术界先驱 |
| GPT-4o / Gemini 2.5 | 闭源，也支持 bbox 输出 |

### 5.1 LocateAnything 的关键创新

**PBD (Parallel Box Decoding)**：

```
传统方式 (NTP): <box> → <x1> → <y1> → <x2> → <y2> → </box>   6次 forward
标准 MTP:      [<box>, <x1>, <y1>, <x2>, <y2>, </box>]         1次 forward, 位置独立
PBD (本文):    [<box>, <x1>, <y1>, <x2>, <y2>, </box>]         1次 forward, 结构化约束
               + decode_bbox_avg (top-k 加权)
               + is_valid_box_frame (合法性检查)
               + hybrid: 不合法时切回 AR
```

**核心**: 框被离散化为 1001 个坐标 token（`<0>` ~ `<1000>`），检测就是"说出这些 token 的序列"。

**优缺点**:
- 最强的自然语言理解和指令跟随能力
- 零成本扩展新任务（换句话就行）
- 速度受限于 LLM 推理（PBD 缓解了这个问题）

---

## 6. Promptable Segmentation（SAM 系，可提示分割）

```
图像 → ViT image encoder (一次性, heavy) → image embeddings ────→ Mask Decoder (light)
提示(点/框/文本) → Prompt Encoder ──────────────────────────────────┘
                                                                      ↓
                                                               输出 mask(s) + score(s)
```

| 模型 | 特点 |
|---|---|
| **SAM** | 点/框 prompt → 分割，10M+ 图像预训练 |
| **SAM2** | 加视频时序一致性 |
| **SAM3** | 加文本 prompt（CLIP embedding 注入） |
| SEEM | 多模态 prompt（点/框/涂鸦/文本）统一 |
| HQ-SAM | 高质量 mask 边缘输出 |
| MobileSAM | 轻量化 |
| EfficientSAM | 蒸馏版 |

**核心**: 不预测"有哪些物体"，而是"你告诉我哪里/什么东西，我分割出来"。

**与上面各范式的根本区别**:
- 不是检测器（不输出类别+框）
- 是分割器（输出 mask）
- "提示"而非"指令"驱动

---

## 7. Diffusion-Based（扩散模型检测）

```
噪声框 → Denoising U-Net / Transformer ──→ step-by-step 去噪后的精确框
              ↑
        图像特征条件
```

| 模型 | 特点 |
|---|---|
| **DiffusionDet** | 把检测建模为去噪过程，框从随机噪声逐步 refine |
| Pix2Seq-D | 扩散 + 序列生成 |
| DDP | 条件扩散用于检测 |

**核心**: "框一开始是随机噪声，在图像条件的引导下逐步去噪成真框"。

**优缺点**:
- 理论上能生成任意数量的高精度框
- 推理需要多步去噪，速度极慢（几十到上百步）
- 目前停留在学术探索阶段

---

## 8. Autoregressive Non-LLM（非 LLM 的自回归检测）

```
图像 → CNN Encoder → 轻量 Transformer Decoder (自回归) → token序列 → 还原为框
```

| 模型 | 特点 |
|---|---|
| **Pix2Seq** | 谷歌，把检测视为 token 序列生成，但 decoder 是轻量的 |
| SeqTR | 类似 Pix2Seq |
| OFA | 微软，统一多任务序列生成 |

**核心**: "跟 LLM 一样生成序列，但 decoder 是随机初始化的，没有语言先验知识"。

**与 LLM-as-Detector 的区别**:
- Non-LLM AR: 轻量 decoder，没有世界知识，纯视觉驱动
- LLM-as-Detector: 复用 LLM 的语言理解和推理能力

## 9. LocateAnything 前处理与 ViT 架构详解

> 来源：逐行分析 `locateanything_worker.py` + `modeling_vit.py` + `processing_locateanything.py`

### 9.1 推理入口的配置参数

```python
LocateAnythingWorker(
    model_path="nvidia/LocateAnything-3B",
    attn="la_flash",          # LLM attention 实现 (FlashAttention varlen)
    vision_attn="auto",       # Vision encoder attention (自动选择后端)
    scheduler="pipeline",     # batch 调度策略 (batch_utils 中定义)
)
```

| 参数 | 作用域 | 含义 |
|---|---|---|
| `attn` | LLM（语言模型） | 控制文本/多模态的 attention 后端，`la_flash`=FlashAttention varlen |
| `vision_attn` | Vision Encoder | 控制 ViT 内部 attention 后端，`auto`=自动选择 |
| `scheduler` | batch 推理 | 混合 MTP/NTP 的调度策略，当前仅暴露 `pipeline` |

两者独立配置，对应环境变量 `LA_FLASH_ATTN` 和 `LA_FLASH_VISION_ATTN`。

### 9.2 任务方法选择机制

8 个任务便捷方法（`detect`, `ground_single`, `ground_multi`, `ground_text`, `detect_text`, `ground_gui`, `point`, `detect_visual_prompt`）**没有自动路由**，方法选择完全由调用方决定。

核心机制是 **prompt 驱动**——所有方法共享同一个 `predict()`，区别仅在于拼进去的指令文本：

```
detect()       → "Locate all the instances that matches the following description: {cats}."
ground_single()→ "Locate a single instance that matches the following description: {phrase}."
ground_multi() → "Locate all the instances that match the following description: {phrase}."
ground_text()  → "Please locate the text referred as {phrase}."
detect_text()  → "Detect all the text in box format."
ground_gui()   → "Point to: {phrase}." (point) / "Locate the region..." (box)
point()        → "Point to: {phrase}."
```

`ground_gui(output_type="point")` vs `ground_gui(output_type="box")` 的切换是纯 prompt 级别——不同指令 → 模型输出不同格式（`<box><x><y></box>` vs `<box><x1><y1><x2><y2></box>`），后处理用不同正则解析。

### 9.3 完整前处理管线

**图像侧（3 步）**：
1. `_build_messages()` → 将 PIL Image 放入 `{"type": "image", "image": image}`，成为 `<image-1>`
2. `process_vision_info()` → 提取图像，统一转 PIL
3. `processor(images=images)` → `rescale → normalize → patchify → pixel_values + image_grid_hws`

**patchify 输出**: `[H*W, C, patch_size, patch_size]`。336×336 图 + patch_size=14 → `[576, 3, 14, 14]`。每个 patch 是 3×14×14 的小方块，**不是一个像素**。

**多图 concat**: 所有图的 patch 在 dim=0 上堆叠。3 张图各 576 个 patch → `[1728, 3, 14, 14]`。

**文本侧（3 步）**：
1. `_build_messages()` → `{"type": "text", "text": question}`
2. `py_apply_chat_template()` → 渲染为 ChatML 格式（`<|im_start|>user\n<image-1>\n{question}<|im_end|>`）
3. `processor(text=[text])`:
   - `replace_media_placeholder`: `<image-1>` → `<img><IMG_CONTEXT>×N</img>`（N = H*W/merge_kernel_size²）
   - `tokenizer` → input_ids + attention_mask

最终给模型的：
```python
{
    "input_ids":      [..., IMG_CONTEXT(xN), ...],     # 文本 token + 图像占位符
    "pixel_values":   [P_total, 3, 14, 14],            # 原始 patch 像素
    "image_grid_hws": [(24,24), (24,24), (24,24)],     # 每张图的 patch grid 尺寸
}
```

### 9.4 IMG_CONTEXT 的两阶段替换

```
阶段1 (tokenizer): <image-1> → N 个 IMG_CONTEXT token（同一个 ID，仅占位）
阶段2 (forward):   IMG_CONTEXT 的 embedding 被 ViT 产出的视觉特征硬替换
```

核心代码 `modeling_locateanything.py:205-242`：

```python
input_embeds = self.language_model.get_input_embeddings()(input_ids)  # token→embed
vit_embeds = self.extract_feature(pixel_values, image_grid_hws)        # ViT 前向
vit_embeds = self.mlp1(vit_embeds)                                     # MLP 投影
selected = (input_ids == self.image_token_index)                       # 找到 IMG_CONTEXT
input_embeds[selected] = vit_embeds[:selected.sum()]                   # 硬替换
outputs = self.language_model(inputs_embeds=input_embeds, ...)         # 送入 LLM
```

本质：tokenizer 挖坑 → ViT 产内容 → forward 时填坑。

### 9.5 为什么需要 image_grid_hws

`pixel_values` 是**无结构的扁平数据**（所有 patch 压在 dim=0），`image_grid_hws` 是恢复结构的钥匙：

1. **拆分多图**：`patch_merger` 按 H×W 切出每张图的 patch，reshape 成 2D 做合并
2. **2D RoPE 位置编码**：需要知道每个 patch 的 (row, col)，只知序号无法推算
3. **确定 IMG_CONTEXT 数量**：N = H×W / merge_kernel_size²

### 9.6 ViT 如何处理 patch

**ViT 不会再重新切图**——image_processor 已经切好，ViT 直接用。

- **patch_embed**: `Conv2d(3, D, kernel=14, stride=14)` 对每个 `[3,14,14]` 小块独立卷积 → `[1728, D]`，然后加 2D 位置编码

- **Transformer Encoder**: 一维序列 + **块对角注意力 mask** 隔离多图：
```
        图1(576)  图2(576)  图3(576)
图1       ████      ░░░░      ░░░░       ← 图1 的 patch 只互看
图2       ░░░░      ████      ░░░░       ← 图2 同理
图3       ░░░░      ░░░░      ████       ← 图3 同理
```
packed sequence + block-diagonal mask，无 padding 浪费，mask 保证独立。

- **patch_merger**: 用 grid_hws 恢复 2D → 2×2 merge → 如 24×24=576 → 12×12=144 个向量/图

最终 ViT 输出：`List[[144, D], [144, D], [144, D]]`，各图独立。

### 9.7 位置编码对比

| | LocateAnything | Qwen2-VL |
|---|---|---|
| ViT 内 | 2D RoPE（row+col） | 2D RoPE |
| LLM 侧 | 复用 1D RoPE | 带 2D row/col 位置信息 |
| LLM 感知空间 | 间接（靠 ViT embedding 携带） | 直接（显式 visual position） |

### 9.8 全链路数据流

```
PIL Image                     Text
    │                           │
image_processor           chat_template → ChatML
  patchify                <image-1> 占位
    │                           │
pixel_values               replace_media_placeholder
[P_total,3,14,14]          <image-1> → IMG_CONTEXT×N
+ image_grid_hws                │
    │                       tokenizer → input_ids
    └──────────┬────────────────┘
               ↓
          model.forward()
    ┌──────────┴──────────┐
    │ ViT:                 │  LLM:
    │  patch_embed         │  token embeddings
    │  transformer         │  IMG_CONTEXT ← vit_embeds
    │  (2D RoPE + mask)    │  → transformer layers
    │  patch_merger        │  → PBD/MTP 解码
    │  → MLP1 → vit_embeds │
    └──────────────────────┘
               ↓
         解码输出文本
    <box><100><200><300><400></box>
               ↓
    parse_boxes() → 像素坐标
```

## 10. image_grid_hws 在 MoonViT 中的三个作用

> 来源：分析 `modeling_vit.py` 中 `image_grid_hws` 的每一次使用

`image_grid_hws` 是 shape `(N, 2)` 的 tensor，记录每张图的 patch 网格尺寸 `(h, w)`，在多图 packed 场景中充当序列分隔符。

### 作用①：可学习位置编码插值（Learnable2DInterpPosEmb）

```python
# Learnable2DInterpPosEmb.forward(x, grid_hws)
for shape in grid_hws.tolist():        # e.g. [(40,60), (20,20)]
    if shape == (64, 64):
        pos_embs.append(weight.flatten(start_dim=1))   # 原始尺寸，直接用
    else:
        pos_embs.append(F.interpolate(                  # 双三次插值缩放
            weight.permute(2,0,1).unsqueeze(0),
            size=shape, mode='bicubic'
        ).squeeze(0).permute(1,2,0).flatten())
```

不同分辨率的图各自从 64×64 的权重网格上插值出对应尺寸的 2D 位置编码。训练时 64×64 直接取用，推理时其他尺寸通过双三次插值适配。

### 作用②：RoPE 频率 + cu_seqlens（MoonVitEncoder）

```python
# Step A: 2D RoPE — 每张图取各自区域的 freqs_cis
freqs_cis = self.rope_2d.get_freqs_cis(grid_hws)
# 内部: for (h,w) in grid_hws: 取 freqs_cis[:h, :w] → flatten → cat
# 结果: (Σh*w, head_dim//2)，每个 patch 有独立的 (x,y) 旋转频率

# Step B: cu_seqlens — 累积序列长度
lengths = torch.cat([torch.zeros(1), grid_hws[:,0] * grid_hws[:,1]])
cu_seqlens = lengths.cumsum(dim=0, dtype=torch.int32)
# e.g. [0, 1600, 2000] 表示图1占 [0,1600)，图2占 [1600,2000)
```

flash_attn 用 cu_seqlens 实现 block-diagonal attention：同图内部互相 attend（causal=False），不同图之间隔离。用 3 个整数替代 N×N 的 attention mask 矩阵。

### 作用③：patch_merger 拆分（patch_merger 函数）

```python
pre_sum = 0
for (h, w) in grid_hws.tolist():
    seq = x[pre_sum : pre_sum + h*w]       # 按图的边界切分
    # reshape → permute → merge 2×2 → 通道×4
    # (h, w, D) → (h/2, w/2, D×4) → (h/2 * w/2, D×4)
    outputs.append(merged)
    pre_sum += h * w
```

把 packed 序列按图的边界拆开，各自做 patch merge，最终返回 `List[Tensor]`。

### 一句话总结

没有 `image_grid_hws`，`pixel_values` 就是一堆不知道谁属于谁的像素块——位置编码不知道往哪插，attention 不知道哪些能互看，merger 不知道在哪切分。

## 11. 自动驾驶决策三层框架 (2026.07)

> 来源：梳理自动驾驶感知-规划-决策的整体架构

### 三层次总览

```
整体规划（提前建模 + 路网信息）  →  当前时刻（瞬时感知）  →  未来决策（预测与规划）
        ↓                              ↓                          ↓
   "这条路是什么样的"           "现在周围有什么"           "接下来会发生什么"
```

### 层次1：整体规划（静态+先验信息）

**数据来源：** 高精度地图 + 路网导航

| 类型 | 内容 | 特点 |
|------|------|------|

## 12. 3D高斯泼溅（3DGS）核心逻辑串讲 (2026.07)

> 来源：围绕3DGS学习目标、高斯点本质、参数优化、增删机制的完整Q&A

### 一句话总结

> **3DGS把稀疏点云"膨胀"成数百万个可学习的3D椭球，通过不断渲染并与真实照片对比，反向优化每个椭球的位置、形状、透明度和视角相关颜色，同时在固定间隔动态增删点，最终拼凑出完整逼真的三维场景。**

### 学习目标：高斯椭球的四个属性参数

| 参数 | 作用 |
|------|------|
| 位置 (μ) | 椭球中心在哪 |
| 形状 (Σ = 尺度×旋转) | 椭球多大、多歪 |
| 不透明度 (α) | 多透明（0=完全透明，1=不透明） |
| 球谐系数 (SH) | 不同观察视角下的颜色（模拟金属反光等） |

颜色通过球谐函数（SH）表达，但学习的是**SH系数本身**，不是球谐函数这个数学工具。

### 高斯点 vs 点云

- **点云**：无限小的点，只有位置，表面是"稀疏钉子"
- **高斯点**：点云的升级版，是膨胀后有体积、有形状的3D椭球，像"钉子上的膨胀泡沫"，填满空洞后拼出连续表面
- **数量关系**：初始时一对一等同于点云，密集化后激增到初始的**10~100倍**（几万→百万级），剪枝后仍远多于点云

### 损失函数：两个指标驱动优化

| 损失 | 作用 |
|------|------|
| **L1 Loss** | 像素绝对值差 → 保证亮度颜色准确 |
| **SSIM Loss** | 结构相似性 → 保证边缘纹理不失真 |

**总损失 = L1 + λ × SSIM**

### 参数更新 vs 点增删：两个不同频率的操作

```
每一步都做（反向传播驱动）：
  渲染 → 计算L1+SSIM损失 → 反向传播 → 更新位置/形状/不透明度/SH系数

每100步固定间隔做：
  密集化：
    位置梯度大 → 分裂（大尺度）或克隆（小尺度）
    尺度太大 → 分裂成更小的点
  剪枝：
    不透明度接近0 → 删除（透明无用）
    尺度太大+位置空旷 → 删除（噪声点）
```

**为什么间隔做？** 计算成本高，需要稳定梯度信号，中间间隔让参数先收敛。

### 整体训练流程

```
多视角照片 → COLMAP生成稀疏点云(几万点)
    ↓
【初始化】每个点→一个高斯椭球（数量=点云数）
    ↓
┌─────────────────────────────────────────────┐
│ 循环训练（数万次迭代）                        │
│                                             │
│   每一步：渲染→算损失→反向传播→更新参数       │
│       ↓                                     │
│   每100步：密集化(点增多) + 剪枝(点减少)      │
└─────────────────────────────────────────────┘
    ↓
百万级高斯点构成逼真3D场景
```

## 13. RMSNorm + weight 核心机制 (2026.07)

> 来源：分析 Qwen2RMSNorm 源码，理解归一化后为何还需要可学习的缩放系数

### 一句话总结

> **RMSNorm归一化抹掉"大小"但保留"形状"，weight给每个维度一个"全局音量"，让模型关注相对模式而非绝对数值。**

### 源码

```python
class Qwen2RMSNorm(nn.Module):
    def __init__(self, hidden_size, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size))  # 可学习缩放
        self.variance_epsilon = eps

    def forward(self, hidden_states):
        input_dtype = hidden_states.dtype
        hidden_states = hidden_states.to(torch.float32)
        variance = hidden_states.pow(2).mean(-1, keepdim=True)
        hidden_states = hidden_states * torch.rsqrt(variance + self.variance_epsilon)
        return self.weight * hidden_states.to(input_dtype)  # ← 归一化后再乘 weight
```

**公式表达**：

```
                 x
output = ─────────────── × γ
         √variance + ε

其中：
  x        = 输入向量
  variance = mean(x²)  沿最后一维
  ε        = 防止除零的小常数
  γ        = self.weight（可学习缩放系数）
```

### 两步操作的本质

| 步骤 | 操作 | 作用 |
|------|------|------|
| ① 除以RMS | `x / RMS(x)` | 抹掉绝对大小，保留维度间比例（"形状"），所有样本RMS=1 |
| ② 乘weight | `weight * x_norm` | 每个维度独立的全局缩放，让模型学习各维度重要性 |

### weight 为什么必要？

- **没有weight**：归一化后每个维度的尺度被强制统一，模型失去调整"哪个维度重要"的自由度
- **有weight**：模型可以把重要维度放大（weight>1），次要维度缩小（weight<1），对所有样本统一施加

### 关键边界：纯缩放样本无法区分

```
样本1: [2, -1, 3, 0.5]   归一化后: [1.06, -0.53, 1.59, 0.26]
样本2: [20, -10, 30, 5]  归一化后: [1.06, -0.53, 1.59, 0.26]  ← 10×样本1，结果相同！
样本3: [1, 0.5, -0.5, 2] 归一化后: [0.83, 0.42, -0.42, 1.66]  ← 不同分布，结果不同
```

样本1和样本2归一化后完全相同，weight也无法区分——但这不碍事，因为**纯缩放不改变语义**（"形状"一样）。

### 记忆口诀

```
归一化：去大小，留形状（RMS=1）
weight：调音量，分主次（维度独立）
纯缩放：归一后，变相同（形状一致）
不同样：归一后，仍不同（模式差异）
```

## 14. RoPE（旋转位置编码）完整总结 (2026.07)

### 一句话总结

> **RoPE用固定的"频率金字塔"（从高到低）乘上"递增的位置索引"（0,1,2,...），为每个位置、每个维度生成专属旋转角度，让模型通过不同维度分别捕捉从近到远的位置关系，实现高效的相对位置编码。**

### 三大核心要素

**① 频率（theta_i）** — 由维度决定，完全固定

```python
theta_i = 10000^(-2i/dim), i = 0, 1, 2, ..., dim/2-1
```

| 特点 | 高频（i小） | 低频（i大） |
|------|-----------|-----------|
| 频率值 | 大（如1.0） | 小（如0.001） |
| 旋转速度 | 快 | 慢 |
| 擅长捕捉 | 短距离依赖（相邻词） | 长距离依赖（远距离词） |
| 角色 | "显微镜"，关注局部 | "望远镜"，关注全局 |

**② 位置（pos）** — 由序列索引决定，所有维度共享

```python
pos = 0, 1, 2, 3, ..., seq_len-1
```

**③ 旋转角度 = pos × theta_i** — 每个位置、每个维度专属角度

### 五步工作流程

```
Step 1: 计算固定频率
inv_freq = 1.0 / (10000^(2i/dim)) = [1.0, 0.562, 0.316, 0.178, ...]
                                         高 → → → → → → → 低

Step 2: 位置 × 频率 = 角度矩阵
位置0: [0,    0,     0,     0,    ...]
位置1: [1.0,  0.562, 0.316, 0.178, ...]
位置2: [2.0,  1.125, 0.632, 0.356, ...]

Step 3: 复制匹配head_dim（每对维度共享同一频率）
维度对0(0,1)用θ₀, 维度对1(2,3)用θ₁, ...

Step 4: 计算cos/sin缓存
cos_cached = cos(emb), sin_cached = sin(emb)

Step 5: 应用到Q/K向量（逐维度对旋转）
x'_2i   = x_2i·cos(θ_i·pos) - x_{2i+1}·sin(θ_i·pos)
x'_2i+1 = x_2i·sin(θ_i·pos) + x_{2i+1}·cos(θ_i·pos)
```

### 关键特性

| 特性 | 说明 |
|------|------|
| 操作维度 | 每个向量的特征维度（head_dim），不是跨样本 |
| 参数共享 | 所有token、所有head、所有batch共用同一套频率 |
| 相对位置 | 两个token的相似度只依赖于相对距离 (m-n) |
| 多尺度 | 不同频率捕捉不同距离的依赖关系 |
| 预计算 | cos/sin可提前缓存，推理时直接查表 |

### rotate_half：旋转的真正执行者

**为什么有了 cos/sin 缓存还需要 rotate_half？**

cos_cached 和 sin_cached 只存储了"角度"，没有实现"旋转"。rotate_half 才是真正实现旋转矩阵交叉项的操作。

**数学本质**（以维度对 (x₀, x₁) 为例）：

```
旋转公式：
  x₀' = x₀·cos(θ) - x₁·sin(θ)    ← 需要 x₁（交叉项）
  x₁' = x₀·sin(θ) + x₁·cos(θ)    ← 需要 x₀（交叉项）
```

rotate_half 的作用就是构造交叉项：

```python
def rotate_half(x):
    x1 = x[..., : x.shape[-1] // 2]   # 前半
    x2 = x[..., x.shape[-1] // 2 :]   # 后半
    return torch.cat((-x2, x1), dim=-1)  # [-后半, +前半]

# 对 [x₀, x₁, x₂, x₃]
# rotate_half → [-x₁, x₀, -x₃, x₂]
```

**组合在一起**：

```
x * cos + rotate_half(x) * sin

= [x₀·cos, x₁·cos, x₂·cos, x₃·cos]
  + [-x₁·sin, x₀·sin, -x₃·sin, x₂·sin]

= [x₀·cos - x₁·sin, x₁·cos + x₀·sin, ...]  ← 真正的旋转！
```

**如果没有 rotate_half 会怎样？**

```python
# ❌ 只用 x * cos
q_rotated = q * cos  # 每个维度独立缩放，没有交叉

# 后果：
# - 失去相对位置编码能力，退化为逐元素缩放
# - 一个维度的输出只看自己，相邻维度互不干扰
# - 等同于普通位置嵌入，失去RoPE全部优势
```

**三者分工**：

| 组件 | 角色 |
|------|------|
| cos_cached / sin_cached | 存储旋转角度（cosθ, sinθ） |
| rotate_half | 提供交叉项（`[-x₁, x₀, -x₃, x₂, ...]`） |
| 两者结合 `x*cos + rotate_half(x)*sin` | 完整旋转矩阵 |

> **rotate_half 不是可选的装饰，而是旋转的核心——它让 x₀ 和 x₁ 能够互相影响，实现真正的2D旋转。**

### RoPE 三层架构：频率→角度→旋转

```
频率 (Frequency)  →  决定"转多快"  →  由维度决定（固定）
角度 (Angle)      →  决定"转多少"  →  由位置×频率决定
旋转 (Rotation)   →  真正"转起来"  →  用cos/sin + rotate_half实现
```

**第1层：频率** — 维度决定了齿轮大小

```python
theta_i = 10000^(-2i/dim)
# 高频(i小) = 小齿轮，转得快，对短距离敏感
# 低频(i大) = 大齿轮，转得慢，对长距离敏感
```

**第2层：角度** — 位置×频率决定转动圈数

```python
角度 = pos × theta_i
# 位置0→角度0（不转），位置1→角度θ，位置2→角度2θ
# 位置越大，转得越多；频率越高，角度增长越快
```

**第3层：旋转** — cos/sin + rotate_half 真正转动向量

```python
x' = x * cos(角度) + rotate_half(x) * sin(角度)
# 对维度对 (x₀, x₁):
#   x₀' = x₀·cos(θ) - x₁·sin(θ)
#   x₁' = x₀·sin(θ) + x₁·cos(θ)
```

**三层对照表**：

| 层次 | 概念 | 代码 | 决定因素 | 比喻 |
|------|------|------|---------|------|
| 1 | 频率 | `inv_freq` | 维度索引 i | 齿轮大小（转速） |
| 2 | 角度 | `pos × inv_freq` | 位置 × 频率 | 转动圈数 |
| 3 | 旋转 | `x·cos + rotate_half(x)·sin` | 角度 + 向量 | 最终位置 |

**一句话**：频率是"刻度"（转多快），角度是"读数"（转多少），旋转是"动作"（真正转起来）。

### RoPE 记忆口诀

```
频率固定维度定，位置递增角度增
高频看近低频远，协同捕捉全距离
每个向量独立转，位置编码妙无穷
```

## 15. Qwen2 模型完整结构 (2026.07)

> 来源：逐行分析 `modeling_qwen2.py`，Decoder-only Transformer

### 整体架构

```
输入: input_ids (B, N)
    │
    ▼
embed_tokens ─── nn.Embedding(vocab_size, hidden_size)
    │               查表得到每个 token 的向量
    ▼
┌──────────────────────────────────────────────────────────┐
│  Qwen2DecoderLayer × num_hidden_layers                   │
│                                                          │
│  residual ───────────────────────────────────► + ─┐      │
│  │                                                │      │
│  input_layernorm (RMSNorm)                        │      │
│  │                                                │      │
│  self_attn ──────────────────────────────────► + ─┤      │
│  │  ├─ q_proj:  hidden → q_heads × head_dim       │      │
│  │  ├─ k_proj:  hidden → kv_heads × head_dim      │ GQA  │
│  │  ├─ v_proj:  hidden → kv_heads × head_dim      │      │
│  │  ├─ RoPE (Q/K 注入位置信息)                    │      │
│  │  ├─ KV Cache → concat(历史K, 当前K) → 更新缓存 │      │
│  │  │            concat(历史V, 当前V)             │      │
│  │  ├─ repeat_kv (K/V 复制对齐 Q 头数)            │      │
│  │  ├─ Q @ [K_hist|K_cur]^T / √d   ← 注意力分数   │      │
│  │  ├─ + mask → softmax                           │      │
│  │  ├─ @ [V_hist|V_cur]            ← 加权求和     │      │
│  │  └─ o_proj:  多头输出 → hidden                 │      │
│  │                                                  │      │
│  residual ───────────────────────────────────► + ─┐  │      │
│  │                                                │  │      │
│  post_attention_layernorm (RMSNorm)               │  │      │
│  │                                                │  │      │
│  mlp (SwiGLU) ───────────────────────────────► + ─┘  │      │
│     ├─ gate_proj: hidden → intermediate              │      │
│     ├─ up_proj:   hidden → intermediate              │      │
│     ├─ SiLU(gate) * up                               │      │
│     └─ down_proj: intermediate → hidden              │      │
│                                                          │
│  ┌─ KV Cache 逐层读写 ─────────────────────────────┐     │
│  │ 训练: 不缓存                                    │     │
│  │ 推理: 每层 attn 结束后 K_cur,V_cur 追加进缓存   │     │
│  │       下一 token 来时 concat 历史 K,V 一起算     │     │
│  └─────────────────────────────────────────────────┘     │
└──────────────────────────────────────────────────────────┘
    │
    ▼
norm (RMSNorm) ─── 最后归一化
    │
    ▼
lm_head ─── nn.Linear(hidden_size, vocab_size), bias=False
    │         与 embed_tokens 共享权重 (tied weights)
    ▼
输出: logits (B, N, vocab_size) → 每个位置预测下一个 token

loss = CrossEntropyLoss(shift(logits), shift(labels))
```

### 关键设计

| 设计项 | 做法 |
|--------|------|
| 归一化 | Pre-Norm + RMSNorm（只缩放不去均值） |
| 激活函数 | SiLU (Swish) → SwiGLU MLP |
| 位置编码 | 1D RoPE，预计算 cos/sin 缓存查表，推理超长序列时动态扩展 |
| 注意力 | GQA：28 个 Q 头 / 4 个 K/V 头，KV 缓存减少 7 倍 |
| KV Cache | 每层存 K/V 原始投影结果(不加权)，推理时 concat 历史，每次用新 Q 动态加权所有历史 V |
| 注意力后端 | eager / flash_attn_2 / sdpa / magi 四种可切换 |
| 权重绑定 | embed_tokens.weight = lm_head.weight |
| 训练优化 | gradient checkpointing 逐层重算省激活显存 |

### 各模块职责

| 模块 | 类名 | 职责 |
|------|------|------|
| RMS 归一化 | `Qwen2RMSNorm` | `x / RMS(x) * weight`，去大小留形状 |
| 旋转位置编码 | `Qwen2RotaryEmbedding` | 预计算 cos/sin 缓存，按位置查表 |
| SwiGLU MLP | `Qwen2MLP` | `down(SiLU(gate(x)) * up(x))`，门控信息流 |
| 注意力基类 | `Qwen2Attention` | Q/K/V 投影 + RoPE + GQA + masked softmax |
| Flash Attn | `Qwen2FlashAttention2` | pad→unpad→varlen_flash_attn→pad 回来 |
| SDPA Attn | `Qwen2SdpaAttention` | `F.scaled_dot_product_attention` 自动选后端 |
| Magi Attn | `Qwen2MagiAttention` | 范围稀疏注意力，支持 MTP packing 训练 |
| Decoder 层 | `Qwen2DecoderLayer` | Pre-Norm + Attn + Pre-Norm + MLP |
| Transformer | `Qwen2Model` | embed + N×layers + norm |
| 因果 LM | `Qwen2ForCausalLM` | Qwen2Model + lm_head + loss |

### 数据流

```
input_ids (B, N)
  → embed_tokens → (B, N, hidden)
  → N × DecoderLayer:
      norm → attn(Q/K/V投影→RoPE→KV Cache拼接→repeat_kv→flash/sdpa/eager→o_proj) → +residual
      norm → mlp(gate/up→SiLU→*) → down → +residual
  → norm
  → lm_head → (B, N, vocab_size) logits
  → shift logits/labels → CrossEntropyLoss

推理时: 每层 attn 结束后 K_cur,V_cur 追加进 KV Cache
        下一 token 来时 concat(历史K,当前K)、concat(历史V,当前V) 一起算 attention
        历史 token 不需要重新走 embed → transformer，只存 K/V 原始向量
```

### 对比 MoonViT (Vision Encoder)

| | Qwen2 (LLM) | MoonViT (ViT) |
|---|---|---|
| 类型 | Decoder-only | Encoder-only |
| 位置编码 | 1D RoPE | 2D RoPE (row+col) |
| 注意力 | causal=True | causal=False |
| 序列格式 | (B, N, d) 或 packed | packed (Σh*w, d) + cu_seqlens |
| MLP | SwiGLU (3 条线) | Standard (2 条线) |
| 归一化 | RMSNorm | LayerNorm |
| 输出 | logits 预测下一个 token | visual features 送给 LLM |
| mask | causal 三角形 | block-diagonal 块对角 |

## 16. KV Cache 核心机制 (2026.07)

> 来源：分析 Qwen2Attention.forward 中 past_key_value 的读写逻辑

### 一句话总结

> **KV Cache 把历史 token 的 K、V 向量存下来，新 token 推理时直接拼接，历史 token 不再重新走 embed → transformer → 投影，只需用新 Q 动态加权所有历史的 V。**

### 缓存的是什么

存的是**经过投影 + RoPE 后的原始 K 和 V**，即 `self.k_proj(x)` 和 `self.v_proj(x)` + RoPE 之后的输出，**没有经过 attention 加权**。

```
存入: K_raw, V_raw    ← 投影 + RoPE 后直接存，不变
每次用: Q_new @ K_all^T → softmax → @ V_all    ← 用最新的 Q 重新动态加权
```

attention 的加权是 `softmax(QK^T/√d) @ V` 这一步的事，和缓存无关。缓存的 V 是"原材料"，每次用新 Q 重新算一遍权重。

### 自回归推理时发生了什么

```
第1步: "今天"  → embed → layer0...layerN → 预测 "天气"
       每层缓存 K₁, V₁

第2步: "天气"  → embed → layer0:
       Q₂ @ [K₁|K₂]^T → softmax → @ [V₁|V₂] → 输出
       每层缓存 K₂, V₂ 追加到后面

第3步: "不错"  → embed → layer0:
       Q₃ @ [K₁|K₂|K₃]^T → softmax → @ [V₁|V₂|V₃] → 输出
```

每次 Q 只看当前这 1 个 token，但 K/V 是全部历史，所以 Q 能 attend 到前面的所有 token。

### 省了什么

```
没有 KV Cache:
  token1 → embed → layer0→...→layerN → 预测
  token2 → embed → layer0→...→layerN → 预测  ← token1 重新走一遍所有层
  token3 → embed → layer0→...→layerN → 预测  ← token1,token2 又重算

有 KV Cache:
  token1 → embed → layer0→...→layerN → 预测，存每层 K,V
  token2 → embed → layer0(K,V拼接)→...→layerN(K,V拼接) → 预测  ← token1 不再重算
  token3 → embed → layer0(K,V拼接)→...→layerN(K,V拼接) → 预测  ← token1,token2 不再重算
```

省的不是 `embed_tokens` 这一层（新 token 还是要 embed 的），省的是**历史 token 在所有 N 层 transformer 中重算 Q/K/V 投影 + attention + MLP** 的全部计算。

### GQA 进一步压缩 KV Cache

```
MHA (28 个 KV 头): 每层存 2 × 28 × seq_len × 128 个 float
GQA (4 个 KV 头):  每层存 2 ×  4 × seq_len × 128 个 float  ← 1/7 的显存

50 层 × 4096 token:
  MHA: 2 × 28 × 50 × 4096 × 128 × 2 bytes ≈ 2.7 GB
  GQA: 2 ×  4 × 50 × 4096 × 128 × 2 bytes ≈ 0.4 GB
```

长序列生成时 KV Cache 是显存的主要占用者，GQA 就是为这个设计的。

## 17. Transformer Decoder Layer 完整数据流与 Pre-Norm 残差机制 (2026.07)

> 来源：分析 `modeling_qwen2.py` 中 `Qwen2DecoderLayer.forward()` 的逐行逻辑

### 一句话总结

> **每个 Decoder Layer 在上一层的表示上累加两次增量——Attention 负责"和别人交流"融合上下文，MLP 负责"自己思考"提炼特征。Pre-Norm 让计算分支输入稳定，残差路径让主干信息无损传播。**

### 源码追踪：Qwen2DecoderLayer.forward()

```python
def forward(self, hidden_states, ...):
    # ──── Attention 子层 ────
    residual = hidden_states                                    # ① 保存残差(原始x)
    hidden_states = self.input_layernorm(hidden_states)         # ② Pre-Norm: 归一化后再进Attn
    hidden_states = self.self_attn(hidden_states, ...)          # ③ Attention计算
    hidden_states = residual + hidden_states                    # ④ 残差加法: 原始x + Attn增量

    # ──── MLP 子层 ────
    residual = hidden_states                                    # ⑤ 保存残差(Attn后的中间值)
    hidden_states = self.post_attention_layernorm(hidden_states) # ⑥ Pre-Norm: 归一化后再进MLP
    hidden_states = self.mlp(hidden_states)                     # ⑦ SwiGLU MLP
    hidden_states = residual + hidden_states                    # ⑧ 残差加法: 中间值 + MLP增量
```

### 精确数据流图

```
x (原始输入)
│
├────────────────────────────────────┐ (residual1 = x)
│                                    │
├─ input_layernorm ──→ self_attn ──→ + ──→ x_attn  ← 原始信息 + 上下文融合
│                                    │
│  x_attn = x + attn_out
│
├────────────────────────────────────┐ (residual2 = x_attn)
│                                    │
├─ post_attention_layernorm ──→ mlp ──→ + ──→ x_out   ← ... + 特征提炼
│                                    │
│  x_out = x_attn + mlp_out = x + attn_out + mlp_out
```

### 两个子层的职责

| 子层 | 做了什么 | 增量含义 |
|------|---------|---------|
| **Attention** | 每个 token 的 Q 去匹配所有 K，加权读取各处的 V，汇总上下文 | **"别人说了什么相关的"** — 从全序列拉取信息 |
| **MLP (SwiGLU)** | 把 Attention 融合后的向量做非线性升维→门控筛选→降维，提炼更高层抽象特征 | **"把这些信息重新消化一下"** — 独立思考 |

**注意**：Attention 是 token 之间"交流"（cross-token），MLP 是每个 token 独立"思考"（per-token），两者分工明确。

### Pre-Norm vs Post-Norm：为什么"先归一化，后残差"

**原始 Transformer (Post-Norm)**：
```
x ──→ Attn ──→ + ──→ LayerNorm ──→ MLP ──→ + ──→ LayerNorm ──→ 输出
       ↑                                  ↑
       └── 残差 ──────────────────────────┘
```

**Qwen2 / LLaMA (Pre-Norm)**：
```
x ──→ LayerNorm ──→ Attn ──→ + ──→ LayerNorm ──→ MLP ──→ + ──→ 输出
      ↑                         ↑
      给Attn的输入做归一化      给MLP的输入做归一化
```

关键区别：
- **Post-Norm**：残差加法后的整个输出再过归一化 → 残差恒等映射被打破 → 深层梯度消失
- **Pre-Norm**：归一化只在计算分支上（Attn 和 MLP 之前），残差路径完全不打折扣 → 训练稳定、梯度不爆炸

### 为什么残差和归一化后的值可以相加？

```
residual = x                     # 原始尺度，分布自由
x_norm   = layernorm(x)          # 被压缩到 RMS≈1 的稳定分布
attn_out = attention(x_norm)     # 在稳定分布上计算，输出也在归一化尺度附近
output   = residual + attn_out   # 大尺度 x + 小尺度增量 = 微调
```

这**不是 bug 是 feature**：
- **残差路径**：保持信号主干，传播不受 norm 干扰，梯度无损回传
- **计算路径**：norm 把输入压缩到稳定分布，注意力矩阵不会因为输入漂移而爆炸/消失
- **attn_out / mlp_out 本质是"增量"(delta)**，不是"替换"整个表示

类比：残差 = 电流主干，Attn/MLP = 在主干上叠加的微调信号。Norm 只控制微调信号的幅度，不碰主干。

### 每一层输出 = 原始信息 + 两层增量

```
x_out = x                    ← 原始语义
      + attn_out             ← 第1层增量: 从其他token拉来的上下文信息
      + mlp_out              ← 第2层增量: 非线性特征拆分重组
```

堆叠 N 层后，token 的表示 = 原始 embedding + N 次注意力的上下文累积 + N 次 MLP 的抽象提炼。**残差保证"身份"不丢，Attn/MLP 负责越来越深的"理解"。**

## 18. BERT 模型核心机制 (2026.07)

> 来源：分析 `modeling_bert.py`，理解 MLM 掩码预测、双向注意力与 GPT 的根本区别

### 一句话总结

> **BERT 通过 MLM（Masked Language Model）随机 mask 掉 15% token，让被 mask 位置用 Q 去双向 attend 周围所有 token 来预测自己，核心就是 Encoder + bidirectional attention mask，没有生成能力。**

### BERT vs GPT 架构对比

| | BERT | GPT |
|---|---|---|
| 结构 | Transformer Encoder-only | Transformer Decoder-only |
| Attention mask | `create_bidirectional_mask` — 全开放 | `create_causal_mask` — 三角/下三角 |
| 能看到的方向 | 左边 + 右边 | 只有左边 |
| 预训练任务 | MLM（完形填空） | NTP（预测下一个词） |
| 生成能力 | 无（不能自回归生成文本） | 有（逐 token 生成） |
| 复杂度 | 简单，纯 encoder 堆叠 | 更复杂：KV Cache、采样策略、自回归循环 |
| KV Cache | 训练和推理都**不需要**（一次前向） | 推理必须用，否则每步重算全部历史 |
| 典型用途 | 语义理解、分类、NER、问答 | 文本生成、对话、代码生成 |

代码证据（`modeling_bert.py:693-713`）：

```python
def _create_attention_masks(self, attention_mask, ...):
    if self.config.is_decoder:
        attention_mask = create_causal_mask(...)       # GPT 那种，三角 mask
    else:
        attention_mask = create_bidirectional_mask(...) # BERT 默认，全部可见
```

### MLM（Masked Language Model）工作机制

核心问题：**被 [MASK] 的 token 是怎么被预测出来的？**

```
输入: "我 [MASK] 苹果"  →  3 个 token，[MASK] 有自己的 embedding
                ↓
          Self-Attention
                ↓
  [MASK] 的 Q ──→ 和所有 token 的 K 算相似度（包括 "我" 和 "苹果"）
         │
         ├── "我" 的 V 被拉过来（包含主语信息）
         ├── "苹果" 的 V 被拉过来（包含宾语信息）
         └── 融合后的向量 → 分类头 → 预测出 "吃"
```

每一步的细节：

1. **输入层**：[MASK] 是一个真实的 token（有自己的 ID 和 embedding），不是空位，不是"跳过"
2. **Attention 层**：[MASK] 作为 Q 去匹配所有位置（包括自己）的 K，因为 bidirectional_mask **不做方向限制**，所以能看到"我"和"苹果"两个方向的语义
3. **输出层**：[MASK] 位置的输出向量融合了双向上下文，过 `BertLMPredictionHead`（一个带 GeLU + LayerNorm 的变换 + 输出投影到 vocab_size），选出概率最高的 token

**为什么不用 causal mask？** 如果像 GPT 那样只允许从左到右看，"苹果"这个词的信息就到不了 [MASK] 的位置，预测就瞎猜了。MLM 任务本身决定了必须双向。

### BERT 能不能用 top-k / top-p 采样？

**技术上完全可以**，`BertForMaskedLM` 输出的就是 `(vocab_size,)` 的概率分布：

```python
prediction_scores = self.cls(sequence_output)  # (batch, seq_len, vocab_size)
# softmax 之后，top-k、top-p、temperature 随便用
```

**但实际不这么做**，原因不是能力问题，是场景不一样：

| | GPT 的 top-k/top-p | BERT 为什么不需要 |
|---|---|---|
| 生成方式 | 自回归：一次采一个 token，采出来的 token **喂回去当下一步输入** | 并行：所有 [MASK] 一次性预测，**没有反馈回路** |
| 为什么需要采样 | 贪心(argmax)会导致误差级联放大、文本重复退化 | 无反馈回路，不存在"上一步错下一步更错" |
| 错误传播 | 会：一步错 → 步步错 | 不会：各 [MASK] 独立预测 |
| 采样目的 | 在确定性和多样性间找平衡，防止退化 | 通常只要 argmax 就够了（填空追求准确，不追求多样性） |

**核心结论**：top-k / top-p 是为**自回归生成的反馈回路**设计的药方，BERT 没有这个病。但不妨碍你用——如果你想让 BERT 给每个 [MASK] 位置输出多个候选词，直接 softmax → top-k 取出来就行。

### BERT 不需要 KV Cache

GPT 的 KV Cache 是为了省掉"历史 token 重走 transformer"的计算——每次只算新 token，历史 K/V 从缓存读。

BERT 一次前向就能看到所有 token（包括所有 [MASK]），不需要分步生成，没有"历史"和"当前"之分，所以**训练和推理都不需要 KV Cache**。这也是 Encoder-only 结构更简单的原因之一。

## 19. 自回归模型训练与推理流程对比 (2026.07)

> 来源：理解 chat_template → tokenizer → 词表 → 生成停止的完整链路，区分训练和推理

### 一句话总结

> **训练：完整问答一次前向，BOS+EOS 数据给齐，只看 answer 部分算损失。推理：只有 BOS 给进去，模型一步步自回归生成，吐出 EOS 时停止。**

---

### 训练流程（数据准备 → 一次前向 → 损失计算）

```
训练数据: {"prompt": "今天天气如何", "answer": "天气不错"}

① chat_template 拼模板（训练：BOS 和 EOS 都加）
    ▼
  "<BOS>user\n今天天气如何\nassistant\n天气不错<EOS>"
    │
    ▼
② 分词 → BPE 合并 → 查词表转 ID
    ▼
  [BOS, user, \n, 今天, 天气, 如何, \n, assistant, \n, 天气, 不错, EOS]
   └──── prompt tokens ────┘└──── answer tokens ────┘
    │
    ▼
③ 一次前向（teacher forcing），不需要自回归循环
   模型同时看到所有 token，每个位置预测下一个 token：
     [BOS]       → 预测 user
     [BOS, user] → 预测 \n
     ...
     [..., 天气] → 预测 EOS  ← 模型学到"答完该停"
    │
    ▼
④ 只对 answer 部分（含 EOS）算损失，prompt 部分 mask 掉
   loss = CrossEntropy(logits[answer部分], labels[answer部分])
    │
    ▼
⑤ loss.backward() → 更新参数
```

**关键点**：
- 训练时一次前向就完成了，不需要 for 循环，因为答案已经知道（teacher forcing）
- EOS 是训练数据给的，作为 answer 的最后一个 token 参与损失计算，模型学到"答完该输出 EOS"
- **只对 answer tokens 算损失**，prompt 部分被 mask 掉（`label = -100`），不贡献梯度

---

### 推理流程（用户输入 → 自回归循环 → EOS 停止）

```
用户输入: "今天天气如何"

① chat_template 拼模板（推理：只加 BOS，不加 EOS）
    ▼
  "<BOS>user\n今天天气如何\nassistant\n"
    │
    ▼
② 分词 → BPE 合并 → 查词表转 ID
    ▼
  [BOS, user, \n, 今天, 天气, 如何, \n, assistant, \n]
   └──── prompt tokens ────┘
   （没有 answer，没有 EOS）
    │
    ▼
③ 自回归生成（逐个 token 输出，拼回去再喂给模型）

   step 1: 输入 [BOS, user, ..., assistant, \n]  → 预测 "天"
   step 2: 输入 [BOS, user, ..., assistant, \n, 天]  → 预测 "气"
   step 3: 输入 [..., 气]  → 预测 "不"
   step 4: 输入 [..., 不]  → 预测 "错"
   step 5: 输入 [..., 错]  → 预测 EOS  ← 模型自己判断"答完了"
    │
    ▼
④ 命中 eos_token_id → break，停止生成
   最终输出: "天气不错"
```

**关键点**：
- 推理时必须自回归循环，因为下一步要等上一步的输出
- EOS 是模型自己生成的，模板不给
- KV Cache 让历史 token 不重算，否则每步都重跑整个序列

---

### 训练 vs 推理 核心区别

```
                       训练                          推理
                   ──────────────              ──────────────
输入:   完整 BOS+prompt+answer+EOS     只有 BOS+prompt
EOS:    数据给的，参与损失计算           模型自己生成的
前向:   一次，所有 token 同时看到         多次自回归，每次多看一个 token
输出:   已有，不需要生成                 一步步生成出来
损失:   只算 answer 部分               不需要算损失
Teacher forcing:  是                    否
KV Cache:  不需要                       必须用，否则 O(n²) 重算
```

### 伪代码对比

```python
# ===== 训练 =====
input_ids = tokenizer("[BOS]user\n今天天气如何\nassistant\n天气不错[EOS]")
labels    = input_ids.clone()
labels[:prompt_len] = -100        # mask 掉 prompt 部分
logits = model(input_ids)         # 一次前向
loss   = CrossEntropyLoss(logits, labels)
loss.backward()

# ===== 推理 =====
input_ids = tokenizer("[BOS]user\n今天天气如何\nassistant\n")  # 没有 EOS
while len(input_ids) < max_length:
    logits = model(input_ids, use_cache=True)   # KV Cache 加速
    next_token = logits[-1].argmax()
    if next_token == eos_token_id:
        break
    input_ids.append(next_token)
```

---

### 每一步详解

#### chat_template 的作用

把用户输入包装成模型训练时见过的对话格式。**训练和推理加的 token 不同**：

```python
# 训练：BOS + prompt + answer + EOS 全给
"<|im_start|>user\n今天天气如何<|im_end|>\n<|im_start|>assistant\n天气不错<|im_end|>"

# 推理：只给 BOS + prompt，answer 和 EOS 都是空的
"<|im_start|>user\n今天天气如何<|im_end|>\n<|im_start|>assistant\n"
```

#### 分词 + BPE 合并 + 查词表

训练和推理共享同一套流程：

1. 特殊 token 不切分（BOS、角色分隔符等在词表里有独立条目）
2. 普通文本先拆到字符级，再按 BPE merge 规则逐一尝试合并：
   ```
   "今天天气" → "今" "天" "天" "气"
                 ↓ merge("今","天") → 词表里有 "今天" → 合并 ✓
                 ↓ merge("天气","天") → 词表里没 "天气天" → 不合并 ✗
                 ↓ merge("天","气") → 词表里有 "天气" → 合并 ✓
                 → "今天" "天气"
   ```
3. 查词表转 ID（纯字典查找，不涉及模型）

#### BOS 和 EOS 的职责

| token | 训练时的角色 | 推理时的角色 |
|-------|------------|------------|
| BOS | 给序列起跑点 | 给第一步生成起跑点 |
| EOS | 作为 answer 最后一个 token 参与损失，让模型学会"这里该停" | 模型自己生成出来，代码遇到就 break |

**关键**：BOS/EOS 不是模型内部的魔法，它们就是词表里普通的 embedding 向量。是 config 里的 `bos_token_id` / `eos_token_id` 告诉代码：生成时从这开始，到这停下。

---

### 与 BERT 的对比

```
BERT（理解）:  输入 "[CLS] 今天 天气 [SEP]" → 一次前向 → 理解完毕
GPT（生成）:   输入 "<BOS>" → 预测"今天" → "<BOS>今天" → 预测"天气" → ... → 输出<EOS>停
```

BERT 不需要 BOS/EOS 控制起停——拿完整输入，产出理解结果，一次结束。GPT 需要这两个标记是因为它得知道从哪开始、在哪停。

## 20. 大模型指令微调的数据组织与批次训练机制 (2026.07)

> 来源：讨论多任务指令微调时，批次内样本如何混合、损失如何计算、梯度是否冲突

### 一句话总结

> **指令微调时所有任务的样本打散混在一起 shuffle，每个 batch 内什么任务都有，损失按 token 独立计算（prompt 部分 mask 掉），梯度按样本累加后取平均，模型往"对所有任务都还行"的方向收敛。**

### 为什么要混在一起而不是按任务分批次？

**直觉（按任务分批）**：

```
batch 1: 全是翻译任务 → 算翻译损失 → 更新参数
batch 2: 全是代码任务 → 算代码损失 → 更新参数
batch 3: 全是对话任务 → 算对话损失 → 更新参数
```

问题：后面学的覆盖前面学的 → **灾难性遗忘**（catastrophic forgetting）。

**实际做法（打散混合）**：

```
一个 batch 8 条样本：
  sample 1: 翻译   "Translate: 你好 → Hello"
  sample 2: 代码   "写快速排序 → def quicksort..."
  sample 3: 摘要   "总结文章 → 本文讨论了..."
  sample 4: 数学   "1+1= → 2"
  sample 5: 翻译   ...
  sample 6: 对话   ...
  sample 7: 代码   ...
  sample 8: 数学   ...
```

### 损失如何计算：per-sample token-level

```python
loss = 0
for each sample in batch:
    logits = model(sample.prompt)         # 前向
    loss += cross_entropy(logits, sample.target)  # 只看 target token 的损失
loss = loss / batch_size
loss.backward()  # 所有样本的梯度加在一起更新参数
```

**关键设计**：prompt 部分的 token 不参与损失计算（被 mask 掉），只有回答部分的 token 才贡献梯度。等价于：

- 翻译样本说"这条路好"（只对翻译那几个 target token 回传梯度）
- 代码样本说"那条路好"（只对代码那几个 target token 回传梯度）
- 模型汇总所有人的意见，往"对所有任务取平衡"的方向走一步

### 梯度冲突是存在的，但不是致命问题

**梯度冲突**：两个任务对同一参数的更新方向可能正好相反。例如翻译任务想让某参数变大，代码任务想让同一个参数变小。

为什么实践中不致命：

| 原因 | 说明 |
|------|------|
| 参数够多 | 大模型有足够容量，不同任务会自然地"占领"不同的参数子空间，不会互相抹掉 |
| batch 够大、任务够杂 | 冲突在大量样本中平滑掉，极端个例互相抵消的概率很低 |
| 学习率够小 | 每一步只动一点点，不会因为一个 batch 的冲突让某任务废掉 |

**真遇到严重冲突时的解法**：调整数据配比（给弱势任务多采样几次），而不是分批次训练。

### 对比：直觉做法 vs 实际做法

| | 按任务分批（直觉） | 打散混合（实际） |
|---|---|---|
| Batch 构成 | 同一任务 | 什么任务都有 |
| 损失计算 | 任务级 | token级（per-sample 独立算） |
| 主要问题 | 灾难性遗忘，后面的覆盖前面的 | 梯度冲突（靠数据配比缓解） |
| 为什么可行/不可行 | 顺序训练抹掉旧知识 | 梯度自然叠加，模型找全局平衡点 |

### 类比

所有任务同时"投票"——翻译说往东，代码说往西，100 个翻译样本和 100 个代码样本各投各的票，模型一步只走学习率那么大的步子，最终稳定在所有任务的"折中位置"，而不是被某个任务单方面支配。

### 数据配比（Data Mixing）的重要性

不同任务的样本数量不是 1:1 就完事的。实际训练中会根据：

- 任务难度（数学比对话难，需要更多样本）
- 下游需求（目标场景需要更强的代码能力 → 提高代码数据占比）
- 退化风险（某个任务数据太多会挤掉其他能力）

来设定每个任务的采样权重。这是"炼丹"的核心调参之一，比网络结构改动影响更大。

## 21. SfM（运动恢复结构）完整流程 (2026.07)

> 来源：分析 3D Gaussian Splatting 中 COLMAP 的 SfM 流程

### 一句话总结

> **SfM 纯靠多视角 2D 图像之间的几何约束，交替迭代地恢复相机位姿和 3D 点云，不需要任何 GPS/IMU 等硬件传感器，但输出的场景缺少真实世界尺度（差一个未知的缩放因子 s）。**

### 完整流程

```
输入: 多视角 2D 图像（只有像素，没有深度、没有 GPS）
    │
    ▼
① 所有图像提取 SIFT 特征点
   每张图 → 关键点 + 128维描述子
    │
    ▼
② 两两匹配（exhaustive matching, O(n²)）
   图A的描述子 vs 图B的描述子 → 找到相同的特征点
   → 匹配对 (u₁,v₁) ↔ (u₂,v₂)
    │
    ▼
③ 选两张初始图，对极几何算相对位姿（不需要3D点）
   x₂ᵀ · E · x₁ = 0  （x = K⁻¹[u,v,1]ᵀ，归一化方向向量）
   → SVD 分解本质矩阵 E → 4种可能的 R,T → 三角化验证 → 唯一解
   → 第2台相机相对第1台的 R, T（尺度未知）
    │
    ▼
④ 三角测量出第一批 3D 点
   已知: 相机1位姿、相机2位姿、匹配点对
   P = C₁ + t₁·d₁ = C₂ + t₂·d₂
   → 最小二乘解 t → 代入得 3D 点 P
    │
    ▼
⑤ 逐张加入剩余图片（增量注册）
   新图 + 已有3D点 → PnP 解新相机位姿
   新相机 + 已有相机 → 三角测量扩充更多3D点
    │
    ▼
⑥ 重复⑤，直到所有图片加入
    │
    ▼
⑦ 全局 BA 优化（Bundle Adjustment）
   min Σ ||投影(Pⱼ, 相机ᵢ) - 实际像素坐标||²
   → 所有相机位姿 + 所有3D点一起非线性优化
   → Levenberg-Marquardt 迭代最小化重投影误差
    │
    ▼
输出:
   - cameras.bin   相机内参（焦距、分辨率）
   - images.bin    相机外参（R: 四元数 QW,QX,QY,QZ, T: 平移 TX,TY,TZ）
   - points3D.bin  稀疏3D点云（位置 + RGB颜色）
```

### 核心机制

#### 对极几何：从匹配点到相对位姿

**本质矩阵 E 的几何含义**：左图光心 C₁、右图光心 C₂、3D点 P，三点共面的约束。

已知：N 对匹配点的归一化坐标 `x₁ = K⁻¹[u₁,v₁,1]ᵀ`, `x₂ = K⁻¹[u₂,v₂,1]ᵀ`
约束：`x₂ᵀ E x₁ = 0`

8点法求解：
```
[u₂u₁, u₂v₁, u₂, v₂u₁, v₂v₁, v₂, u₁, v₁, 1] · vec(E) = 0
堆 N 行 → N×9 矩阵 → SVD → 最小奇异值对应 vec(E) → 恢复 E
E = U · diag(1,1,0) · Vᵀ  （强制 rank=2）
→ 分解出 R, T（4选1，深度>0为正确答案）
```

#### 三角测量：从位姿+匹配点求解3D点

```
已知: C₁, d₁, C₂, d₂（两台相机的位置和方向向量）
方程: t₁·d₁ - t₂·d₂ = C₂ - C₁
     [d₁, -d₂] · [t₁; t₂] = C₂ - C₁  →  最小二乘解
P = (C₁ + t₁d₁ + C₂ + t₂d₂) / 2
```

**方向向量 d 从哪来**：从像素坐标反算，从相机光心射向物理世界：
```
d_cam = K⁻¹ · [u, v, 1]ᵀ     ← 相机坐标系下的方向
d_world = R · d_cam            ← 旋转到世界坐标系
```

### 关键问题

#### Q: 尺度为什么是未知的？

对极几何分解出的 T 只有方向没有大小——你只知道"相机2在相机1的右边"，但不知道是 1 米还是 100 米。所有 3D 点也等比缩放。必须有一个外部尺度参考才能确定 s：
- 已知两台相机的真实距离
- 场景中有已知尺寸的标定物
- GPS/IMU 提供的真实相机位姿（→ 直接计算出 s）
- 激光雷达提供的参考距离

#### Q: 有 GPS/IMU 可以干嘛？

| | 纯视觉 SfM | 有传感器 |
|---|---|---|
| R（朝向）| 对极几何+BA 算 | IMU 直接测 |
| C（位置）| 对极几何+BA 算 | GPS 直接测 |
| 尺度 | 未知 s | 1:1，真实米 |
| 实际用法 | SfM 输出 | 传感器给初值 + 约束，BA 再精化 |

#### Q: 两两匹配的具体策略？

- **exhaustive_matcher**: 每张和所有其他图配，O(n²)，几十几百张图用
- **sequential_matcher**: 只和相邻帧配，O(n)，适合视频流
- **vocab_tree_matcher**: 用视觉词袋筛出相似图再配，适合几千张大规模场景

### 流程顺序记忆

```
提取特征点 → 两两匹配
    → 选初始两张图 → 对极几何算相对位姿 → 三角测量出第一批3D点
    → 加新图 → PnP算新相机位姿 → 三角测量扩充点云 → 再加下一张...
    → 全部加完 → BA全局优化
```

**位姿和点云是交替增长的，不是先算完位姿再算点。**

## 22. 3DGS 训练与评测的完整流程 (2026.07)

> 来源：分析 `gaussian-splatting` 工程代码（`train.py` / `render.py` / `metrics.py` / `convert.py`）

### 一句话总结

> **训练：用 COLMAP 反推的相机位姿，把 3D 高斯椭球逐一投影到训练视角，和真实照片对比算 L1+SSIM 损失，反向传播优化每个高斯的参数，同时定期增删点。评测：用训练时没见过的测试视角，把高斯投影出来和真实测试图对比，算 PSNR/SSIM/LPIPS 量化指标。**

---

### 1. 数据准备阶段

```
拍摄物体/场景的多角度照片（或视频抽帧）
        ↓
COLMAP 特征提取 + 匹配 + BA 优化
        ↓
输出：
  - cameras.bin   相机内参（fx, fy, width, height）
  - images.bin    相机外参（R 旋转矩阵, T 平移向量，即 position）
  - points3D.bin  稀疏点云（几万个 3D 点）
```

相机参数示例（工程中的 `cameras.json` 格式）：

```json
{
  "img_name": "00001.jpg",
  "width": 1255,
  "height": 702,
  "position": [-1.057, 1.613, -3.945],
  "rotation": [[...], [...], [...]],
  "fx": 1092.40,
  "fy": 1089.69
}
```

| 参数 | 含义 |
|------|------|
| `position` | 相机中心在世界坐标系中的 3D 位置 |
| `rotation` | 3×3 旋转矩阵，相机朝向 |
| `fx`, `fy` | 像素焦距，决定视野宽窄 |
| `width`, `height` | 图像分辨率 |

**position + rotation = 外参（相机在世界中的位姿）**
**fx/fy + 分辨率 = 内参（相机成像特性）**

---

### 2. 训练阶段（`train.py`）

```
稀疏点云（几万个点）
    ↓
【初始化】每个点 → 一个 3D 高斯椭球
    ↓
循环迭代 30000 次（默认）
    │
    ├─ 每一步都做的事：
    │   ① 随机选一张训练图片
    │   ② 用该图片的相机位姿，把 3D 高斯投影成 2D 图像
    │   ③ 和真实照片对比，计算 L1 Loss + SSIM Loss
    │   ④ 反向传播 → 优化高斯的 位置/形状/不透明度/SH颜色
    │
    └─ 每 100 步做的事：
        ① 密集化（densify）：梯度大的点分裂/克隆
        ② 剪枝（prune）：不透明度太低或太大的点删除
        ③ 定期重置不透明度，防止透明度累积错误
    ↓
保存训练好的高斯模型（`point_cloud/iteration_30000/point_cloud.ply`）
```

#### 损失函数

```python
L_total = L1(渲染图, 真实图) + λ × (1 - SSIM(渲染图, 真实图))
```

| 损失 | 作用 |
|------|------|
| L1 Loss | 像素绝对值差异，保证颜色和亮度准确 |
| SSIM Loss | 结构相似性，保证边缘和纹理不失真 |

#### 优化哪些参数

| 参数 | 意义 |
|------|------|
| 位置 μ | 高斯中心在哪 |
| 协方差 Σ | 高斯的形状（尺度 × 旋转） |
| 不透明度 α | 0=透明，1=不透明 |
| 球谐系数 SH | 不同观察方向下的颜色 |

#### 密集化与剪枝

```
每 100 步检查一次：

密集化：
  - 位置梯度大 + 尺度大 → 分裂成两个更小的点
  - 位置梯度大 + 尺度小 → 克隆一个副本沿梯度方向移动

剪枝：
  - 不透明度 < 阈值 → 删除（看不见，没用）
  - 尺度异常大 + 位置空旷 → 删除（漂浮噪声点）
```

**点的数量变化**：初始几万个 → 训练中可能激增到百万级 → 最终稳定到几十万级。

---

### 3. 评测阶段（`render.py` + `metrics.py`）

```
加载训练好的高斯模型
    ↓
对测试集中的每一张图：
  ① 读取该图的相机位姿（来自 COLMAP，训练时没用过）
  ② 用相同位姿把高斯投影成 2D 图像
  ③ 保存渲染图，同时保存真实图作为 gt
    ↓
metrics.py 对比渲染图和真实图
    ↓
输出 PSNR / SSIM / LPIPS
```

#### 评测的本质

```
训练时：用训练视角 → 教模型“从这里看应该长什么样”
评测时：用测试视角 → 考模型“从没见过的角度看，你还能不能画对”
```

#### 评测指标

| 指标 | 含义 | 好坏方向 |
|------|------|---------|
| PSNR | 峰值信噪比，衡量像素差异 | ↑ 越高越好 |
| SSIM | 结构相似性，衡量亮度/对比度/结构 | ↑ 越高越好 |
| LPIPS | 感知距离，用神经网络特征衡量视觉差异 | ↓ 越低越好 |

#### 运行命令

```bash
# 1. 训练（带评测划分）
python train.py -s data -m data/output --eval

# 2. 渲染训练集和测试集
python render.py -m data/output

# 3. 计算指标
python metrics.py -m data/output
```

---

### 4. 训练 vs 评测的对比

| | 训练 | 评测 |
|---|---|---|
| 输入 | 训练集的相机位姿 + 真实照片 | 测试集的相机位姿 + 真实照片 |
| 相机位姿来源 | COLMAP 反推 | COLMAP 反推，但训练时没用过 |
| 做什么 | 渲染 → 算 loss → 反向传播更新高斯参数 | 渲染 → 和 GT 对比 → 算指标 |
| 是否更新模型 | 是 | 否（`torch.no_grad()`） |
| 评价标准 | L1 + SSIM（用于优化） | PSNR + SSIM + LPIPS（用于报告） |
| 目的 | 让高斯学会重建场景 | 看模型泛化到新视角的能力 |

---

### 5. 为什么需要相机参数才能渲染

3D 高斯是定义在世界坐标系里的。要知道它在屏幕上呈现成什么样，必须知道：

1. **相机在哪、朝哪**（外参：position + rotation）
2. **相机怎么把 3D 点投影到 2D 像素**（内参：fx, fy, 分辨率）

```
3D 高斯（世界坐标）
    ↓  外参：相机位姿变换
相机坐标系
    ↓  内参：透视投影
2D 像素平面 → 光栅化 → 渲染图
```

`render.py` 就是拿数据集中每张图对应的相机参数，重复做上述投影，生成和真实图同样视角的渲染图。

---

### 6. 生成“环绕视频”是怎么回事

`render.py` 默认只渲染数据集中已有的相机位姿。如果想做环绕视频，需要额外构造一条新的相机轨迹（例如对训练相机位姿插值得到圆形轨迹），然后逐帧渲染、最后用 ffmpeg 合成视频：

```bash
# 把渲染出的图像序列合成 30fps 视频
ffmpeg -framerate 30 -i data/output/train/ours_30000/gt/%05d.png -c:v libx264 output_video.mp4
```

## 23. COLMAP 稀疏重建 → 稠密重建：PatchMatch + 融合 (2026.07)

> 来源：梳理 COLMAP 从稀疏点云走向稠密点云的两个核心步骤

### 一句话总结

> **`patch_match_stereo` 把去畸变后的图像+相机位姿变成每张图独立的深度图；`stereo_fusion` 把所有深度图反投影并融合成一张完整的彩色稠密点云。**

---

### 流程位置

```
COLMAP SfM 输出稀疏点云 + 相机参数
        ↓
   image_undistorter（图像去畸变）
        ↓
   ┌─────────────────┐
   │ patch_match_stereo │  ← 每张图算深度图 + 法线图
   └─────────────────┘
        ↓
   depth.bin + normal.bin（./dense/stereo/）
        ↓
   ┌─────────────────┐
   │   stereo_fusion    │  ← 全部深度图融合为稠密点云
   └─────────────────┘
        ↓
   fused.ply（彩色稠密点云）
```

---

### 5. `patch_match_stereo`（稠密深度图估计）

**作用**：对每张去畸变图像，估计每个像素的高精度深度值。

**核心算法：PatchMatch**

1. **平面假设**：每个像素对应空间中一个小平面片，由**深度 + 法线**定义。
2. **随机初始化**：所有像素先随机给深度和法线。
3. **迭代传播优化**：相邻像素的好估计会传播过来，用多视角**光照一致性**（同一平面在不同视角颜色应相似）评分，反复迭代收敛。
4. **几何一致性过滤**（`--PatchMatchStereo.geom_consistency true`）：
   - 左图像素按估计深度投影到邻接视角，再反投影回来。
   - 若反投影深度与原深度差异过大，标记为无效（深度置 0）。
   - 有效剔除遮挡、弱纹理区域的噪声和漂浮点。

**输出**：`./dense/stereo/` 下每张图对应
- `image_id.depth.bin`
- `image_id.normal.bin`

---

### 6. `stereo_fusion`（深度图融合）

**作用**：把多张图像的深度图合并成覆盖全场景的稠密彩色点云。

**流程**：

1. 读取所有深度图和法线图。
2. 对每个有效像素，利用对应相机的内参和外参**反投影到三维空间**。
3. **冗余融合**：同一个 3D 点被多个视角看到时，做一致性检查和加权平均，剔除离群值。
4. 颜色直接从对应图像像素取 RGB。

**输出**：`fused.ply`（XYZ + RGB 的稠密点云）。

---

### 关键参数

| 参数 | 作用 | 建议 |
| :--- | :--- | :--- |
| `--PatchMatchStereo.max_image_size` | 限制计算深度图时长边像素数 | 设小（1024）提速损失细节；设大（2000）精度高但慢且耗显存 |
| `--PatchMatchStereo.gpu_index` | 指定 GPU（或多卡 `"0,1"`） | 多卡场景可并行加速 |
| `--PatchMatchStereo.geom_consistency true` | 开启几何一致性过滤 | **建议开启**，显著减少噪声和漂浮点 |
| `--StereoFusion.min_num_pixels` | 过滤小连通区域的最小像素数 | 根据场景尺度调整 |

---

### 与 3DGS 的关系

- **3DGS 只需要**：去畸变图像 + 相机位姿 +（可选）初始点云。
- **稠密重建这两个步骤可跳过**：3DGS 不依赖 COLMAP 的稠密点云，直接用稀疏点云初始化即可。
- **何时需要**：若目标是要纯视觉稠密点云作为中间产物（对比验证、SLAM 地图、展示），则跑这两步。

---

### 记忆口诀

```
PatchMatch：随机给深度，传播加优化，几何一致性过滤噪声。
Stereo Fusion：多张深度图，反投影回三维，冗余融合出稠密点云。
3DGS 可跳过稠密：有位姿有图像，稀疏点云就能初始化。
```

## 24. 线性 vs 非线性：深度学习的第一性原理 (2026.07)

> 来源：理解 Transformer 中各模块本质——线性在融合权重，非线性在提升特征

### 一句话总结

> **线性层负责融合、重组、加权已有信息；非线性层负责创造、筛选、激活新的特征。没有非线性，再多层也只是等价的线性变换，无法解决复杂问题。**

### 核心对比

| 特性 | 线性变换 | 非线性变换 |
|------|---------|-----------|
| 核心作用 | 融合、重组、加权已有信息 | 创造、筛选、激活新的模式 |
| 操作 | 矩阵乘法、加权求和 | 激活函数（ReLU/GELU/Swish）、Softmax、门控 |
| 信息流 | 信息被混合、压缩或扩展 | 信息被"门控"、筛选、增强 |
| 能新增信息吗？ | ❌ 不能，只是重新组合 | ✅ 能！引入新的非线性结构 |

### Transformer 中的线性/非线性分工

```
输入 x
    │
    ├── LayerNorm (预处理，非严格线性/非线性)
    │
    ├── Q = x·W_q  → 线性（融合x的各维度生成Q）
    ├── K = x·W_k  → 线性
    ├── V = x·W_v  → 线性
    │
    ├── Q·K^T  → 线性（计算相似度，融合Q和K的信息）
    │
    ├── Softmax  → 非线性！（将分数转为概率分布，"强者更强"）
    │
    ├── 概率 × V  → 线性（加权求和，融合V的各部分）
    │
    ├── Concat  → 线性（合并多头信息）
    ├── W_o  → 线性（混合多头发现）
    │
    ├── + 残差  → 线性（叠加原始x）
    │
    ├── FFN 升维 (W_up)  → 线性（扩展特征空间）
    │
    ├── 门控/激活 (GELU/SiLU)  → 非线性！（筛选重要特征，抑制不重要特征）
    │
    └── FFN 降维 (W_down)  → 线性（压缩回原维度，提炼关键信息）
```

### 关键非线性机制

**① Softmax：注意力的"聚焦"**

```python
scores = [0.5, 0.6, 0.7]
weights = softmax(scores)  # [0.29, 0.32, 0.39]
# 原本差距不大，Softmax 后差距更明显
```

作用：让注意力权重变成概率分布，突出重点，抑制次要。

**② GELU/ReLU：FFN 的"特征开关"**

```python
x = [-2.3, -1.1, 0.5, 0.8, 3.2]
gelu(x) ≈ [-0.08, -0.08, 0.35, 0.65, 3.0]
#    几乎清零  几乎清零  保留  增强  增强
```

作用：决定哪些特征有用（保留/增强），哪些无用（抑制/清零），这是特征"升华"的核心。

### 类比：工厂流水线

| 环节 | 对应操作 | 本质 |
|------|---------|------|
| 把原材料放在一起 | 线性变换 | 融合、重组 |
| 评估哪些材料重要 | Softmax（非线性） | 筛选、聚焦 |
| 按重要性组装产品 | 加权求和（线性） | 融合、加权 |
| 专家会诊（多头） | Concat + W_o（线性） | 多方意见融合 |
| 化学处理，产生新特性 | 激活函数（非线性） | **创造新特征！** |
| 包装出厂 | 线性降维 | 压缩、提炼 |

### 为什么非线性是"智能"的来源？

**没有非线性**：无论多少层线性层堆叠，数学上等价于一个大的线性变换。

```python
f(x) = W₃·W₂·W₁·x = W_total·x  ← 还是线性！
```

**有了非线性**：每一层都能创造新的特征表示，网络可以逼近任意复杂函数（通用近似定理）。

```python
f(x) = W₃·σ(W₂·σ(W₁·x))  ← σ 是非线性激活，每一层都产生新的特征空间
```

### 最终结论

```
线性 = 融合/重组信息
非线性 = 创造/提升特征
```

**记忆口诀**：

```
线性层，做融合，权重矩阵来相乘
非线性，造特征，激活门控做筛选
Softmax 聚焦注意力，GELU 开关升特征
没有非线深如浅，有了非线智乃生
```

## 25. 为什么 PyTorch 张量通常是 `[B, C, H, W]` 而不是 `[B, H, W, C] (2026.07)

> 来源：理解 NCHW 内存布局的工程必然性

### 一句话总结

> **通道放第二维没有"数学必然性"，但有"性能必然性"。它匹配 PyTorch 底层 C++ 实现、保证 GPU 连续内存访问、最大化 cuDNN 卷积效率。**

### 四个核心原因

**1. PyTorch 的"通道优先"约定**

PyTorch 默认采用 **NCHW**（`[Batch, Channel, Height, Width]`）。底层算子如 `Conv2d`、`BatchNorm2d` 都是按这种内存偏移量硬编码优化的。

```python
x = torch.randn(2, 1024, 72, 72)  # B=2, C=1024, H=72, W=72
# 这在内存中是连续存放的
```

如果强行用 NHWC（`[B, H, W, C]`），虽然也能算，但会触发内存重排（permute），产生额外拷贝开销。

**2. 卷积在 Channel 维度做乘加**

```
卷积核在 C 维度滑动累加：output[h,w] = Σ_c kernel[c] * input[c, h, w]
```

C 放在第 1 维，同一空间位置 (h,w) 的所有通道在内存上连续。GPU 读取时不用跨大跨度跳跃，L1/L2 缓存命中率高。

**3. 高通道、低分辨率场景的效率**

`[2, 1024, 72, 72]` 属于通道重、分辨率低。计算瓶颈在 Channel 维度，把 1024 放第 1 维让 cuDNN 的 `im2col` / Winograd 形成大矩阵乘法（GEMM 的 M 维度大），GPU 利用率高。

**4. BatchNorm 沿 Batch 计算**

```
BN 对每个通道 c：
  mean[c] = mean(x[:, c, :, :])
  var[c]  = var(x[:, c, :, :])
```

`[B, C, H, W]` 布局下，x[:, c, :, :] 在内存中连续，计算均值方差时步长固定，无需复杂索引。

### 例外：什么时候换成 NHWC？

```python
# Transformer 需要把每个空间位置当 token
x = x.permute(0, 2, 3, 1)  # [B, H, W, C]
# 每个 (h,w) 是一个 token，C 是特征维度

# Attention 做完后立刻换回来
x = x.permute(0, 3, 1, 2).contiguous()  # 回到 [B, C, H, W]
```

| 场景 | 推荐格式 | 原因 |
|------|---------|------|
| 卷积、BN | NCHW | 底层优化、内存连续 |
| Transformer / Attention | 临时 NHWC | token 维度放最后符合序列习惯 |

### 结论

```
[B, C, H, W] 是工程上的最优选择：
  - PyTorch 原生支持
  - GPU 连续访存
  - cuDNN 卷积高效
  - BN 计算方便

只有在进 Transformer 时才临时 permute 成 [B, H, W, C]，用完立刻换回来。
```

## 26. 2D 正弦位置编码（DETR/BEVFormer 式，不是 RoPE）(2026.07)

> 来源：理解 DETR/BEVFormer 中直接加到 feature map 上的 2D 位置编码

### 一句话总结

> **2D 正弦位置编码把特征图上每个像素的 (x, y) 坐标分别用不同频率的正弦/余弦编码，前半段通道编码 y 轴位置，后半段通道编码 x 轴位置，最后直接加到特征图上。它和 RoPE 完全不同：RoPE 是旋转向量，这个是直接相加。**

### 形状与通道分配

```python
fpn_hidden_size = 256      # 总通道数
num_pos_feats = 128        # 每个轴用的通道数（一半是 sin，一半是 cos）

最终位置编码 shape: [N, 256, H, W]

通道 0   ~ 127  → y 轴位置编码
通道 128 ~ 255  → x 轴位置编码
```

### 关键区分：两个"索引"完全不同

| 概念 | 取值范围 | 作用 |
|------|---------|------|
| **位置索引**（x / y） | 0 ~ W-1 或 0 ~ H-1 | **sin/cos 的自变量**（括号里那个数） |
| **通道索引**（i） | 0 ~ 127 | **选择不同频率**（决定高频还是低频） |

### 计算方式

```python
# 生成坐标网格
y_embed = torch.arange(H).unsqueeze(1).repeat(1, W)  # [H, W], 值 = 行号
x_embed = torch.arange(W).unsqueeze(0).repeat(H, 1)  # [H, W], 值 = 列号

# 通道索引，用于计算不同频率
dim_t = torch.arange(num_pos_feats)  # [0, 1, 2, ..., 127]
freq = 10000^(2 * dim_t / num_pos_feats)  # 频率从低到高

# 正余弦交替
pos_y = sin(y_embed / freq)  # [H, W, 128]
pos_x = sin(x_embed / freq)  # [H, W, 128]

# 最终位置编码：concat 后在通道维度 permute 成 NCHW
pos = concat([pos_y, pos_x], dim=-1)  # [H, W, 256]
pos = pos.permute(2, 0, 1).unsqueeze(0)  # [1, 256, H, W]
```

### 每个通道对应什么？

以特征图上一个点 `(y=5, x=12)` 为例：

```
y 轴部分（通道 0~127）：
  通道 0:   sin(5 / freq_0)      ← 括号里是行号 5
  通道 1:   cos(5 / freq_0)
  通道 2:   sin(5 / freq_1)
  通道 3:   cos(5 / freq_1)
  ...

x 轴部分（通道 128~255）：
  通道 128: sin(12 / freq_0)     ← 括号里是列号 12
  通道 129: cos(12 / freq_0)
  通道 130: sin(12 / freq_1)
  ...
```

**同一行不同列**：前 128 个通道完全相同（y 没变），后 128 个通道变化。  
**同一列不同行**：前 128 个通道变化，后 128 个通道完全相同。

这就是 **"坐标解耦"**——模型能区分变化来自水平移动还是垂直移动。

### 如何融入模型？

```python
# 直接相加
output = feature_map + pos_encoding  # [N, 256, H, W]

# 不是旋转，不是乘，就是简单的 element-wise 相加
```

### 与 RoPE 的核心区别

| | 2D 正弦位置编码 | RoPE |
|---|---|---|
| 应用对象 | 特征图 / 图像位置 | 序列中的 token 向量 |
| 形式 | 生成一个位置编码张量，**直接相加** | 不生成额外张量，**旋转向量** |
| 维度 | 2D 空间 (x, y) | 1D 序列位置 |
| 是否改变 Q/K 向量 | 否，只是加了一个偏置 | 是，对 Q/K 向量做旋转 |
| 相对位置 | 模型自己学习 | 内积自然体现相对位置 |
| 代表模型 | DETR、BEVFormer | LLaMA、Qwen、GPT |

### 记忆口诀

```
DETR 位置编码：空间坐标编正弦，xy 解耦通道分
前半段编上下，后半段编左右
RoPE 不一样：token 向量做旋转，频率位置乘一起
一个相加一个转，千万别把两者混
```

## 27. Object Query 的两种形式 (2026.07)

> 来源：讨论 RT-DETR v2 / Grounding DINO / DETR 时整理

### 一句话总结

> **传统 Object Query 是无空间坐标的纯向量，靠全局注意力找目标；空间 Query 是“参考点坐标 + 局部特征”，靠可变形注意力在指定位置附近 refine。**

---

### 形式一：传统 Object Query（如 DETR）

```
图像 → CNN Backbone → Transformer Encoder
                              ↓
                   300 个可学习的 object queries
                              ↓
              每个 query 和 所有 图像 token 做全局 cross-attention
                              ↓
                        输出 cls + bbox
```

**Query 是什么？**

```python
nn.Embedding(300, hidden_dim)
```

- 没有显式的 `(x, y)` 坐标
- 没有“我应该看图哪里”的先验
- 完全靠训练学会关注什么

**注意力方式：**

**全局 attention**：每个 query 和整张图的所有位置算相似度。

```
复杂度: O(num_queries × num_image_tokens)
```

如果特征图有 8000 个 token，300 个 query：

```
300 × 8000 = 2,400,000 次相似度计算
```

**优点：**

- 不受固定位置限制，可以看图里任何地方
- 对遮挡、大目标、全局上下文建模能力强

**缺点：**

- 计算量大，内存占用高
- 收敛慢（DETR 原论文要 500 epochs）
- 高分辨率特征图上速度很慢

**代表模型：** DETR

---

### 形式二：带空间坐标的 Query（如 RT-DETR v2 / Deformable DETR / Grounding DINO）

```
图像 → CNN Backbone → Hybrid Encoder 做密集预测
                              ↓
                 每个空间位置预测 class score + 粗框
                              ↓
                    选 top-K 个高分候选位置
                              ↓
           这些位置的 坐标 + 特征 作为初始 query
                              ↓
              Decoder 用可变形注意力在参考点周围采样
                              ↓
                    迭代 refine 输出最终框
```

**Query 是什么？**

```python
query = {
    "reference_point": (0.3, 0.5),  # 图像上的空间坐标
    "content_feature": [...]        # 该位置的特征向量
}
```

- 有显式的空间位置
- 从一开始就知道“我应该先看图哪里”
- 可以用可变形注意力只在附近采样

**注意力方式：**

**可变形注意力（Deformable Attention）**：每个 query 只在自己的 reference point 周围采几个点。

```
复杂度: O(num_queries × num_levels × num_points)
```

例如 300 个 query，4 个 feature level，每个点采 4 个位置：

```
300 × 4 × 4 = 4,800 次采样
```

相比全局注意力的 2,400,000，小了约 **500 倍**。

**优点：**

- 计算量小，速度快
- 收敛快（Deformable DETR 50 epochs）
- 适合高分辨率特征图
- query 有空间先验，refine 更稳定

**缺点：**

- 依赖 encoder 密集预测的质量
- 如果初始 reference point 不准，可能 refine 不回来
- 对远离初始位置的目标不敏感

**代表模型：** Deformable DETR、RT-DETR v2、Grounding DINO

---

### 两种形式的本质区别

| | 传统 Object Query | 空间 Query |
|---|---|---|
| **Query 内容** | 纯可学习向量 | 参考点坐标 + 局部特征 |
| **空间信息** | 无显式坐标 | 有显式坐标 |
| **注意力范围** | 全局所有图像 token | 参考点周围局部采样 |
| **计算复杂度** | `O(N_q × N_tokens)` | `O(N_q × K × L)` |
| **收敛速度** | 慢 | 快 |
| **空间先验** | 无 | 有 |
| **对初始质量依赖** | 低 | 高 |
| **代表模型** | DETR | Deformable DETR、RT-DETR v2、Grounding DINO |

---

### 为什么 RT-DETR v2 / Grounding DINO 选空间 Query？

1. **快**：可变形注意力避免全局 attention 的巨大计算量
2. **准**：query 从 encoder 密集预测中选出，一开始就有好的初始位置
3. **稳**：reference point 可以迭代 refine，每层都在前一层基础上微调
4. **适合高分辨率**：检测任务需要高分辨率特征图，全局 attention 吃不消

---

### 类比理解

> **传统 query 像“盲人摸象”**：没有方向，要摸遍全图才知道东西在哪。  
> **空间 query 像“已经知道大概位置，只在附近细看”**：有地图指引，效率高很多。

---

```
DETR query 纯向量，全局 attention 慢慢学
空间 query 有坐标，可变形 attention 局部看
一个无先验全局找，一个有坐标快速 refine
实时检测用后者，精度速度两相宜
```

## 28. MoE 为什么能缓解灾难性遗忘 (2026.07)

> 来源：讨论 MoE 持续学习能力时整理

### 一句话总结

> **MoE 每次训练只激活少数专家（如 Kimi K3 激活 16/896 个），大部分专家参数保持不变，旧知识因此得到“物理隔离”，从而显著减缓灾难性遗忘。**

### 核心逻辑：参数隔离

| | 传统稠密模型 | MoE 模型 |
|---|---|---|
| 参数更新范围 | 全部参数都参与更新 | 只有被路由选中的少数专家更新 |
| 知识存储 | 所有知识纠缠在一起 | 不同知识分散在不同专家 |
| 学新任务 | 容易覆盖旧知识 | 旧知识所在的专家大概率不被触动 |
| 比喻 | 整个大脑一起调整 | 专家委员会，每次只调整相关专家 |

### 为什么 MoE 有优势？

```
输入 token → Router → 选择 top-K 个专家
              ↓
        只有这 K 个专家前向 + 反向更新
              ↓
        其他 800+ 专家参数完全不动
              ↓
        它们存储的旧知识保持完整
```

**结论**：MoE 的稀疏激活天然提供了一种 **参数隔离**，让新旧知识尽量不冲突。

### 学术界佐证

谷歌 DeepMind 等机构的研究（如 *Mixture of Experts for Lifelong Learning*）表明：

- MoE 在持续学习（Continual Learning）场景下表现优于稠密模型
- 核心策略：**Parameter Isolation**，为不同任务保留独立的专家空间
- 目标：**Learning without Forgetting**

### 需要厘清的两个关键点

**1. 预训练阶段依旧全量更新**

在海量预训练阶段，所有专家都会参与训练。此时不存在“防止遗忘”的需求，目标是让所有专家获得通用基础能力。

```
预训练：所有 896 个专家都训练  ← 没有遗忘问题
微调/持续学习：只激活 top-K 专家  ← 缓解遗忘的优势在这里体现
```

**2. 路由器坍缩风险**

如果路由器总是把 token 派给少数几个“全能”专家，大部分专家闲置，模型就退化为稠密模型，缓解遗忘的优势也会消失。

**解决方案：负载均衡损失（Load Balancing Loss）**

```python
# 强制路由器雨露均沾
loss_total = task_loss + α * load_balancing_loss

# load_balancing_loss 让每个专家被使用的频率尽量均匀
```

### 对比总结

| 阶段 | 是否缓解遗忘 | 原因 |
|---|---|---|
| 预训练 | 不适用 | 所有专家都参与，目标是学通用能力 |
| 微调 / 持续学习 | ✅ 有效 | 只更新少数专家，旧知识被隔离 |

### 记忆口诀

```
稠密模型全脑调，新旧知识互相扰
MoE 路由选专家，只动少数留多数
预训练时全专家，微调阶段显神威
负载均衡防坍缩，遗忘缓解有底气
```

## 29. Decoder Self-Attention：所有词都参与，但只取最后一个预测 (2026.07)

> 来源：梳理因果解码器中自注意力的完整输出与预测取舍

### 一句话总结

> **Decoder 的每一层 Self-Attention 都会输出所有位置的新向量（每个位置都看到了上文），但只有最后一个位置的向量被拿去预测下一个词。**

### 三个关键结论

**1. Attention 输出的是所有词对上文的理解**

```
输入序列：[BOS, token1, token2, token3, token4]
              ↓
        Self-Attention + Causal Mask
              ↓
输出向量：[v_BOS, v1, v2, v3, v4]

其中：
  v_BOS = BOS 对“上文=BOS”的理解
  v1    = token1 对“上文=BOS+token1”的理解
  v2    = token2 对“上文=BOS+token1+token2”的理解
  ...
  v4    = token4 对“上文=BOS+...+token4”的理解
```

每个位置都只能 attend 到自己及之前的词（causal mask），所以每个位置都得到了它自己的“上文理解”。

**2. 下一层依然是所有词对上文的理解**

- 第 2 层接收第 1 层输出的**所有位置向量**作为输入
- 再次为每个位置计算新的上文理解
- 经过 N 层之后，每个位置的向量都融合了多层、多角度的上下文

```
Layer 1:  [v_BOS^1, v1^1, v2^1, v3^1, v4^1]
              ↓
Layer 2:  [v_BOS^2, v1^2, v2^2, v3^2, v4^2]
              ↓
Layer N:  [v_BOS^N, v1^N, v2^N, v3^N, v4^N]
```

**3. 所有词都会走 FFN，且每个词独立走**

- 多头注意力把多个头的结果 concat 后，每个位置都会独立经过 FFN
- FFN 不是“整合多角度注意力”（那是多头 attention 干的），而是对每个位置向量做非线性变换和特征增强

```
每个位置：Attention输出 → +residual → LayerNorm → FFN → +residual → LayerNorm
```

### Decoder Layer 完整伪代码（含残差连接）

```python
# 输入 X（来自上一层）
x = 上一层的输出   # shape: (batch, seq_len, hidden_dim)

# ========== 第一个子层：多头注意力（MHA） ==========
identity = x                     # 残差支路：保存原始 X

x_norm = layer_norm(x)           # 归一化
q = q_proj(x_norm)               # 生成 Q
k = k_proj(x_norm)               # 生成 K
v = v_proj(x_norm)               # 生成 V
attn_out = attention(q, k, v)    # 自注意力计算
z = o_proj(attn_out)             # 输出投影生成 O

# 第一次残差相加
x = identity + z                 # 此时 x = X + O_attention

# ========== 第二个子层：FFN（前馈网络） ==========
identity2 = x                    # 残差支路：保存第一次残差的结果

x_norm2 = layer_norm(x)          # 第二次归一化
ffn_out = ffn(x_norm2)           # FFN：升维 → 激活（门控）→ 降维

# 第二次残差相加
x = identity2 + ffn_out          # 此时 x = (X + O_attn) + FFN_out

# ========== 输出到下一层 ==========
return x
```

### Attention 计算细节拆解

输入序列有 N 个位置，每个位置先投影出 q_i, k_i, v_i（i = 1...N）：

**Step 1：计算注意力分数（所有词两两打分）**

```
score_ij = q_i · k_j / √d    对所有 i, j ∈ [1, N]

得到注意力分数矩阵：

        k_1   k_2   k_3   k_4
q_1    s11   s12   s13   s14
q_2    s21   s22   s23   s24
q_3    s31   s32   s33   s34
q_4    s41   s42   s43   s44
```

**Step 2：Causal Mask（防止偷看未来）**

```
        k_1   k_2   k_3   k_4
q_1    s11    -∞    -∞    -∞      ← 位置1只能看自己
q_2    s21   s22    -∞    -∞      ← 位置2能看1,2
q_3    s31   s32   s33    -∞      ← 位置3能看1,2,3
q_4    s41   s42   s43   s44      ← 位置4能看1,2,3,4
```

把未来位置设为 -∞，softmax 后权重为 0。

**Step 3：Softmax 得到权重矩阵**

```
weight_ij = softmax(score_ij, 按行计算)

每行和为 1：
        k_1    k_2    k_3    k_4
q_1    w11    0      0      0
q_2    w21    w22    0      0
q_3    w31    w32    w33    0
q_4    w41    w42    w43    w44
```

**Step 4：权重乘 V，再按维度相加**

```
对每个位置 i：
    output_i = Σ_j weight_ij × v_j

展开位置4的例子：
    output_4 = w41 × v_1 + w42 × v_2 + w43 × v_3 + w44 × v_4
             = 加权求和
```

**结果**：

```
输出 = [output_1, output_2, output_3, output_4]

每个 output_i 都是第 i 个位置对“上文”的加权理解。
位置 i 越靠前，能看的词越少；越靠后，能看的词越多。
```

### 训练 vs 推理的差异

| 阶段 | 拿多少个位置算损失/预测 |
|---|---|
| **训练** | 所有位置都参与计算 CrossEntropy Loss（每个位置预测下一个位置的词） |
| **推理** | 只取**最后一个位置**的输出向量，过 lm_head + softmax 预测下一个词 |

**训练时**的 Teacher Forcing：

```python
# 输入: [BOS, 今天, 天气, 不错]
# 标签: [今天, 天气, 不错, EOS]

# 每个位置都预测下一个词
v_BOS  → 预测 "今天"
v1     → 预测 "天气"
v2     → 预测 "不错"
v3     → 预测 "EOS"
```

**推理时**的自回归：

```python
# 输入: [BOS, 今天, 天气, 不错]
# 只取 v4（最后一个）→ lm_head → softmax → 预测下一个词
```

### 为什么推理时只取最后一个？

因为最后一个位置的向量已经“看遍”了所有上文：

```
v4 能看到：BOS, 今天, 天气, 不错
v3 能看到：BOS, 今天, 天气       ← 少了“不错”
v2 能看到：BOS, 今天              ← 更少
```

**v4 包含了生成下一个词所需的全部上下文信息**，所以只用它预测。

### 完整流程图

```
输入序列: [BOS, 今天, 天气, 不错]
    ↓
N × Decoder Layer:
  每层：所有位置都做 Self-Attention + FFN
    ↓
输出向量: [v_BOS, v_今天, v_天气, v_不错]
    ↓
训练: 所有位置都参与算 loss
推理: 只取 v_不错 → lm_head → softmax → 下一个词
```

### MoE 场景：FFN 换成专家网络

在 MoE 大模型（如 Kimi K3、Mixtral）中，Decoder 的 **FFN 被替换成多个 Expert FFN + Router**：

```
Attention 输出
    ↓
Router: 对每个 token 打分，选出 top-K 个专家
    ↓
只激活 K 个 Expert FFN（比如 2/8 或 16/896）
    ↓
按 router 权重加权融合 K 个专家输出
    ↓
得到该 token 的 FFN 输出
```

**关键问题：MoE 真的省参数吗？**

| | 普通 Dense FFN | MoE FFN |
|---|---|---|
| 总参数量 | 1 个大 FFN | 多个专家 FFN 相加，**总参数通常更多** |
| 每个 token 激活的参数 | 整个大 FFN | 只激活 top-K 个专家，**激活参数更少** |
| 每个 token 的计算量 | 大 | 小 |
| 模型知识容量 | 小 | 大（总参数多） |

**直观例子**：

```
Dense 模型: 1 个 FFN，中间维度 4096，总参数 100B
MoE 模型:   64 个专家，每个 FFN 中间维度 1024，top-k=2

总参数:    MoE > Dense（64 × 小专家 加起来比 1 × 大专家还多）
激活参数:  MoE ≈ Dense 的 2/64 = 1/32（只跑 2 个专家）
效果:      MoE 通常更好，因为总容量更大，但推理成本可控
```

**一句话**：MoE 不是“参数更少”，而是 **“总参数更多，但每个 token 只激活一小部分”**。

**为什么这样更好？**

- 一个 FFN 要服务所有主题、语言、任务，容易变成“通才但不够专”
- MoE 让每个专家专攻特定模式（代码、中文、推理、数学……）
- Router 把 token 派给最合适的专家，同样推理成本下获得更大模型容量

### 每一层都会重新投影 Q、K、V

在 Transformer 的每一层，都有**自己独立训练**的 Q/K/V 投影矩阵：

```
第 1 层：W_Q^1, W_K^1, W_V^1
第 2 层：W_Q^2, W_K^2, W_V^2
...
第 L 层：W_Q^L, W_K^L, W_V^L
```

每层接收上一层的输出作为输入，然后**用自己的投影矩阵重新计算新的 Q、K、V**：

```
输入 X^l（来自第 l 层的输出）
    │
    ├──→ X^l · W_Q^l → Q^l
    ├──→ X^l · W_K^l → K^l
    └──→ X^l · W_V^l → V^l
              │
    Attention(Q^l, K^l, V^l) → 输出 X^{l+1}
```

**三个“重新”的区分**：

| 概念 | 是否重新计算 | 说明 |
|------|------------|------|
| 每层投影矩阵 W_Q/W_K/W_V | ✅ 是，每层独立训练 | 不同层数值不同 |
| 每层的 Q/K/V 向量 | ✅ 是，用本层参数重新投影 | 不是复用上一层的 Q/K/V |
| 推理时旧词的 K/V | ❌ 不是重新算，是复用缓存 | 已生成词的 K/V 缓存起来 |

### KV Cache 存的是每层的所有历史 K/V

推理生成第 N 个词时，KV Cache 的结构：

```
第 1 层: [K_1^1, K_2^1, ..., K_{N-1}^1]  和  [V_1^1, V_2^1, ..., V_{N-1}^1]
第 2 层: [K_1^2, K_2^2, ..., K_{N-1}^2]  和  [V_1^2, V_2^2, ..., V_{N-1}^2]
...
第 L 层: [K_1^L, K_2^L, ..., K_{N-1}^L]  和  [V_1^L, V_2^L, ..., V_{N-1}^L]
```

**注意**：
- **Q 不缓存**——每次生成新词，当前词的 Q 需要重新投影
- **K/V 按层分开存**——不同层的 K/V 来自不同投影矩阵，数值完全不同
- **所有历史词都存**——生成新词时，前面的所有词都作为 K/V 参与 attention

**生成第 N 个词时的流程**：

```
1. 计算新词的 Q_N, K_N, V_N（用每层自己的 W_Q/W_K/W_V 投影）
2. 把 K_N, V_N 追加到该层 KV Cache
3. 用 Q_N 查询所有历史 K（包括 K_N 自己）
4. 加权求和所有历史 V，得到当前层的输出
5. 进入下一层，重复 1-4
```

### 记忆口诀

```
Decoder 自注意力，所有位置并行算
每个词看上文，因果 mask 防偷看
多层迭代深理解，FFN 每个词独立走
训练所有位置算 loss，推理只取最后一个猜
```
