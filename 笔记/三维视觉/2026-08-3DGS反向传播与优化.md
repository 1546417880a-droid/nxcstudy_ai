## 3DGS 反向传播与优化总结 (2026.08)

> 来源：回答"Loss 怎么反过来更新 Gaussian 的各个参数"时整理。核心纠正：**不是"Gaussian 自己把梯度传播出去"，而是 RGB 图像的 Loss 沿着可微渲染器反向传播回来，最终把梯度传到每一个 Gaussian 的参数上**——一条"逆向的链"。

### 一、正向链路

```
Gaussian参数（μ 位置 / Σ Shape / α Opacity / SH Appearance）
   ↓ 3D Gaussian
投影到 2D（2D Gaussian）
   ↓ 计算每个像素贡献
Alpha Compositing
   ↓
Rendered RGB Image
   ↓ 与 Ground Truth 比较
Loss
```

### 二、反向传播 = 链式法则

方向完全反过来：`Loss ← Renderer ← Gaussian`。对任意参数 θ，本质是：

```
∂L/∂θ = ∂L/∂Pixel × ∂Pixel/∂Weight × ∂Weight/∂投影后位置 × ∂投影后位置/∂θ
```

不需要手工算，PyTorch/自动微分会算；3DGS 的 CUDA rasterizer 需自己实现可微反向。

### 三、四个参数各自拿到梯度

- **Position**：`∂L/∂μ`（位置动一点，Loss 变多少；经投影 u=f·x/z 传导）
- **Shape**：`∂L/∂Σ`（椭圆影响哪些像素 → Loss）
- **Opacity**：`∂L/∂α`（贡献不足 → 梯度推高 opacity：0.2→0.25→0.31…）
- **SH**：`∂L/∂SH`（当前方向颜色不对 → 往真实 RGB 方向调整）

### 四、优化器更新

```
θ_new = θ_old − η·∂L/∂θ
```

3DGS 实际常用 **Adam**，不只是朴素 SGD。

### 五、两个重要的"累积"性质

1. **一个 Gaussian 影响很多像素** → `∂L/∂μ` 是它覆盖的所有像素梯度贡献的**累积**，所以一张图的一大片区域都能给它训练信号。
2. **一个 Gaussian 受多张照片共同约束** → `L = L1 + L2 + L3 + …`，多视角共同把它调整到能解释整个场景。

### 六、一句话总结

> **3DGS 本质上就是：把一组带 Position/Shape/Opacity/Appearance 的 3D Gaussian 通过可微 Rasterizer 渲染成 2D 图像 → 用真实图像算 Loss → 用链式法则把梯度反向传播到每个 Gaussian 的这些参数 → 由 Adam 更新它们，循环。**

### 七、下一步值得搞懂的点

> **"Position 的梯度到底怎么穿过 3D→2D 投影？"**——一旦明白 `∂L/∂μ = ∂L/∂pixel × ∂pixel/∂2DGaussian × ∂2DGaussian/∂μ`，就真正理解为什么 3DGS 是"可优化的 3D 表示"，而不只是"很多椭球画到图片上"。
