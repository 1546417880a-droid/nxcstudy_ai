## 22. 3DGS 训练与评测的完整流程 (2026.07)

> 来源：分析 `gaussian-splatting` 工程代码（`train.py` / `render.py` / `metrics.py` / `convert.py`）

### 一句话总结

> **训练：用 COLMAP 反推的相机位姿，把 3D 高斯椭球逐一投影到训练视角，和真实照片对比算 L1+SSIM 损失，反向传播优化每个高斯的参数，同时定期增删点。评测：用训练时没见过的测试视角，把高斯投影出来和真实测试图对比，算 PSNR/SSIM/LPIPS 量化指标。**

---

### 1. 数据准备阶段

```
拍摄物体/场景的多角度照片（或视频抽帧）
        ↓
COLMAP 特征提取 + 匹配 + BA 优化
        ↓
输出：
  - cameras.bin   相机内参（fx, fy, width, height）
  - images.bin    相机外参（R 旋转矩阵, T 平移向量，即 position）
  - points3D.bin  稀疏点云（几万个 3D 点）
```

相机参数示例（工程中的 `cameras.json` 格式）：

```json
{
  "img_name": "00001.jpg",
  "width": 1255,
  "height": 702,
  "position": [-1.057, 1.613, -3.945],
  "rotation": [[...], [...], [...]],
  "fx": 1092.40,
  "fy": 1089.69
}
```

| 参数 | 含义 |
|------|------|
| `position` | 相机中心在世界坐标系中的 3D 位置 |
| `rotation` | 3×3 旋转矩阵，相机朝向 |
| `fx`, `fy` | 像素焦距，决定视野宽窄 |
| `width`, `height` | 图像分辨率 |

**position + rotation = 外参（相机在世界中的位姿）**
**fx/fy + 分辨率 = 内参（相机成像特性）**

### 2. 训练阶段（`train.py`）

```
稀疏点云（几万个点）
    ↓
【初始化】每个点 → 一个 3D 高斯椭球
    ↓
循环迭代 30000 次（默认）
    │
    ├─ 每一步都做的事：
    │   ① 随机选一张训练图片
    │   ② 用该图片的相机位姿，把 3D 高斯投影成 2D 图像
    │   ③ 和真实照片对比，计算 L1 Loss + SSIM Loss
    │   ④ 反向传播 → 优化高斯的 位置/形状/不透明度/SH颜色
    │
    └─ 每 100 步做的事：
        ① 密集化（densify）：梯度大的点分裂/克隆
        ② 剪枝（prune）：不透明度太低或太大的点删除
        ③ 定期重置不透明度，防止透明度累积错误
    ↓
保存训练好的高斯模型（`point_cloud/iteration_30000/point_cloud.ply`）
```

#### 损失函数

```python
L_total = L1(渲染图, 真实图) + λ × (1 - SSIM(渲染图, 真实图))
```

| 损失 | 作用 |
|------|------|
| L1 Loss | 像素绝对值差异，保证颜色和亮度准确 |
| SSIM Loss | 结构相似性，保证边缘和纹理不失真 |

#### 优化哪些参数

| 参数 | 意义 |
|------|------|
| 位置 μ | 高斯中心在哪 |
| 协方差 Σ | 高斯的形状（尺度 × 旋转） |
| 不透明度 α | 0=透明，1=不透明 |
| 球谐系数 SH | 不同观察方向下的颜色 |

#### 密集化与剪枝

```
每 100 步检查一次：

密集化：
  - 位置梯度大 + 尺度大 → 分裂成两个更小的点
  - 位置梯度大 + 尺度小 → 克隆一个副本沿梯度方向移动

剪枝：
  - 不透明度 < 阈值 → 删除（看不见，没用）
  - 尺度异常大 + 位置空旷 → 删除（漂浮噪声点）
```

**点的数量变化**：初始几万个 → 训练中可能激增到百万级 → 最终稳定到几十万级。

### 3. 评测阶段（`render.py` + `metrics.py`）

```
加载训练好的高斯模型
    ↓
对测试集中的每一张图：
  ① 读取该图的相机位姿（来自 COLMAP，训练时没用过）
  ② 用相同位姿把高斯投影成 2D 图像
  ③ 保存渲染图，同时保存真实图作为 gt
    ↓
metrics.py 对比渲染图和真实图
    ↓
输出 PSNR / SSIM / LPIPS
```

#### 评测的本质

```
训练时：用训练视角 → 教模型“从这里看应该长什么样”
评测时：用测试视角 → 考模型“从没见过的角度看，你还能不能画对”
```

#### 评测指标

| 指标 | 含义 | 好坏方向 |
|------|------|---------|
| PSNR | 峰值信噪比，衡量像素差异 | ↑ 越高越好 |
| SSIM | 结构相似性，衡量亮度/对比度/结构 | ↑ 越高越好 |
| LPIPS | 感知距离，用神经网络特征衡量视觉差异 | ↓ 越低越好 |

#### 运行命令

```bash
# 1. 训练（带评测划分）
python train.py -s data -m data/output --eval

# 2. 渲染训练集和测试集
python render.py -m data/output

# 3. 计算指标
python metrics.py -m data/output
```

### 4. 训练 vs 评测的对比

| | 训练 | 评测 |
|---|---|---|
| 输入 | 训练集的相机位姿 + 真实照片 | 测试集的相机位姿 + 真实照片 |
| 相机位姿来源 | COLMAP 反推 | COLMAP 反推，但训练时没用过 |
| 做什么 | 渲染 → 算 loss → 反向传播更新高斯参数 | 渲染 → 和 GT 对比 → 算指标 |
| 是否更新模型 | 是 | 否（`torch.no_grad()`） |
| 评价标准 | L1 + SSIM（用于优化） | PSNR + SSIM + LPIPS（用于报告） |
| 目的 | 让高斯学会重建场景 | 看模型泛化到新视角的能力 |

---

### 5. 为什么需要相机参数才能渲染

3D 高斯是定义在世界坐标系里的。要知道它在屏幕上呈现成什么样，必须知道：

1. **相机在哪、朝哪**（外参：position + rotation）
2. **相机怎么把 3D 点投影到 2D 像素**（内参：fx, fy, 分辨率）

```
3D 高斯（世界坐标）
    ↓  外参：相机位姿变换
相机坐标系
    ↓  内参：透视投影
2D 像素平面 → 光栅化 → 渲染图
```

`render.py` 就是拿数据集中每张图对应的相机参数，重复做上述投影，生成和真实图同样视角的渲染图。

---

### 6. 生成“环绕视频”是怎么回事

`render.py` 默认只渲染数据集中已有的相机位姿。如果想做环绕视频，需要额外构造一条新的相机轨迹（例如对训练相机位姿插值得到圆形轨迹），然后逐帧渲染、最后用 ffmpeg 合成视频：

```bash
# 把渲染出的图像序列合成 30fps 视频
ffmpeg -framerate 30 -i data/output/train/ours_30000/gt/%05d.png -c:v libx264 output_video.mp4
```
