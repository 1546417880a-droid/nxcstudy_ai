> 来源：追问"单目 RGB 只有 (u,v) 没有深度，是不是就没法通过 `T_cb` 变到车体系"。一句话：**对，链条断在第一步——不是外参有问题，而是单张 RGB 像素反推不出相机系 3D 点；实际系统里深度要么由 LiDAR/双目提供，要么由地面假设 + IPM 提供，要么由单目深度估计 / BEV 网络预测，图像本身只提供语义。**

### 一、像素 → 相机坐标，缺的到底是什么

相机成像模型：

```
[u]         [X_c]
[v] = (1/Z_c)·K·[Y_c]
[1]         [Z_c]
```

反推相机坐标：

```
[X_c]            [u]
[Y_c] = Z_c · K⁻¹·[v]
[Z_c]            [1]
```

**关键：`Z_c` 未知。** 没有 `Z_c`，你只能得到一条从光心出发的**射线**，无法确定射线上的哪个点。

> 所以"单目 RGB 像素没有深度就没有相机坐标"这个判断是对的——**`T_cb` 本身没问题，问题在于它作用的对象（相机系 3D 点）根本还没求出来。**

### 二、实际系统怎么把图像信息落到车体系（四种情况）

#### 情况 A：有深度传感器（LiDAR / 深度相机 / 双目）——最直接

1. LiDAR 给出点在**雷达系**下的 3D 坐标 `(X_l, Y_l, Z_l)`；
2. 通过外参 `T_lb` 变到车体系 B；
3. 通过 `T_cb` 的逆，把 3D 点**投影**到相机像素 `(u, v)`；
4. 于是每个（投影到的）像素就对应一个已知深度的 3D 点。

反过来，图像上检测到一个像素想找它的 3D 位置：**先把 LiDAR 点云投影到图像，找到与该像素对应的 LiDAR 点**，那个点自带 3D 坐标。

> **LiDAR 提供深度，图像提供语义，两者通过外参对齐**——这是融合里最基本的分工。

#### 情况 B：纯视觉 + 几何假设（地面平面）

若已知：相机高度、相机俯仰角、地面是平面，则对**地面上的点**可用"地面平面约束 + 像素射线求交"解出 `Z_c`，得到相机坐标再变到车体系。

- 这就是车道线检测、地面箭头识别、BEV 感知常用的思路：假设目标在地面上，用 **IPM（逆透视变换）** 把图像映射到地面 BEV。
- **局限**：对非地面物体（车辆、行人、空中目标）假设不成立，**单目无法直接得到准确 3D 位置**。

#### 情况 C：单目深度估计 / 神经网络预测深度

用单目深度估计网络预测每像素的 `Z_c`，再代入上式得相机坐标，最后 `T_cb` 变到车体系。

- **缺点**：单目深度是**相对/尺度不确定**的，精度有限，通常用于辅助，不用于高精度定位。

#### 情况 D：纯 2D 检测，根本不需要 3D

任务只是"图像上有没有车"时，检测框就是像素坐标，**不需要转到车体系**。只有需要 BEV 位置、跟踪、规划控制时，才需要 3D 坐标。

### 三、那条链条对单目 RGB 意味着什么

```
相机系 → 车体系 B → odom → map
```

链条成立的前提是：**你已有一个相机系下的 3D 点 `(X_c, Y_c, Z_c)`。**

| 3D 点来源 | 链条是否走得通 |
| :--- | :--- |
| LiDAR 投影 | ✅ 深度由 LiDAR 提供 |
| 地面假设 + IPM | ✅ 深度由地面约束提供 |
| 只有单张 RGB 像素 | ❌ **断在第一步**——连相机系 3D 点都得不到 |

- **`T_cb` 本身没问题**，它描述相机系与车体系的刚体变换；
- **问题在于单目 RGB 缺少深度**，无法从像素得到相机系 3D 点；
- **解决深度来源，链条才能走通。**

### 四、多传感器融合的典型流程

```
1. LiDAR 点云 → 通过 T_lb 到车体系 B
2. 同时通过 T_cb 投影到图像，和图像检测结果关联
3. 关联上的检测目标，继承 LiDAR 点的 3D 坐标
4. 这个 3D 坐标再通过 T_{odom←B}(t) 变到 odom
5. 再通过 T_{map←odom} 变到 map
```

图像在这里提供**语义信息**（是什么、检测框），3D 位置由 LiDAR 提供，两者通过外参对齐——**而不是从像素直接算 3D**。

### 五、纯视觉 BEV（BEVFormer、LSS）怎么绕开这个限制

这类方法用神经网络**隐式或显式地预测深度分布**：

| 方法 | 做法 |
| :--- | :--- |
| **LSS** | 对每个像素预测一组**深度概率**，把图像特征"抬升"到 3D 空间，再投影到 BEV |
| **BEVFormer** | 用 Transformer 在 BEV query 和图像特征间做**交叉注意力**，隐式学习 3D 对应关系 |

它们不显式输出每个像素的深度，但网络内部学到了"像素 → 3D"的映射，输出的 BEV 特征可直接放在车体系或 odom 系下。

> 纯视觉也能做 BEV，但靠的是**学习出来的深度/对应关系**，不是几何上从单像素直接算出来的。

### 六、一句核心总结

> **单目 RGB 只有像素坐标、没有深度，确实无法直接得到相机系 3D 点，也就无法直接通过 `T_cb` 变到车体系 B。** 实际系统里 3D 位置要么由 LiDAR / 深度相机提供，要么由地面平面假设 + IPM 提供，要么由单目深度估计 / BEV 网络预测；**图像本身提供语义，3D 几何由其他来源或网络补上，外参 `T_cb` 只负责把两个坐标系对齐。**
