ROS 数据链路：从底盘 CAN 总线 到规划节点

CAN 是硬件之间的通信总线，不是流程里的一个"节点"；发布动作发生在驱动节点内部。

ROS 驱动节点 ROS Node · 就是发布者本身

① 按 DBC 定义把字节解析成物理量（如 ID 0x123 的 byte0–1 → 车速 32.5 km/h）

② 封装为标准 ROS 消息，再调用 publisher.publish(msg) —— 发布是它的一个动作，不是下一跳。

publish() 在本节点内完成
不存在"发布节点"这个中间环节

两处常见画法要修正 Corrections

✕
硬件 → CAN → 驱动节点 → "ROS 节点发布" → 订阅者
把 CAN 画成独立环节，把"发布"画成另一个节点。
✓
硬件 ⇄ CAN 总线 ⇄ 接口卡 ⇄ 驱动节点（自己 publish） → Topic → 订阅者
CAN 只是线束协议；驱动节点在 ROS 图里是一个 node，同时就是 publisher。

反向下行：控制指令怎么落到执行器 Downlink

控制节点→ /cmd_vel Topic→ 驱动节点→ cansend→ CAN 帧→ 底盘 ECU / 执行器
上下行共用同一个驱动节点，只是收发方向不同；差速底盘上就是"订阅 /cmd_vel → 写 CAN"。
ONE-LINE RULE
总线不是节点，节点自己发。
画图时给"驱动节点"标注 publish 即可，不必再插入一个发布环节；
