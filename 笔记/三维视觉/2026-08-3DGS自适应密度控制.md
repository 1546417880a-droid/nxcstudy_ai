## 3DGS 自适应密度控制总结（Densification / Pruning）(2026.08)

> 来源：回答"为什么训练着训练着 Gaussian 越来越多，又有些被删掉"时整理。核心结论：**Gaussian 数量不是固定的**——训练中同时解决两个问题：**哪里需要更多 Gaussian（densification）** 和 **哪些 Gaussian 多余（pruning）**。

### 一、总体流程

```
初始化一批 Gaussian → 正常训练 Position/Shape/Opacity/SH
   ↓
发现某些地方表示不好 → Densification（增加）
   ↓
发现某些 Gaussian 没用 → Pruning（删除）
   ↓
继续训练 → 不断重复
```

### 二、为什么需要增加 Gaussian？

初始点云太稀疏（一堵墙只有几个点）→ 渲染出现空洞/误差大 → 单纯移动现有 Gaussian 不够 → 需要增加表示能力。

**系统怎么知道这里缺 Gaussian？** 靠梯度：

> **Loss 对 Gaussian 位置的梯度大小 `|∂L/∂μ|` 长期很大 → 说明当前区域还没拟合好 → Densify。**

### 三、Clone vs Split

| 情形 | 判断 | 操作 |
|---|---|---|
| Gaussian **小** + 梯度大 | 需要更多细节 | **Clone（克隆）**：产生新的小 Gaussian |
| Gaussian **大** + 梯度大 | 一个 Gaussian 在硬拟合复杂区域 | **Split（分裂）**：拆成多个更小 Gaussian 精细描述 |

记忆：**Gradient 大 + Gaussian 小 → Clone；Gradient 大 + Gaussian 大 → Split。**

直觉：梯度大说明渲染器和真实图在这个区域分歧大，现有 Gaussian"很努力在修"但结构不足，于是给它更多自由度。

### 四、为什么又要删除（Pruning）？

只增不删会爆炸，典型删除依据：

1. **Opacity ≈ 0**（如 0.001）：几乎透明、对 RGB 无贡献 → 删。
2. **Gaussian 过大**：为压低 Loss 而"膨胀"得夸张、不合理 → 处理/限制。

### 五、与梯度的两层关系（关键联系）

```
Gradient
   ├──→ 参数优化（高频）：Adam 更新 Position/Shape/Opacity/SH
   └──→ Densification 判断（间歇）：Clone / Split
```

**易误解点**：不是每次梯度下降都增删 Gaussian。实际是：参数优化**高频**进行；数量调整在**densification interval**间歇进行（先累积观察 gradient statistics，再统一检查 Clone/Split/Prune）。

### 六、一个完整的训练过程示例

```
Iter 0:  1000 Gaussian
Iter 100: 发现部分区域梯度大 → Densification → 1200
Iter 200: 一些 opacity→0 → Pruning → 1100
Iter 300: 细节区梯度仍大 → Split/Clone → 1500
...
最终: 几十万~数百万 Gaussian（取决于场景/初始化/阈值/实现）
```

### 七、回答更深的问题：稀疏点云怎么变成细腻场景？

> **它不是一开始就知道每个 Gaussian 该在哪**，而是"先搭粗糙模型，根据图像误差不断**长出**细节"：稀疏点云 → 少量 Gaussian → 渲染 → 发现误差 → 梯度 → 判断哪里缺表达 → 增删 Gaussian → 再优化 → 循环 → 高密度场景。

### 八、一句话总结

> **3DGS 真正厉害的不只是"用 Gaussian 表示 3D"，而是同时在做两件事：优化 Gaussian 参数（Adam）＋ 动态调整 Gaussian 的数量和空间分布（Densification/Pruning）。** 这也是为什么 Position/Shape/Opacity/SH/Transmittance/Rendering/Gradient 最后会全部连成一个系统。
