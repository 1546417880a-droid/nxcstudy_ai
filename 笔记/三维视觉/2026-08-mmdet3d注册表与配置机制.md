## 0. 先厘清"三个基类"

mmdet3d 的检测器基类大致分三类：

| 基类 | 输入 | 例子 |
|---|---|---|
| `SingleStage3DDetector` / `TwoStage3DDetector` | 纯点云 | PointPillars、CenterPoint |
| 单目/图像检测器 | 纯图像(RGB) | FCOS3D、MonoCon |
| `MVXTwoStageDetector` | **多模态**(图像 + 点云融合) | BEVFormer、TransFusion |

**关键点**：`BEVFormerV2` 继承的是多模态基类 `MVXTwoStageDetector`（`bevformerV2.py:18`），但它**只借用了多模态的骨架结构，点云分支全部置空(None)，只用了图像分支**。构造参数里所有 `pts_voxel_layer / pts_voxel_encoder / pts_backbone / pts_neck` 都是 `None`，真正用的只有 `img_backbone + img_neck + pts_bbox_head`（`pts_bbox_head` 名字带 pts 是历史遗留，实际吃图像特征）。

## 1. 核心机制：Registry（注册表）

OpenMMLab 家族（mmcv/mmdet/mmdet3d）统一用 **注册表 + 按 `type` 字符串查表实例化**。

### 三步

```python
# ① 类自己注册：装饰器把 "BEVFormerV2" 这个字符串和类 BEVFormerV2 绑定，存进 DETECTORS 注册表
@DETECTORS.register_module()      # bevformerV2.py:17
class BEVFormerV2(MVXTwoStageDetector):
    ...

# ② 配置里只写 type 字符串，其余字段作为构造 kwargs
model = dict(type='BEVFormerV2', use_grid_mask=True, ...)

# ③ build 时查表：build_model → build_from_cfg → DETECTORS.get('BEVFormerV2') → 用剩余键值实例化
model = build_model(cfg.model, train_cfg=..., test_cfg=...)   # tools/train.py:219
```

### Python 何时"知道"有这些类 —— plugin 加载链

配置里：
```python
plugin = True
plugin_dir = 'projects/mmdet3d_plugin/'
```

`tools/train.py:114-135` 看到 `plugin=True` 后执行：
```python
plg_lib = importlib.import_module('projects.mmdet3d_plugin')
```
触发 `projects/mmdet3d_plugin/__init__.py`，它**链式 import 所有子模块**（`.bevformer`、`.dd3d`、`.datasets`、`.models`…），import 过程中所有 `@XXX.register_module()` 装饰器被执行，注册表就被填满。

```
config 的 plugin=True
  → train.py import 插件包
  → __init__.py 链式 import
  → 装饰器把类注册进各注册表
  → build_model / build_head / pipeline 构建时按 type 查表实例化
```

## 2. 五步流水线（正确心智模型）

```
(1) 配置 cfg
      ↓ build_model(cfg.model)   ← 按注册表查 type，实例化每个子模块
(2) 完整模型结构(Model 对象，含 backbone/neck/head/transformer...)
      ↓ 结构定了，forward 就定了（forward 只是调用这些模块，不需额外配置）
(3) init_weights() / load_from   ← 加载预训练权重
      ↓
(4) 前处理 pipeline              ← 原始数据 → 模型 forward 需要的输入
      ↓
      model.forward(img, img_metas, ...)
      ↓
(5) 后处理(在 head 内部)        ← 预测 → 最终检测框
```

- 结构靠注册表拼出来 ✅
- 结构定了 forward 就定了 ✅
- 前处理负责把输入喂成 forward 要的样子 ✅

## 4. 前处理 pipeline（逐条解析）

`pipeline` 是一个 **list**，每条是一个 `dict(type='XXX', ...)`，对应一个 `@PIPELINES.register_module()` 的类。数据按顺序流过，每个类接收 `results` 字典，往里加/改键，再传给下一个。

`train_pipeline`（`bevformerv2-r50-t1-base-48ep.py:60-82`）：

| 步骤 | 作用 | 来源 |
|---|---|---|
| `LoadMultiViewImageFromFiles` | 读多相机图像 | mmdet3d 内置(插件 `loading.py` 是空的) |
| `PhotoMetricDistortionMultiViewImage` | 光度失真(亮度/对比度/饱和度/色相) | `transform_3d.py:98` |
| `LoadAnnotations3D` | 加载 3D 真值框+标签 | mmdet3d 内置 |
| `ObjectRangeFilter` | 过滤点云范围外的目标 | mmdet3d 内置 |
| `ObjectNameFilter` | 只保留指定类别 | mmdet3d 内置 |
| `CropResizeFlipImage` | 裁剪/缩放/随机翻转，**同时更新相机内参 cam2img** | `augmentation.py:9` |
| `NormalizeMultiviewImage` | 减均值/除标准差归一化 | `transform_3d.py:61` |
| `PadMultiViewImage` | 填充到 32 的倍数 | `transform_3d.py:7` |
| `DefaultFormatBundle3D` | 把 img/gt 转成 tensor 和 `DataContainer` | mmdet3d 内置 |
| `CustomCollect3D` | **收集最终 keys**，元信息打包成 `img_metas` | `transform_3d.py:199` |
| `DD3DMapper` | V2 新增：为 FCOS3D 单目分支准备 2D/3D 标注、内参、位姿 | `dd3d_mapper.py:11` |

几个关键点：

1. **`results` 字典是贯穿全程的载体**：前几步往里写 `results['img']`、`results['gt_bboxes_3d']`、`results['lidar2cam']` 等；最后 `CustomCollect3D` 把 `keys=[...]` 抽出来给模型，把 `meta_keys` 打包成 `img_metas`（存相机内外参、翻转标记等）。

2. **`CropResizeFlipImage` 的副作用很重要**：它不只是改图，还会更新 `cam2img`/`lidar2img`（`augmentation.py:93,137`），保证几何变换后"图上像素 ↔ 3D 空间"的映射仍然正确——这是 3D 检测里图像增强比 2D 更复杂的地方。

3. **`DD3DMapper` 是 V2 特有**：把 `mono_input_dict`（单目标注）转成 `instances` 结构，供 `fcos3d_bbox_head`（NuscenesDD3D）辅助分支用，对应模型里 `forward_mono_train` 那条支路。

## 5. 后处理不是"固定"的（重要纠正）

**对的部分**：输出**格式**是标准化的。`BEVFormerV2.simple_test_pts`（`bevformerV2.py:290`）调用 `get_bboxes`，再经 `bbox3d2result` 转成固定结构：

```python
bbox_results = [
    bbox3d2result(bboxes, scores, labels)   # → {'boxes_3d':..., 'scores_3d':..., 'labels_3d':...}
    for bboxes, scores, labels in bbox_list
]
```
每个样本输出一个 dict（`boxes_3d / scores_3d / labels_3d`），评估器按这个格式消费。

**需修正的部分**：后处理本身**不是写死的**，而是**由配置 + 模块共同决定**，做在 head 的 `get_bboxes()` 里，不是独立于模型的固定步骤。它包含：

1. **bbox_coder 解码**：head 输出的是编码后的量（中心偏移、尺寸、旋转角、分类分数等），`NMSFreeCoder`（`core/bbox/coders/nms_free_coder.py:9`）负责"解码"成真实 3D 框。coder 由配置 `bbox_coder=dict(type='NMSFreeCoder', post_center_range=..., max_num=300, ...)` 指定，参数直接影响输出框数量。

2. **NMS + 后处理参数**：在 `head.get_bboxes()` 里做，受 `test_cfg` 控制（NMS 阈值、每类保留框数等）。

**一个易混淆点**：`bbox_coder` 同时服务训练和测试：
- **训练**：`HungarianAssigner3D`（匹配器）用 coder 把预测和真值配对算 loss（在 `train_cfg` 里配置）。
- **测试**：coder 把预测解码成最终框。

所以准确说法：
> 后处理不是"固定"的，而是"由 `bbox_coder` + `test_cfg` 配置化决定"的；它做在 head 的 `get_bboxes()` 里，输出格式（`boxes_3d/scores_3d/labels_3d`）才是标准化的。

## 6. 一句话总结

- 模型和前处理的"每个 `type` 去哪找"——答案是**注册表**：类用 `@XXX.register_module()` 登记自己，`plugin=True` 让 `train.py` import 插件从而触发登记，`build_model`/`build_head`/pipeline 构建时按 `type` 查表实例化。
- 前处理 `pipeline` = **顺序执行、共享 `results` 字典**的类列表。
- 主链条：**配置 → build 出结构 → forward 定了 → 加载权重 → 前处理喂输入 → 后处理(head 内 get_bboxes)输出标准格式**。
