## 一、配置文件（Config，唯一事实来源）

配置文件是一个 **dict**，一次训练的"唯一事实来源"（single source of truth）。一个文件（加上 `_base_` 继承链）包含启动训练/推理所需的一切。

### 1.1 配置块全景

| 配置块 | 内容 | 推理要不要 |
|---|---|---|
| 顶部变量 | `point_cloud_range`、`class_names`、`img_norm_cfg`、`bev_h_`、`voxel_size`、`_dim_` 等，被下面各块引用 | ✅ 要 |
| `model` | 完整模型结构（backbone/neck/head/transformer/loss/coder） | ✅ 要 |
| `data` | 数据集（train/val/test + pipeline + sampler + batch） | ✅ 要 `data.test` |
| `train_cfg` | 训练专用：正负样本匹配器(assigner) | ❌ 置 None |
| `optimizer` / `optimizer_config` | 优化器、梯度裁剪 | ❌ 不读 |
| `lr_config` | 学习率策略、warmup | ❌ 不读 |
| `runner` / `total_epochs` | 运行器、训练轮数 | ❌ 不读 |
| `evaluation` | 多久评测一次 | ❌ 不读 |
| `load_from` / `plugin` / `plugin_dir` | 预训练权重、插件开关 | plugin 要 |

### 1.2 `_base_` 继承机制

配置文件**不是 100% 自包含**，通过 `_base_` 继承公共配置：

```python
_base_ = ['../_base_/default_runtime.py']
```

`default_runtime.py` 只提供 9 行运行时配置（checkpoint 间隔、日志、分布式后端、workflow），避免每个配置重复写。所以：

- **内联在文件里**：模型、数据、优化器、学习率、runner（跟模型/数据/训练相关的）
- **从 `_base_` 继承**：checkpoint/日志/分布式/workflow（运行时通用配置）

### 1.3 数据配置在哪

BEVFormerV2 的数据配置是**内联**的（`data = dict(...)` 直接写在文件里），**不读** `configs/datasets/`。

- `configs/datasets/custom_nus-3d.py` 只有 **V1**（bevformer_base/tiny/small/fp16）引用
- V2 因为改用 `CustomNuScenesDatasetV2`（时序多帧 + mono_cfg），数据需求变了，所以自己内联写

## 二、自定义模块（插件 Plugin）

### 2.1 插件的四件套

```
projects/mmdet3d_plugin/          ← 插件根目录
├── __init__.py                   ← ③ 链式 import，触发所有装饰器注册
├── bevformer/...                 ─┐
├── dd3d/...                       │ ② 自定义模块类
├── datasets/pipelines/...         │   (带 @XXX.register_module())
└── models/...                    ─┘

projects/configs/bevformerv2/xxx.py  ← ① 配置文件
    ├── plugin = True              ← ④ 开关：让 train.py 去 import 插件
    └── plugin_dir = 'projects/mmdet3d_plugin/'
```

| 东西 | 作用 |
|---|---|
| 配置文件 | 定义"构建什么、怎么构建"（type + 参数） |
| 自定义模块类 | 真正的实现，带 `@XXX.register_module()` 装饰器 |
| `__init__.py` 链 | 被 import 时触发装饰器，把类填进注册表 |
| `plugin=True/plugin_dir` | 配置里声明用了插件，train.py/test.py 据此 import |

### 2.2 注册表机制（三步）

```python
# ① 类自己注册：装饰器把类名和类绑定存进注册表
@DETECTORS.register_module()
class BEVFormerV2(MVXTwoStageDetector): ...

# ② 配置里只写 type 字符串
model = dict(type='BEVFormerV2', ...)

# ③ build 时查表实例化
model = build_model(cfg.model)  # → DETECTORS.get('BEVFormerV2')(**kwargs)
```

### 2.3 插件里"自定义"分两类

| 类型 | 特征 | 例子 |
|---|---|---|
| 注册模块 | 带 `@XXX.register_module()`，进注册表 | detectors、heads、transformer、pipelines、coder、dataset |
| 工具/辅助代码 | 不带装饰器，纯 helper，不进注册表 | `Pose`、`TaskManager`、`builder.py`、`apis/` |

### 2.4 关键：注册 ≠ 使用

- **注册**：让类"可用"（放进注册表）
- **使用**：配置里 `type='XXX'` 引用了它，才被 build 实例化

只有**同时满足**两个条件才真正注册：① 类上有装饰器；② 文件被 `__init__.py` 链 import。

死代码例子：`models/backbones/vovnet.py`（VoVNet）有装饰器但没被 import → 没注册；`datasets/nuscenes_mono_dataset.py` 没被 import → 没用上。

注册了但没用的例子：`BEVFormerHead_GroupDETR`、`BEVFormer`(V1)、`BEVFormer_fp16` 都注册了，但 V2 配置不用。

## 三、对象创建 + 调用链路

### 3.1 配置 → 对象 → 调用链路 全映射

| 配置块 | 构建函数 | 创建的对象 | 调用链路 |
|---|---|---|---|
| `model` | `build_model()` | `BEVFormerV2` | `forward()` → `forward_train`/`forward_test` → `head.forward()` → `head.get_bboxes()` |
| `data.train/test` | `build_dataset()` | `CustomNuScenesDatasetV2` | `__getitem__()` → `self.pipeline(results)` |
| `pipeline` | `Compose(pipeline)` | 一串前处理类 | 逐个 `step.__call__(results)` |
| `optimizer` | `build_optimizer()` | `AdamW` | `optimizer.step()` |
| `lr_config` | `build_lr_scheduler()` | `StepLR`+warmup | `scheduler.step()` |
| `runner` | `build_runner()` | `EpochBasedRunner` | `runner.run()` 驱动 epoch 循环 |
| `hooks` | `build_hook()` | EvalHook/CheckpointHook | 特定时机被 runner 触发 |

### 3.2 三条对象关系（谁挂在哪）

```
Runner (训练总管家, 只有训练才有)
 ├── model          ← build_model(cfg.model)
 ├── optimizer      ← 独立对象, 和 model 兄弟, 不是 model 属性
 ├── lr_scheduler   ← 独立对象
 └── hooks

Model (BEVFormerV2)
 ├── img_backbone / img_neck
 ├── pts_bbox_head
 │    ├── forward()         ← 前向
 │    ├── bbox_coder        ← 后处理的解码器(self.bbox_coder)
 │    └── get_bboxes()      ← 后处理的方法
 └── fcos3d_bbox_head

Dataset (CustomNuScenesDatasetV2, 模型外)
 └── self.pipeline = Compose(...)   ← 前处理挂在数据集上
```

关键区分：

| 对象 | 是谁的属性 | 模型内/外 |
|---|---|---|
| 前处理 pipeline | `Dataset.self.pipeline` | 模型外 |
| 后处理 bbox_coder | `head.bbox_coder` | 模型内 |
| optimizer | `runner.optimizer` | 模型外（runner 持有） |

### 3.3 训练 vs 推理 两条链路

**推理（2 个对象，无 runner，直接循环）：**

```python
model = build_model(cfg.model, test_cfg=...)   # ① 模型（train_cfg 置 None）
load_checkpoint(model, ckpt)                    # ② 权重
data_loader = build_dataloader(build_dataset(cfg.data.test))  # ③ 数据
results = single_gpu_test(model, data_loader)   # ④ 一个普通 for 循环
#   for data in data_loader:
#       data = dataset.__getitem__(i)        # 内部跑 eval_pipeline
#       result = model(return_loss=False)    # forward_test → get_bboxes
```

**训练（多个对象，归 runner 编排）：**

```python
# build 出 model + dataset + optimizer + lr_scheduler + runner + hooks
runner.run(data_loaders):
    for epoch:
        for data in dataloader:
            loss = model(return_loss=True)   # forward_train
            loss.backward()
            optimizer.step()
            scheduler.step()
        # hooks 在对应时机触发(checkpoint/eval/log)
```

| | 推理 | 训练 |
|---|---|---|
| 对象 | data + model（2 个） | model + optimizer + lr + hooks + data（多个） |
| 有没有 runner | ❌ | ✅ |
| 调用方式 | `single_gpu_test` 一个循环 | runner 编排全流程 |
| 核心区别 | 只前向，不更新参数 | 前向 + 反向 + 更新参数 |

### 3.4 single_gpu_test vs runner

`single_gpu_test` 是 runner 的"极简退化版"：

| | `single_gpu_test` | `runner` |
|---|---|---|
| 是什么 | 无状态**函数** | 有状态**类对象** |
| 状态 | 跑完即丢 | 记住 epoch/iter、optimizer 状态、lr 进度 |
| 职责 | 只做前向 + 收集结果 | 反向、更新参数、调 lr、存 checkpoint、断点续训、触发 hooks |

根本原因：推理不需要"状态"，一遍过；训练必须记住进度，所以要个长期持久的对象。

### 3.5 完整闭环

```
配置文件(plugin_dir 指向插件)
   ↓ train.py 读到 plugin=True
import 插件包 → __init__.py 链 → 装饰器执行 → 注册表填满
   ↓
build_model / build_dataset / build_optimizer / ... 按 type 查表 → 创建对象
   ↓
对象调用链路跑起来（训练走 runner，推理走 single_gpu_test）
```

## 一句话总结

> 整个框架 = **"注册(装饰器) → 构建(查表实例化) → 调用(对象链路)"** 三步；插件 = **配置文件 + 自定义类 + `__init__.py` 注册链 + `plugin_dir` 开关** 四件套；注册只是"报名"，配置里 `type` 点名才是"录取"，两者是独立的两件事。
