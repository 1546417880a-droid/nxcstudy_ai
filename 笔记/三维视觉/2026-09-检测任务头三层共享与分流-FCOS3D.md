> 来源：纠正"backbone 特征已共享，任务头是不是就只是一个 conv"的混淆。一句话：**任务头不一定只是 1×1 conv，FCOS3D 的任务头是"共享卷积塔 + 各任务独立子塔 + 1×1 conv 线性读出"的小型子网络；backbone/FPN 的共享与任务头内部的共享是**两个不同层次**的事。**

### 一、先分清两种"共享"（这是混淆的根源）

```
图像
  → Backbone + FPN          ← 第一层共享（所有任务共享）
  → 共享特征 f (256维)
  → ┌─────────────────────────────────┐
    │  任务头内部                      │
    │  ├─ 共享卷积塔（shared_convs）    │ ← 第二层共享（所有任务头共享）
    │  │   Conv3×3 → GN → ReLU         │
    │  │   Conv3×3 → GN → ReLU         │
    │  │                               │
    │  └─ 各任务独立子塔                 │ ← 第三层分流（每个任务独立）
    │      ├─ cls 子塔 → 1×1 conv      │
    │      ├─ reg 子塔 → 1×1 conv      │
    │      └─ ...                      │
    └─────────────────────────────────┘
```

| 层次 | 是否共享 | 作用 |
| :--- | :--- | :--- |
| Backbone + FPN | 所有任务共享 | 通用视觉特征 |
| **共享卷积塔** | 所有任务头共享 | 任务相关的通用变换 |
| **各任务独立子塔** | 每个任务独立 | 任务专用特征转换（= 任务子空间转换） |
| 最后 1×1 conv | 每个输出值独立 | 线性读出 |

### 二、任务头内部的"特征转换"是什么

以 FCOS3D 的 `FCOSMono3DHead` 为例（简化）：

```python
# 共享卷积塔（所有任务共享）
shared_convs = [
    Conv2d(256, 256, 3, padding=1), GN(256), ReLU(),
    Conv2d(256, 256, 3, padding=1), GN(256), ReLU(),
]

# 各任务独立子塔
cls_convs = [Conv2d(256, 256, 3), GN, ReLU, ...]   # 分类专用
reg_convs = [Conv2d(256, 256, 3), GN, ReLU, ...]   # 回归专用

# 最后线性读出
cls_score = Conv2d(256, 10, 1)   # 分类输出
bbox_pred = Conv2d(256, 9, 1)    # 回归输出
```

所以任务头不是"一个 conv"，而是：

```
共享卷积塔（2层 Conv+GN+ReLU）
  → 任务独立子塔（2层 Conv+GN+ReLU）
    → 1×1 conv 线性读出
```

### 三、为什么任务头里还要做特征转换

因为 **backbone/FPN 的特征是"通用"的，不是"任务专用"的**：

- Backbone 学的是"图像里有什么边缘、纹理、物体"；
- 但分类需要"语义判别特征"，回归需要"几何定位特征"——这两类特征**不一样**；
- 所以任务头内部要再做一次**任务专用转换**：把共享特征投影到任务关心的子空间。

### 四、三种任务头设计对比（按"共享到哪一层"分）

| 设计 | 结构 | 参数量 | **表达能力** | 任务冲突 | 任务专用特征转换 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **A** 纯线性读出 | `f → 1×1 conv → 输出` | 最少 | **最弱**（只能线性投影，学不出新特征） | 无（各任务独立投影） | ❌ 无 |
| **B** 共享塔 + 读出 | `f → 共享 Conv+ReLU → 1×1 conv` | 中等 | **中等**（能提非线性特征，但任务间共用同一套变换） | 严重（共享变换被多任务拉扯） | ❌ 无（只有共享转换） |
| **C** 共享塔 + 独立子塔 + 读出（FCOS3D） | `f → 共享塔 → 各任务独立子塔 → 1×1 conv` | 最多 | **最强**（先学通用变换，再各自提任务特征） | 缓解（先共享再分流，冲突在子塔处解开） | ✅ 有 |

**表达能力从 A → C 递增的本质**：

- A：只能对**已有特征**做线性组合，无法造出新的、更抽象的特征；
- B：共享塔能造新特征，但所有任务**被迫用同一套**，表达能力被"一鱼多吃"限制；
- C：每个任务都能在共享表示之上**再造一层自己的非线性特征**，等于给每个任务配了独立的小网络——表达能力最强，也因此参数最多。

### 五、完整图景与一句话总结

```
图像
  → Backbone + FPN          ← 共享：通用视觉特征
  → 共享特征 f (256维)
  → 共享卷积塔               ← 共享：任务相关的通用变换
  → 任务相关特征 (256维)
  ├─ cls 独立子塔 → 分类专用特征 → 1×1 conv → 分类输出
  ├─ reg 独立子塔 → 回归专用特征 → 1×1 conv → 回归输出
  └─ ...
```

> **任务头不只是单个 conv**：FCOS3D 的任务头 = 共享卷积塔 + 各任务独立子塔 + 1×1 conv 线性读出。共享塔做"任务相关的通用转换"，独立子塔做"任务专用特征转换"（即任务子空间转换），最后线性读出。**Backbone/FPN 的共享** 与 **任务头内部的共享/分流** 是两个不同层次的事。
